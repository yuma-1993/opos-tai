# Tema 5.3 · Bloque 3 — .NET

> [!abstract] De qué va este tema
> .NET es la plataforma de Microsoft equivalente a la de Java: varios lenguajes (C#, VB.NET, F#...) se compilan a un bytecode intermedio (CIL) que el CLR ejecuta convirtiéndolo a código nativo (JIT). El tema recorre sus componentes y su historia, las construcciones del lenguaje (con la equivalencia constante con Java), la persistencia (ADO.NET, Entity Framework, LINQ), las aplicaciones web (Web Forms, MVC, servicios SOAP y REST), el entorno de ejecución web (IIS / Kestrel) y las herramientas de línea de comandos y de gestión de dependencias (dotnet, MSBuild, NuGet).

> [!tip] Cómo estudiarlo
> El PDF va comparando todo con Java mediante el símbolo ≈ (equivalente a). Aprende .NET como "el Java de Microsoft": cada concepto de esta nota tiene su gemelo en Java (JDK, JRE, bytecode, .jar, JDBC, JPA, Maven, `jax-ws`, `jax-rs`...). Ver la tabla de equivalencias de la sección final.

## 1. Componentes de la plataforma

- El corazón de la plataforma es **.NET Framework** (≈ JDK).
- Usa **Assembly**: empaquetado de CIL (≈ `.jar`) en formato `.dll` o `.exe`; se puede inspeccionar con `ildasm.exe` (≈ `javap`).
- `AssemblyInfo.cs` y `AssemblyInfo.vb`: contienen `Assembly: xxxxxx`.
- Si un lenguaje cumple ciertas reglas (**CTS** y **CLS**), puede crearse un compilador a bytecode para él.
- **JIT** transforma el bytecode en código nativo.
- Soporta varios lenguajes (C#, F#, VB.NET, etc.).

> [!example] Diagrama de compilación y ejecución (del PDF)
> ```
> Compile time                                   |  Runtime
> Source code            Bytecode                |  Native code
> C#      --C# compiler------\
> VB.NET  --VB.NET compiler----> CIL code --CLR--> Native code
> Other .NET language --Other compiler-/
> ```
> Cada lenguaje tiene su compilador; todos generan el mismo **CIL code** en tiempo de compilación; en tiempo de ejecución el **CLR** lo convierte a código nativo.

### Definiciones

| Siglas | Nombre | Qué es / equivalencia |
|---|---|---|
| **CLI** | Common Language Infrastructure | Todo el estándar .NET |
| **VES** | Virtual Execution System | Un runtime de la CLI |
| **CLR** | Common Language Runtime | ≈ JRE. Es la implementación de VES. Pasó a llamarse *Core CLR*. Es el motor de ejecución de .NET: gestión de hilos, gestión de excepciones, recolección de basura, compilar de CIL a código nativo, cargador de clases en memoria y tareas de seguridad |
| **GAC** | Global Assembly Caché | ≈ classpath. Ruta: `C:\Windows\Microsoft.NET\assembly` |
| **CIL** | Common Intermediate Language | Antes llamado **MSIL**. ≈ Bytecode. Lo ejecuta el CLR |
| **CTS** | Common Type System | Estructura de tipos compatibles: Clases, Value Types, Interfaces, Delegates |
| **CLS** | Common Language Specification | Características de los lenguajes compatibles |

Ejemplo del PDF para instalar un assembly en el GAC (en Mono/Linux):

```bash
$ gacutil -i gac_lib.dll
gac_lib installed into the gac (/usr/lib/mono/gac)
```

> [!important] Pares que se confunden
> - **CLR = implementación de VES** (VES es el runtime abstracto de la CLI; CLI es todo el estándar).
> - **CTS** = qué tipos existen y son compatibles; **CLS** = qué características mínimas debe cumplir un lenguaje para ser compatible.
> - **CIL** (antes MSIL) lo ejecuta el CLR; **JIT** lo pasa a código nativo.

## 2. Historia

- En **2001** Microsoft hizo de .NET un estándar **ECMA 335 / ISO 23271** (estándar **CLI**), donde se publican las instrucciones de la CLR (conjunto de instrucciones para convertir un lenguaje en bytecode).
- **.NET Core**: versión multiplataforma, *free* y *open source*, competencia de **Mono** y **DotGNU Portable .NET**.
- Cronología: primero **.NET Framework** para Microsoft (**2002**), luego **.NET Core** multiplataforma (**2016**). Desde **2020** hay un único producto llamado **.NET** (convergencia).
- Para evitar que las clases "base" difieran entre implementaciones de .NET se publica **.NET STANDARD BCL** (Base Class Library).
- Las versiones del CLR **no** se corresponden con las versiones del Framework (en Java sí coincide). El CLR no ha evolucionado desde 2010 (v4.0), mientras que .NET va por la **4.8.1** con mejoras de clases nuevas.
- **ECMA 334** para la estandarización de **C#**. C# no es de Microsoft, es de ECMA.

| Año | Hito |
|---|---|
| 2001 | ECMA 335 / ISO 23271 (estándar CLI) |
| 2002 | .NET Framework (Microsoft) |
| 2010 | CLR v4.0 (no ha evolucionado desde entonces) |
| 2016 | .NET Core (multiplataforma) |
| 2020 | Un único producto: .NET |

## 3. Características de los principales lenguajes

> [!important] Actualización 20/05/2026 (docx de actualizaciones, entrada de 27/03/2026)
> El documento de actualizaciones indica para este tema: "Breve resumen de diferencias entre C# y VB.NET". Es el recuadro que figura en el PDF y que se recoge en esta tabla.

| | C# | VB.NET |
|---|---|---|
| Parecido a | C/C++/Java | VB |
| Sintaxis | Usa `{}` y `;` | Usa `End If`, `End Sub` |
| Mayúsculas/minúsculas | Case-sensitive | Case-insensitive |
| Uso | Mayor uso | Menor uso |

### Clases

Como las de Java. Sirven para crear objetos. Tienen campos y métodos.

```vb
[ <attributelist> ] [ accessmodifier ] [ Shadows ] [ MustInherit | NotInheritable ] [ Partial ] _
Class name [ ( Of typelist ) ]
    [ Inherits classname ]
    [ Implements interfacenames ]
    [ statements ]
End Class
```

| Modificador | Significado |
|---|---|
| `MustInherit` | Debe heredarse |
| `NotInheritable` | No heredable (≈ `final`) |
| `Partial` | Para definir una clase en varios ficheros VB |

### Estructuras

- Son "sacos de información". Similares a las clases.
- **No** permiten herencia (`Inherits`), pero **sí** `Implements`.
- No se pueden inicializar los campos.
- Por defecto todos sus miembros son públicos.
- Las estructuras pasan **por valor**, no por referencia.
- También pueden tener funciones.

```vb
[ <attributelist> ] [ accessmodifier ] [ Shadows ] [ Partial ] _
Structure name [ ( Of typelist ) ]
    [ Implements interfacenames ]
    [ datamemberdeclarations ]
    [ methodmemberdeclarations ]
End Structure
```

### Módulos

- Similares a las clases con **todos sus miembros `shared` o estáticos**, compartidos entre todos los objetos de la clase.
- Cada módulo tiene **una instancia** y no es necesario crearla ni asignarla a una variable.
- Un módulo tiene la misma duración que el programa.
- **No** admiten herencia ni implementación de interfaces.
- Programación modular: conjunto de utilidades que no pertenecen a una clase concreta.

```vb
[ <attributelist> ] [ accessmodifier ] Module name
    [ statements ]
End Module

' Ejemplo del PDF
Public Module BBDD
    Public Sub alta (...) ... End Sub
End Module

' Uso:
BBDD.alta (...)
```

### Property

Son **descriptores de acceso**: un mecanismo para que parezca que accedemos directamente a los campos. Parece que se salta el principio de encapsulación, pero en realidad usa `Get` y `Set` internamente. Si no lleva `Set`/`Get` obliga a usar el modificador `ReadOnly`/`WriteOnly`.

```vb
Class Persona
    Private _nombre As String
    Public Property Nombre() As String
        Get
            Return _nombre
        End Get
        Set(ByVal valor As String)
            _nombre = valor
        End Set
    End Property
End Class

' Uso (del PDF)
Dim Persona1 As new Persona();
Persona1.Nombre = "Carlos"
```

### Tipos y paso de parámetros

- No hay conversión automática entre números y cadenas: hay que usar la función `CStr`.
- El tipo `Currency` ha sido reemplazado por `Decimal` y `Variant` por `Object`.
- En Java los tipos primitivos se pasan **por valor** (se pasa el contenido) y los objetos **por referencia**.
- En .NET los **tipos primitivos y las estructuras** se pasan **por valor**. **Por referencia** se pasan los **strings, arrays, clases y delegados**.

> [!important] Paso por valor vs por referencia en .NET
> Valor: primitivos y estructuras. Referencia: strings, arrays, clases y delegados.

### Otras construcciones y equivalencias con Java

| .NET | Equivalente / explicación |
|---|---|
| Métodos: `Sub` (procedimientos) o `Function` (devuelven un valor) | En Java todo son métodos. Una subrutina ≈ método `void` de Java |
| **Atributos** de .NET | ≈ anotaciones de Java |
| **Namespace** | ≈ `package` de Java. Para usar elementos de otro namespace: `Imports` en VB y `using` en C# |
| Constructor `New` y destructor `Finalize` | En Java el constructor es el nombre de la clase |
| `Try Catch Finally` | Control de errores estructurado |
| `Using` (VB y C#) | Como en Java: bloque en el que se liberan automáticamente recursos. Los objetos/recursos deben tener implementado `IDisposable` para que `using` funcione |
| `Me` | Instancia actual (≈ `this`; parecido a `MyClass`) |
| `MyBase` | Clase base de la que se hereda (≈ `super`) |
| `Exit` (en bucle `For`) | ≈ `break` de Java |

```csharp
using (sqlConnection con = new SqlConnection(...)) { ... }
```

### Delegate

Similar al concepto de **puntero a función**. Existen también en C#. Es una referencia a un método que puede cambiar y apuntar a otra función. **La definición de la función original debe coincidir.**

```vb
Public Delegate Sub SomeWorkDelegate(ByVal strSomeString As String)

Dim delegado As SomeWorkDelegate

delegado = AddressOf SomeFunction   ' SomeFunction sí tiene que tener código
delegado.Invoke("cadena de entrada")
```

### Herencia y sobrescritura (modificadores)

Para poder hacer sobrescritura debes declararlo, y para lo contrario también. (Ver [[Sobrecarga (overloading) vs Sobreescritura (overriding)]] y [[Polimorfismo (POO)]].)

| C# | VB.NET | Significado |
|---|---|---|
| `virtual` | `Overridable` | El método **SÍ PUEDE** ser sobrescrito (con `override` / `Override`). En C# `override` es palabra reservada obligatoria |
| `sealed` | `NotOverridable` / `NotInheritable` | El método **NO PUEDE** ser sobrescrito, o la clase **NO permite** que nadie herede de ella (≈ `final` de Java). Una clase abstracta no puede ser `sealed` |
| `abstract` | `MustOverride` / `MustInherit` | No codificas el método y haces que lo implementen los hijos mediante herencia. `MustOverride`: método que se debe sobrescribir en los hijos |

Resumen de los modificadores de VB.NET del PDF:

- `NotInheritable`: de esa clase nadie puede heredar (≈ `final`). Lo opuesto a `MustInherit`.
- `Overridable`: método que se puede sobrescribir en los hijos con `Override`.
- `MustOverride`: método que se debe sobrescribir en los hijos.
- `NotOverridable`: método que no se puede sobrescribir (≈ `final`). Opuesto de `Overridable`.

### Interfaces, herencia e implementación

- **Interface**: ≈ clase con métodos vacíos.
- `Inherits`: entre clases y entre interfaces. Ejemplo: `interface Guardable Inherits Serializable`.
- `Implements`: entre una clase y una interface.

```vb
Interface Guardable
    sub guardar
end interface

Class Usuario implements Guardable
    sub guardar () implements Guardable.guardar
        ...
    end sub
end class
```

Otras estructuras de programación: **Record** (como una fila de una tabla), **Interface**, **Enum**, etc.

### Event

Además de `sub` y `function` existen los **eventos**.

```vb
Event labResult (...)
' RaiseEvent + declaración con Handles  -> call
public sub gestionaEvento (...) Handles labResult ... End sub
```

### Métodos de clase

Similares a los `static` de Java. No hace falta instanciarlos para usarlos. Para declarar miembros de clase se usa `static` en C# o `shared` en VB.

```vb
Class Util
    public shared sub enviarMail (...)
End Class

' Uso:
Util.enviarMail (...)
```

### Estructuras de control (ejemplos del PDF, VB.NET)

```vb
If count = 0 Then
    message = "There are no items."
ElseIf count = 1 Then
    message = "There is 1 item."
Else
    message = $" {count} items."
End If

Dim number As Integer = 8
Select Case number
    Case 1 To 5
        Debug.WriteLine("Between 1 and 5, inclusive")
    Case 6, 7, 8
        Debug.WriteLine("Between 6 and 8, inclusive")
    Case 9 To 10
        Debug.WriteLine("Equal to 9 or 10")
    Case Else
        Debug.WriteLine("Not between 1 and 10, inclusive")
End Select

While index <= 10
    Debug.Write(index.ToString & " ")
    index += 1
End While

Do
    Debug.Write(index.ToString & " ")
    index += 1
Loop Until index > 10

Do While index <= 10
    Debug.Write(index.ToString & " ")
    index += 1
Loop

For index As Integer = 1 To 5
    Debug.Write(index.ToString & " ")
Next

Dim lst As New List(Of String) _
    From {"abc", "def", "ghi"}
' Iterate through the list.
For Each item As String In lst
    Debug.Write(item & " ")
Next

Public Sub TryExample()
    Dim x As Integer = 5
    Dim y As Integer = 0
    ' Set up structured error handling.
    Try
        ' Cause a "Divide by Zero" exception.
        x = x / y
        ' This statement does not execute because program control passes to the Catch
        ' block when the exception occurs.
        MessageBox.Show("end of Try block")
    Catch ex As Exception
        ' Show the exception's message.
        MessageBox.Show(ex.Message)
        ' Show the stack trace, which is a list of methods that are currently executing.
        MessageBox.Show("Stack Trace: " & vbCrLf & ex.StackTrace)
    Finally
        ' This line executes whether or not the exception occurs.
        MessageBox.Show("in Finally block")
    End Try
End Sub
```

|---|---|
| Condicional | `If ... ElseIf ... Else ... End If` · `Select Case` (rangos `1 To 5`, listas `6, 7, 8`, `Case Else`) |
| Bucles | `While ... End While` · `Do ... Loop Until` · `Do While ... Loop` · `For ... Next` · `For Each ... Next` |
| Errores | `Try ... Catch ... Finally ... End Try` |

## 4. Persistencia

### ADO.NET

API de BBDD de **bajo nivel** (≈ **JDBC**). El programador escribe las SQL.

| Modo | Características |
|---|---|
| **Offline** | **DataSet**: conjunto **desconectado** de datos que tiene que rellenarse usando un `xxDataAdapter`. Puede tener datos de una o varias tablas. Internamente es un XML. Ocupa mucho en memoria. **Obsoleto** |
| **Online** | Maneja **cursores** (ver [[Cursor (SQL)]]). `xxConnection`, `xxCommand` (select, update), `xxParameter`, `DataReader` (≈ `ResultSet` de Java). `xx`: SQL (nativo), oledb (Oracle, etc.) |

Flujo online: `App → DataReader/Command → ADO.NET Clásico → SQL → BBDD`. El programador hace las SQL.

> [!example] Diagrama ADO.NET (del PDF)
> - **Proveedores de datos de .NET Framework**: `Connection` (con `Transaction`), `Command` (con `Parameters`), `DataAdapter` (con `SelectCommand`, `InsertCommand`, `UpdateCommand`, `DeleteCommand`) y `DataReader`.
> - **DataSet**: `DataTableCollection` → `DataTable` → (`DataRowCollection`, `DataColumnCollection`, `ConstraintCollection`) y `DataRelationCollection`.
> - El `DataAdapter` conecta la BBDD con el `DataSet`; el `DataSet` se intercambia también con **XML**.

### Entity Framework (EF)

- Es un **ORM**. **Alto nivel**. ≈ **JPA**. A partir de la versión **3.5**.
- `Model.edmx` es donde se definen las entidades asociadas a las tablas.
- Flujo: `App → Objetos/Modelo → EF → SQL`. **Las SQL no las hace el programador.**
- **NHibernate** es la conversión de Hibernate de lenguaje Java a C# para .NET.
- En la captura del PDF se ve la clase `SchoolDBEntities : DbContext`, con **Fluent API** (`OnModelCreating(DbModelBuilder modelBuilder)`) y los **Entity set** (`DbSet<Course> Courses`, `DbSet<Standard> Standards`, `DbSet<Student> Students`, `DbSet<StudentAddress> StudentAddresses`, `DbSet<Teacher> Teachers`).

| | ADO.NET | Entity Framework |
|---|---|---|
| Nivel | Bajo | Alto (ORM) |
| ≈ en Java | JDBC | JPA |
| Quién escribe la SQL | El programador | No el programador |
| Flujo | App → DataReader/Command → ADO.NET → SQL | App → Objetos/Modelo → EF → SQL |

### LINQ

**Consultas independientes de la fuente**: la misma consulta sirve sobre objetos en memoria, sobre una BD relacional o sobre un XML. A partir de la v**3.5**.

```csharp
var teenStudentsName = from s in studentList
                       where s.age > 12 && s.age < 20
                       select new { StudentName = s.StudentName };

teenStudentsName.ToList().ForEach(s => Console.WriteLine(s.StudentName));

using (var ctx = new SchoolDBEntities()) {
    var student = (from s in ctx.Students
                   where s.StudentName == "Bill"
                   select s).FirstOrDefault<Student>();
}
```

> [!important] Idea clave
> ADO.NET = SQL a mano (JDBC). EF = ORM, sin SQL escrita por el programador (JPA/Hibernate → NHibernate). LINQ = consulta uniforme sobre cualquier fuente (memoria, BD, XML), desde la 3.5, como EF.

## 5. Aplicaciones web

El CLR no sabe nada de páginas web, por eso hace falta el **Motor ASP.NET Core**, que unifica **ASP.MVC** y **ASP.NET Web API**.

`global.asax` es un archivo opcional usado en las aplicaciones web de ASP.NET para declarar y manejar eventos y objetos a nivel de aplicación y de sesión.

### Web Forms

- En un fichero tenías el HTML y en otro el código del ciclo de vida, tanto para VB como para C#. Similar a **WinForms** (aplicaciones de escritorio).
- Modelo de aplicación en el cual el flujo **siempre comienza por las páginas `.aspx`**.
- Extensiones: `.asmx` = páginas de **servicios web**; `.ashx` = **manejadores HTTP personalizados**, que interceptan peticiones realizadas al servidor, ejecutando ciertos procesos.
- La página hereda de `System.Web.UI.Page` y tiene un **ciclo de vida** (eventos en los que podemos codificar cosas): el motor de ASP.NET llama a distintos métodos de tu página (`init()`, `load()`, etc.).
- Si hay vistas muy complejas se puede usar **MasterPage** para tener un modelo de páginas más flexible y reutilizar elementos comunes (menús, cabeceras, etc.). **ASP.NET Razor** mejora las Master Page (modelo plantilla).
- La "página" consta de dos partes:
  - HTML + **etiquetas de servidor** (ej. `<asp:Table>`).
  - **Code-Behind** (métodos que responden a eventos del usuario sobre la página).
- Muy sencillo de programar: ponías un botón, hacías doble clic y escribías el código.
- **Peor arquitectura** al no haber división entre la lógica de negocio y la capa de presentación.
- Pila: **IIS + Motor ASP.NET + CLR**.

### MVC (Modelo Vista Controlador)

Ver [[MVC (Model-View-Controller)]].

- Más difícil de programar, pero **arquitectónicamente más flexible, mejor diseñado y con mejor mantenimiento**. ≈ **jax-rs** de Java.
- Modelo de aplicación en el cual el flujo **siempre comienza por un "Controlador"**, que coordina tanto la lógica de negocio (**Modelo**) como la invocación posterior a la **Vista**.
- Cada Controlador tiene una **URL asociada** (similar a la configuración de los Servlet en el `web.xml` en apps JEE). Esto se configura en el **RouteConfig**.
- **Razor**: producto típico en esta arquitectura para implementar las Vistas como si fueran plantillas.

> [!example] Diagrama ASP.NET MVC Architecture (del PDF)
> `HTTP Request → Controller`; el Controller usa el `Model` (que accede a la BBDD) y pasa los datos (`View data`) a la `View`; la View devuelve la `Response HTML`.

| | Web Forms | MVC |
|---|---|---|
| Flujo comienza en | Páginas `.aspx` | Un Controlador (URL en RouteConfig) |
| Programación | Muy sencilla (doble clic en el botón) | Más difícil |
| Arquitectura | Peor: sin separación negocio/presentación | Más flexible, mejor mantenimiento |
| Vistas | `.aspx` + MasterPage (Razor la mejora) | Razor (plantillas) |
| Similar a | WinForms | ≈ jax-rs de Java |

### Servicios web en .NET

Un servicio web es una funcionalidad que publicas para que la usen terceros. Usada para integración de aplicaciones. Utilizados por aplicaciones. (Ver el tema [[B3 - T6 SERVICIOS WEB]].)

| | Servicios web SOAP | Servicios REST — Web API |
|---|---|---|
| Estándar | **Estándar de la W3C**. Basado en XML | **No** es estándar de la W3C, pero sí **estándar de facto**. Puro **HTTP** (Request) y **JSON** (Response) |
| Extensión / motor | `.asmx`. ≈ **jax-ws** de Java. Motor: **ASP.NET** para servicios SOAP | **ASP WEB API** para servicios REST .NET. ≈ **jax-rs** de Java |
| Qué hay que hacer | Solo dos elementos: **heredar de `System.Web.Services.WebService`** y **"anotar" con el atributo `[WebMethod]`** las operaciones que queramos publicar; el motor .NET se encarga de todo lo demás | Muy similar a MVC con 2 diferencias: **heredan de `ApiControler`** y **no retornan vista sino HTTP STATUS CODES** (ej. 200 + JSON) |
| Extra | Con **WCF** se podrían implementar funcionalidades extra (ej. WS-Security) | Los servicios REST no son para un usuario final: hace falta implementar un **cliente REST** (por ejemplo con AngularJS). Para pruebas sin desarrollar el cliente, **Postman** (similar a SOAPUI pero para REST). *Get* y *Post* son los nombres de los métodos |

## 6. Entorno de ejecución web

| Plataforma | Servidor | Detalles |
|---|---|---|
| **Windows** | **IIS** (Internet Information Server) | Motor de ejecución de código .NET, **servidor estático** (≈ Apache) y servidor **FTP**. **IIS + Runtime ASP.NET**: al instalar IIS se pueden activar *features* como el FTP Server o las *Application Development Features* (para usar páginas ASP.NET). Hay que activar el **ASP.NET Core Module** para que funcione una ASP.NET Core Application. **`web.config`** es el archivo que IIS y el módulo de ASP.NET Core leen para configurar una aplicación hospedada en IIS |
| **Linux** | **Kestrel Web Server** | Equivalente del IIS. Ya lleva implementado en sus tripas ASP.NET Core. Es multiplataforma |

## 7. Herramienta `dotnet`

Herramienta de **línea de comando** que genera aplicaciones (genera el proyecto). También permite compilar y ejecutar. ≈ **Maven**.

| Comando | Función |
|---|---|
| `add` | Añadir o actualizar un paquete al proyecto sobre el que estamos trabajando |
| `new` | Hay que indicar qué tipo de proyecto se quiere crear (`console`, `webapp`, `razor`, `classlib`, etc.); crea todo el árbol de directorios y ficheros de inicio para seguir desarrollando. Ya podría abrirse con Visual Studio |
| `run` | Compila y ejecuta |
| `build` | Compila el proyecto y sus dependencias |

## 8. Herramientas de automatización del desarrollo

- **MSBuild**: equivalente a los *plugins* de Maven. Sirve para definir tareas de compilación y empaquetado.
- **NuGet**: equivalente a la gestión de dependencias. Se puede ejecutar con el comando `nuget` o con `dotnet nuget`. Las librerías, al igual que Maven, están depositadas en **repositorios centrales**. **nuget.org** tiene las librerías para descargar el assembly (≈ `.jar`).

Formas equivalentes de instalar el mismo paquete (ejemplo del PDF, `iTextSharp` versión 5.5.13.3):

```bash
dotnet add package iTextSharp --version 5.5.13.3
```

```powershell
NuGet\Install-Package iTextSharp -Version 5.5.13.3   # comando de PowerShell
```

## 🔑 Resumen ultra-rápido

- .NET ≈ Java de Microsoft. Lenguajes (C#, F#, VB.NET) → compilador → **CIL** (antes MSIL, ≈ bytecode) → **CLR** (≈ JRE, implementación de VES) → JIT → código nativo.
- Assembly = CIL empaquetado en `.dll`/`.exe` (≈ `.jar`), visible con `ildasm.exe` (≈ `javap`). GAC ≈ classpath (`C:\Windows\Microsoft.NET\assembly`).
- CLI = todo el estándar .NET. VES = runtime de la CLI. CTS = tipos compatibles (clases, value types, interfaces, delegates). CLS = características de lenguajes compatibles.
- Historia: ECMA 335 / ISO 23271 (2001); .NET Framework 2002; .NET Core 2016 (multiplataforma, rival de Mono y DotGNU); desde 2020 un único .NET. BCL = .NET Standard. CLR sin cambios desde 2010 (v4.0); Framework en 4.8.1. C# = ECMA 334 (no es de Microsoft).
- C#: ≈ C/C++/Java, `{}` y `;`, case-sensitive, mayor uso. VB.NET: ≈ VB, `End If`/`End Sub`, case-insensitive, menor uso.
- Clases (`MustInherit`, `NotInheritable`, `Partial`), Estructuras (por valor, sin herencia pero con `Implements`, miembros públicos, campos sin inicializar), Módulos (todo `shared`, una instancia, sin herencia ni interfaces).
- Property = descriptor de acceso con `Get`/`Set` (`ReadOnly`/`WriteOnly`). Delegate = puntero a función (misma firma). Event + `RaiseEvent` + `Handles`.
- Por valor: primitivos y estructuras. Por referencia: strings, arrays, clases, delegados. Conversión número↔cadena con `CStr`. `Currency`→`Decimal`, `Variant`→`Object`.
- `virtual`/`Overridable` (se puede sobrescribir) · `sealed`/`NotOverridable` (no se puede; clase no heredable; abstracta no puede ser sealed) · `abstract`/`MustOverride` (hijos implementan).
- `Using` + `IDisposable` libera recursos. `Me` = this, `MyBase` = super, `Exit` = break. Constructor `New`, destructor `Finalize`.
- ADO.NET (JDBC): offline = DataSet + DataAdapter (XML interno, obsoleto); online = Connection/Command/Parameter/DataReader (≈ ResultSet), el programador escribe SQL.
- Entity Framework (JPA, ORM, desde 3.5): `Model.edmx`, sin SQL a mano; NHibernate = Hibernate en C#. LINQ (desde 3.5): misma consulta sobre memoria, BD o XML.
- Web: el CLR no entiende de web → motor **ASP.NET Core** (unifica ASP.MVC y Web API). `global.asax` (eventos de aplicación/sesión). Web Forms: `.aspx`, `.asmx` (servicios web), `.ashx` (manejadores HTTP), `System.Web.UI.Page`, MasterPage/Razor, Code-Behind; peor arquitectura. MVC: Controlador primero, RouteConfig, Razor.
- Servicios: SOAP (`.asmx`, W3C, XML, hereda de `WebService` + `[WebMethod]`, WCF para WS-Security; ≈ jax-ws). REST Web API (estándar de facto, HTTP+JSON, hereda de `ApiControler`, devuelve HTTP status codes, Postman; ≈ jax-rs).
- Entorno: Windows → IIS (+ ASP.NET Core Module, `web.config`); Linux → Kestrel (multiplataforma, lleva ASP.NET Core dentro).
- `dotnet`: `add`, `new`, `run`, `build` (≈ Maven). MSBuild ≈ plugins Maven. NuGet ≈ dependencias (nuget.org); `dotnet add package`, `Install-Package`, `PackageReference`, `paket add`, `nuget install`.

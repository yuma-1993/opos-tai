## Parte I — Arquitectura web y conceptos previos

### 1. Evolución de la arquitectura web

| Etapa | Tecnologías | Notas |
|---|---|---|
| Arquitectura web básica | HTML4 + CSS + JavaScript | JavaScript "propio": **JS Vanilla o JS puro**, sin frameworks ni librerías |
| Etapa AJAX | HTML4 + CSS + **AJAX** + librerías | AJAX es un **objeto JS**. La tecnología AJAX incluyó el objeto **XMLHttpRequest**. Se hace una petición al servidor en segundo plano y, cuando llegan los datos, se refresca **solo esa parte** de la página (de forma parcial); antes se refrescaba toda la página. Hace peticiones **asíncronas**. Librerías generales: jQuery, Dojo, YUI, ExtJS, Prototype, MooTools |
| Etapa moderna | **HTML5** + **CSS3** + frameworks | HTML5 aporta: APIs (funcionalidades), semántica (nuevas etiquetas) y multimedia |

Elementos de la etapa moderna:

| Elemento | Detalle |
|---|---|
| Editores | Atom, Sublime, VSCode |
| Preprocesadores CSS | Less, Sass, Stylus: son "superlenguajes" de estilo |
| Frameworks (MVVM) | MVVM es un patrón de arquitectura de software: **Modelo-Vista-Modelo de vista**, separando la parte visual del negocio. Ejemplos: Angular, ReactJS, Vue.js, Ember.js |
| Nuevos lenguajes | TypeScript (superlenguaje de JS), CoffeeScript, **ECMA 262 / ES 6 / ES 2015 / ECMAScript** |
| Herramientas | Gestores de dependencias (ayudan a la instalación y gestión de versiones): Bower, Yarn, npm. Automatizadores de tareas o *task runners* (compilar, optimizar código): Gulp / Grunt. Plantillas de proyectos: Yeoman |

> [!important] Actualización 20/05/2026 (recogida en el documento de actualizaciones, entrada del 31/10/2025)
> Corrección: el estándar de JavaScript es **ECMA 262**, no ECMA 242.

> [!note] Otras ideas de la arquitectura
> - **Tipo MIME**: lo usan los navegadores para identificar lo que se está procesando. Formato `tipo/subtipo`: `text/xml`, `application/pdf`. Ver [[Tipo MIME]].
> - Las **Rich Applications** hicieron mucho daño a los discapacitados. **WAI-ARIA** (*Accesible Rich Applications*): recomendaciones (ver sección de atributos ARIA).
> - **Tecnología CGI** o Script CGI (*Common Gateway Interface*): generaba páginas dinámicas con varios lenguajes, capaces de leer variables de entorno. Fue la primera tecnología que permitía crear rutinas web que realizaban ciertas tareas en el servidor. **Antesala de las aplicaciones web**.
> - **Transpiler**: software que a partir de un código en un lenguaje genera código en otro lenguaje. **S2S** = *source-to-source*.
> - **Pug** (antes llamado Jade) es un **motor de plantillas** para HTML: ahorra al desarrollador estar abriendo y cerrando etiquetas y luego lo traduce a etiquetas HTML. Otros: Handlebars, Mustache.

### 2. Librería vs API vs Framework

| Concepto | Qué es | Flujo de control / utilidad | Ejemplo |
|---|---|---|---|
| Librería | Conjunto de funciones y clases | El flujo de ejecución lo marca **el programa** | jQuery en JS; "itent" (sic, en el PDF) en Java |
| API | Capa de abstracción: conjunto de especificaciones que tiene que cumplir una serie de librerías | Poder **cambiar de librería sin cambiar el código del programa** | API JPA en Java/JEE y proveedores/implementación/librería: OpenJPA o Hibernate, para guardar objetos en BD relacional |
| Framework | Marco de trabajo: conjunto de clases que proporcionan una estructura base, una arquitectura base para generar aplicaciones | El flujo de control **no solo lo tiene tu programa, es compartido**: tú rellenas varias zonas de código. Ahorra esfuerzos en procesos transversales (seguridad, validaciones, optimizaciones...); tú solo te ocupas de tu línea de negocio | Angular, React, Vue... |

> [!important] Framework = inversión de control
> El framework **no es una herramienta para construir, sino para ejecutar**. Hay **inversión de control** porque el framework es quien manda, llamando a tu código cuando toca. En la librería, en cambio, llamas tú a la librería.

> [!note] Ampliación (conocimiento general, no viene del PDF)
> La inversión de control (IoC) es el mismo concepto de fondo que la inyección de dependencias de Spring y que el principio D de SOLID: ver [[Dependency Inversion Principle (DIP)]]. El patrón MVVM mencionado arriba es "primo" de [[MVC (Model-View-Controller)]] (ambos separan la parte visual de la lógica de negocio); ver también [[B3 - T4.1 PATRONES DE DISENO Y SOLID]].

### 4. HTML5: inicio y estructura semántica

El inicio de la página es `<!DOCTYPE html>`. **HTML5 no es un lenguaje SGML.**

> [!important] Estructura semántica
> Es un **estándar W3C que afecta al SEO**. La semántica es un **complemento a la accesibilidad**. Las etiquetas semánticas **no tienen representación visual**: ayudan a definir la estructura del documento, a los buscadores a indexar mejor las páginas, a los asistentes de discapacidad, etc.

Esquema de la distribución típica (diagrama del PDF): `<header>` arriba a todo el ancho; en el centro, de izquierda a derecha, `<nav>`, `<main>` y `<aside>`; abajo, a todo el ancho, `<footer>`.

| Etiqueta | Función |
|---|---|
| `<header>` | Encabezado |
| `<nav>` | Panel de navegación |
| `<main>` | Tema principal. Puede haber más de uno, pero **solo uno visible** y el resto `hidden` |
| `<section>` | Sección: estructuración de la información, una agrupación |
| `<article>` | Es **independiente** y puede ser visto, reutilizado y distribuido. Información contextualizada, completa |
| `<aside>` | Información tangencial, adicional, relacionada con la sección o artículo |
| `<footer>` | Pie de página |
| `<figure>` | Envuelve párrafos, imágenes, vídeos, ilustraciones con la información autocontenida |
| `<figcaption>` | Subtítulo o leyenda |

> [!important] `<section>` vs `<article>`
> `<section>` y `<article>` son estructuración de la información (agrupación). La diferencia: `<article>` es **independiente** (puede verse, reutilizarse y distribuirse por sí solo, información contextualizada y completa); `<section>` es una agrupación temática.

| `<var>` | Definir variables, con otro tipo de letra |
| `<kbd>` | Teclas de un teclado, con otro tipo de letra |
| `<code>` | Simular código fuente, con otro tipo de letra |
| `<iframe>` | Incrusta una página externa dentro de otra. **`sandbox`** aísla esa página externa por motivos de seguridad; se pueden modificar ciertas restricciones permitiendo comportamientos con `allow-*` |
| `<picture>` | Se usaba para que fuese *responsive*, eligiendo diferentes imágenes en función del tamaño |
| `<link>` | Relaciona |
| `<a>` | Enlaza a otro sitio |
| `<dialog>` | Ventanas emergentes |
| `<template>` | Crear plantillas y luego clonarlas |
| `<blockquote>`, `<cite>`, `<q>` | Se usan de modo diferente pero no suelen usarse |
| `<bdi>`, `<bdo>` | Para lenguajes árabes |

### 11. Extensibilidad de HTML5

#### Atributos personalizados `data-*` y Dataset API

Se pueden definir **atributos personalizados** (`data-*`). El **Dataset API** (JavaScript) permite acceder al atributo: `data-edad` → `elemento.dataset.edad`.

```html
<td data-codigo="47AF356" data-categoria="articuloEnOferta">
<!-- Objeto: td.dataset.categoria -->

<li id="marvel-1" data-comics="1423" data-sexo="M">Capitán América</li>
```

```css
li {
  color: blue;
}
li [data-sexo="F"] {
  color: magenta;
}
```

> [!important] Actualización 20/05/2026 (entrada del 22/01/2025)
> Errata corregida en el apartado de extensibilidad: `td..categoria` → `td.dataset.categoria`. En el apartado de APIs: `Web Worker` → `Web Workers`.

#### Microdatos (schema.org)

Se puede definir **semántica en base a unos "tipos"** de `https://schema.org` u otras webs. Son los **microdatos** y los usan los buscadores para indexar. `itemprop` son las diferentes propiedades asociadas al tipo: image, email, name, gender, blogposting, datepublishing, headline, etc.

```html
<section itemscope itemtype="http://schema.org/Person">
  <p>
    <img itemprop="image" src="foto.gif">
  </p>
  <p>
    <span itemprop="email">...</span>
    <span itemprop="name">...</span>
  </p>
</section>
```

> [!note] Errata del propio PDF
> El original escribe `scr="foto.gif"` en la imagen (errata de `src`).

| Atributo | Función |
|---|---|
| `id` | Identificador de elemento (tiene que ser **único**) |
| `class` | Clases de estilo definidas en las CSS (interna y externa) |
| `title` | Información al pasar el ratón por encima (*tooltip*) |
| `translate` | `yes`/`no`. Indica qué elementos deben ser traducidos |
| `style` | Estilos aplicados directamente a la etiqueta (*inline*) |
| `dir` | Dirección del texto. El árabe va al revés |
| `lang` | Idioma |
| `contenteditable` | `true`/`false`. Permite editar el contenido en memoria |
| `tabindex` | Para ir marcando el foco |
| `draggable` | *Drag and drop* |
| `spellcheck` | `true`/`false`. Habilita el corrector ortográfico |
| `hidden` | `true`/`false`. Indica que es un elemento oculto o no relevante |
| `aria-*` y `role` | Indica el propósito del elemento. Accesibilidad: **WAI-ARIA**. `<main>`, `<header>`, `<nav>`, etc. tienen **roles ARIA implícitos** |

> [!important] Atributo booleano (*boolean attribute*)
> Si está **presente es true, si no false**. **No se le puede asignar "true" o "false"**. True es el valor cadena vacía o su propio nombre. Equivalentes (el PDF aclara que podría aceptarse `disabled="disabled"`):

```html
<label><input type=checkbox checked name=cheese disabled> Cheese</label>
<label><input type=checkbox checked=checked name=cheese disabled=disabled> Cheese</label>
<label><input type='checkbox' checked name=cheese disabled=""> Cheese</label>
```

## Parte III — DOM y APIs de HTML5

### 13. API de DOM (W3C)

**DOM = Document Object Model.** Todos los elementos de una página se cargan en el navegador en forma de **árbol de objetos**. El **Virtual DOM** lo desarrolló Facebook (Meta) porque el DOM ocupaba mucha memoria.

Jerarquía de tipos de nodo:

| Tipo | Representa |
|---|---|
| `NODE` (raíz de la jerarquía) | Nodo genérico |
| `ELEMENT` | Etiqueta. **A las etiquetas se las llama Element** |
| `ATTR` | Atributo |
| `TEXT` | Texto |
| `DOCUMENT` | Un tipo **instrumental**. Representa a todo el documento. **Solo un nodo "Document" por página**. Tiene una extensión para HTML: *HTML Document* |

Árbol de ejemplo (diagrama): `Document` → *Root element* `<html>` → hijos `<head>` y `<body>`; `<head>` → `<title>` → Text "My title"; `<body>` → `<a>` (con atributo `href`) → Text "My link", y `<h1>` → Text "My header".

| Propiedades / métodos del Document | Función |
|---|---|
| `.documentElement` | Es la **raíz del documento**, la primera etiqueta, el propio `html` |
| `.firstchild` / `.childnodes` | Primer hijo / hijos |
| `.createElement(...)` | Antes de añadir un hijo hay que **crearlo** |
| `.appendChild(...)` | Añade un hijo |
| `.getElementById(...)` | Devuelve **un elemento** |
| `.getElementsByTagName(...)` | Devuelve una **lista** de nodos |
| `.getElementsByClassName(...)` | Devuelve una **lista** de nodos |
| `.getElementByName()` | (así aparece en el PDF) |
| `.hasAttributes(...)` | Comprueba atributos |
| `.querySelector(selector)` | Devuelve **un nodo**. Selectores: `#id`, `.class`, `etiqueta` |
| `.querySelectorAll(selector)` | Devuelve una **lista** de nodos |

> [!important] Selectors no es DOM
> **Selectors es un API propio, no es de DOM**: `.querySelector` y `.querySelectorAll` pertenecen a Selectors API (uno de los APIs de HTML5).

### 14. APIs de HTML5

Hay librerías que ayudan a **detectar las características que soporta el navegador**, como **MODERNIZR**, que detecta dinámicamente si el navegador tiene las APIs que usa mi código. Si el navegador no implementa el API de forma nativa, se puede simular con unos plug-in llamados **polyfills**: software en JS que se incrusta en la página. Funciona peor que el API nativo, pero hace que la página funcione en cualquier navegador.

| API | Función |
|---|---|
| Web Storage (Session Storage y Local Storage) | Guardar información en el navegador. **Session Storage se borra si cierro el navegador**. Clave-Valor. "Cookie 2.0" |
| Indexed DB | Base de datos **NoSQL** (ver [[B2 - T5 NOSQL Y BIG DATA]]) |
| Geolocation | Geolocalización |
| File | Controlas la subida de ficheros |
| Canvas | Lienzo |
| Microdata / Data Set | Extensibilidad |
| Drag and Drop | Arrastrar y soltar |
| Selectors | Métodos `.querySelector` y `.querySelectorAll` |
| Web Workers | Creas procesos *batch*, tareas asíncronas, **en segundo plano** |
| Web Socket / Server-Sent Events (SSE) | Comunicación **punto a punto** entre cliente web y servidor web. **Canal abierto que consume bastantes recursos**. **Web Socket es bidireccional**; en **SSE la información viaja del servidor al cliente** (ejemplo: sin que el cliente haga nada, el servidor manda un mensaje) |

> [!note] Ampliación (conocimiento general, no viene del PDF)
> HTTP es sin estado y de tipo petición-respuesta (ver [[B4 - T8 HTTP SSL TLS]]); por eso WebSocket y SSE, que mantienen un canal abierto, y Web Storage ("Cookie 2.0") resuelven necesidades que HTTP puro no cubre.

### 15. WHATWG y motores de los navegadores

**WHATWG** es una organización que mantiene y desarrolla HTML y APIs para las aplicaciones web.

| | Edge | Chrome | Opera | Firefox | Safari |
|---|---|---|---|---|---|
| **Motor JS** | V8 | V8 | V8 | SpiderMonkey | Nitro |
| **Motor de renderizado** | Blink | Blink | Blink | Gecko -> Quantum | Webkit |

- **Motor de JavaScript**: el software que ejecuta JS.
- **Motor de renderizado**: el software que pinta la página, mezclando el HTML, el CSS y los recursos multimedia.

## Ampliación (conocimiento general, no viene del PDF)

> [!note] Ampliación (conocimiento general, no viene del PDF)
> - Un **elemento de bloque** (`<div>`, `<p>`...) ocupa todo el ancho disponible y empieza en nueva línea; un **elemento en línea** (`<span>`, `<a>`...) fluye dentro del texto. Es la distinción que subyace a "Groups tags (block)" y "Text tags (inline)" de la hoja completa.
> - `async` y `defer` evitan que un `<script>` bloquee el análisis del HTML: `defer` ejecuta tras terminar el análisis y respeta el orden; `async` ejecuta en cuanto el script se descarga, sin orden garantizado.
> - Un elemento con `role` o semántica correcta (`<nav>`, `<main>`...) ya expone un rol ARIA implícito; la regla práctica de WAI-ARIA es no añadir `role`/`aria-*` si la etiqueta nativa ya lo cubre.

## 🔑 Resumen ultra-rápido (para repaso)

- Evolución: HTML4+CSS+JS vanilla -> AJAX (objeto JS **XMLHttpRequest**, peticiones asíncronas, refresco parcial) -> HTML5+CSS3+frameworks MVVM (Angular, React, Vue, Ember).
- Librería (flujo lo marca tu programa) vs API (capa de abstracción: cambiar de librería sin tocar código; ej. JPA con Hibernate/OpenJPA) vs Framework (flujo compartido, **inversión de control**; "para ejecutar, no para construir").
- CGI = primera tecnología de rutinas en servidor, antesala de las aplicaciones web. Transpiler = S2S. Pug (ex Jade), Handlebars, Mustache = motores de plantillas. Estándar JS: **ECMA 262** (no 242).
- MIME = `tipo/subtipo` (`text/xml`, `application/pdf`; SVG: `image/svg+xml`). WAI-ARIA = accesibilidad en Rich Applications.
- HTML5: `<!DOCTYPE html>`, **no es SGML**. Semántica = estándar W3C, afecta al SEO, sin representación visual: `header`, `nav`, `main` (solo uno visible), `section`, `article` (independiente), `aside`, `footer`, `figure`/`figcaption`.
- `<b>`/`<i>` = presentación; `<strong>`/`<em>` = importancia/énfasis semántico. `<iframe sandbox>` aísla; se relaja con `allow-*`.
- `target`: `_blank` (nueva), `_self` (por defecto), `_parent`, `_top`, `framename`.
- **Void elements** (sin "/" de cierre): area, base, br, col, command, embed, hr, img, input, link, keygen, meta, param, source, track, wbr.
- Formularios: nuevos `type` (color, date, datetime, email, month, number, range, search, tel, time, url); atributos list, autofocus/autocomplete, min/max, multiple, pattern (regex), placeholder, required.
- Extensibilidad: `data-*` + Dataset API (`elemento.dataset.edad`); microdatos (`itemscope`, `itemtype`, `itemprop`, schema.org) para buscadores.
- Atributos booleanos: presente = true; no se asigna "true"/"false". `id` único; `contenteditable`, `draggable`, `spellcheck`, `hidden`, `translate`, `dir`, `tabindex`.
- DOM: árbol de objetos; tipos NODE, ELEMENT (etiqueta), ATTR, TEXT, DOCUMENT (uno por página, `.documentElement` = raíz). `getElementById` -> 1 elemento; `getElementsBy...`/`querySelectorAll` -> lista; `querySelector` -> un nodo (Selectors API, no es DOM). Virtual DOM: Facebook/Meta.
- APIs HTML5: Web Storage (Session se borra al cerrar; clave-valor; "Cookie 2.0"), Indexed DB (NoSQL), Geolocation, File, Canvas, Microdata/Data Set, Drag and Drop, Selectors, **Web Workers** (segundo plano), WebSocket (**bidireccional**) / SSE (servidor -> cliente). Modernizr detecta; polyfills simulan.
- WHATWG mantiene HTML. Motores JS/render: Edge, Chrome, Opera = V8/Blink; Firefox = SpiderMonkey/Gecko->Quantum; Safari = Nitro/Webkit.
- Cheatsheets de Manz (lite en español y completo en inglés): estructura por categorías (texto, agrupación, listas, tablas, sección, scripting, multimedia, documento, head/metadatos, formularios, validaciones, ARIA, obsoletas, SVG, embedded...). Obsoletas clave: `<frame>` -> `<iframe>`, `<acronym>` -> `<abbr>`, `<strike>` -> `<s>`/`<del>`, `<center>`/`<font>`/`<big>`/`<tt>` -> CSS.

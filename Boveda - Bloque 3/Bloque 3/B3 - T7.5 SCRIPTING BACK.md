# Tema 7.5 · Bloque 3 — Scripting back (lenguajes de servidor)

> [!abstract] De qué va este tema
> Los lenguajes de scripting de backend son lenguajes interpretados que se ejecutan en el servidor. El tema compara el ecosistema de los cinco principales (gestor de paquetes, framework web, runtime), clasifica los paquetes "todo en uno" XAMPP/LAMP/WAMP/MAMP/LEMP/WIMP, presenta las arquitecturas JavaScript end-to-end MEAN/MERN/MEVN, repasa el lenguaje PHP (sintaxis, POO, traits, magic methods), cómo se ejecuta PHP bajo Apache (`mod_php` frente a FCGI/FPM) y los componentes principales de Laravel.

---

## 1. Introducción: scripting y backend

**Scripting**: son lenguajes **interpretados**. **Backend**: se ejecuta **en el servidor**.

### 1.1 Ecosistema por lenguaje

| | PHP | Ruby | Python | Perl | JavaScript |
|---|---|---|---|---|---|
| **Package Manager** (descarga dependencias transitivas) | **Composer**. `composer.json` guarda las librerías en el directorio `vendor`. Repositorio: http://packagist.org | **Gems**. `Gemfile`. http://rubygems.org. `gem install itext` | **Pip**. `setup.py`. https://pypi.org | **PPM**. ppm.activestate.com | **npm**. `package.json`. https://npmjs.com |
| **Web Framework** | Laravel, Symfony, Cake PHP, CodeIgniter | Ruby on Rails, Roda, Cuba | Django, Pyramid, Flask (orientado a crear microservicios) | Catalyst | Express (se ejecuta sobre Node; se instala con npm) |
| **Runtime** | Motor **Zend Engine** (≈ JVM) | — | — | — | Motor **V8** (Node) |

> [!important] Fichero del package manager
> Los ficheros del Package Manager, tipo `composer.json` o `package.json`, contienen las **dependencias del proyecto**.

> [!note] Ampliación (conocimiento general, no viene del PDF)
> Node.js es el entorno de ejecución que permite correr JavaScript fuera del navegador, y V8 es el motor de JavaScript de Google Chrome en el que se basa. Por eso el PDF coloca "Node" como runtime y "Express" como framework de la columna JavaScript.

### 1.2 Productos finales desarrollados en PHP

| Tipo de producto | Ejemplos |
|---|---|
| Cursos online | Moodle |
| Foros | phpBB |
| Gestor documental | Alfresco |
| Ecommerce | Magento, OSCommerce, Prestashop |
| Gestores de contenido (CMS), portales de noticias | WordPress, Joomla!, Drupal |

### 1.3 Paquetes "todo en uno": XAMPP, LAMP, WAMP, MAMP, LEMP, WIMP

Cuando quieres ejecutar una app con PHP que tira de una BD tienes que instalar Apache, habilitar el módulo de PHP, instalar MySQL, etc. La forma sencilla es utilizar una especie de **contenedor** que facilita todo el proceso de instalación y configuración. Producto: **EasyPHP**.

**XAMPP, LAMP, WAMP, MAMP, LEMP, WIMP**: software con lo necesario ya montado. El desarrollador pasa las páginas PHP a un directorio y funciona.

| Letra | Significado |
|---|---|
| 1ª | **L**: Linux · **W**: Windows · **M**: Mac · **X**: si es multiplataforma y se puede instalar en varios SO |
| 2ª | **A**: Apache · **E**: Nginx · **I**: IIS |
| 3ª | **M**: MySQL o MariaDB |
| 4ª | **P**: PHP inicialmente, pero ahora puede ser PHP o Perl o Python |
| 5ª | **P**: PHP y Perl. Es capaz de utilizar los 2 lenguajes, aunque nosotros solo desarrollemos en uno de ellos |

> [!tip] Cómo leer la sigla
> Siempre en el orden SO – servidor web – BD – lenguaje. **LEMP** = Linux + Nginx ("E") + MySQL + PHP. **WIMP** = Windows + **IIS** + MySQL + PHP.

> [!important] Actualización 20/05/2026 (listado de actualizaciones, entrada del 27/09/2025)
> Se añade **WIMP**, incluyendo **IIS como servidor web** en los sistemas de infraestructura. Ya está recogido en la tabla (2ª letra: I = IIS).

Para el servidor Apache concreto, ver [[B4 - T1.3 ADMON SSOO - APACHE]].

## 2. Arquitecturas MEAN, MERN y MEVN

Una pega de las arquitecturas **Cliente-Servidor** en web es que hay **mucha transformación de información** (Objetos a SQL, de SQL a Objetos, de Objetos a JSON, etc.). Esta arquitectura intenta paliar esa pega.

```
 BASE DE DATOS        SERVIDOR con una API REST          FRONTEND
 MongoDB  <-- 2. Consulta a la BD / 3. Respuesta de la BD -->  Node + Express  <-- 1. Llamadas AJAX al API REST / 4. Devuelve un objeto en JSON --> AngularJS
```

> [!example] Flujo del esquema del PDF (MongoDB – Express – Angular – Node)
> 1. El frontend (Angular) hace **llamadas AJAX al API REST**.
> 2. Node + Express **consulta a la base de datos** (MongoDB).
> 3. La BD devuelve la **respuesta**.
> 4. El servidor **devuelve un objeto en JSON** al frontend.

### MongoDB – Express – Angular – node

- **Angular** maneja la información en formato **JSON** de forma nativa.
- **Node** maneja la información de forma nativa en formato **JSON**.
- La información entre **Servidor y Frontend es JSON**. No se transforma.
- **MongoDB** es una base de datos **NoSQL de tipo documental** que maneja datos JSON (ver [[MongoDB]] y [[B2 - T5 NOSQL Y BIG DATA]]).
- La información entre **Servidor y BD es JSON**. No se transforma tampoco.

Estas arquitecturas son **JavaScript End-To-End** (de extremo a extremo), ya que no transforman la información.

| Sigla | Componentes | Frontend |
|---|---|---|
| **MEAN** | **M**ongoDB, **E**xpress, **A**ngular, **N**ode | Angular (de **Google**) |
| **MERN** | MongoDB, Express, **React**, Node | React (de **Facebook**) |
| **MEVN** | MongoDB, Express, **Vue.js**, Node | Vue.js |

> [!important] Qué cambia entre las tres
> Solo cambia el framework de frontend: si sustituimos Angular por React tenemos **MERN**; si en lugar de Angular o React utilizamos Vue.js, **MEVN**. MongoDB + Express + Node son comunes.

Un desarrollador **Fullstack** domina tecnologías back y frontend. Luego habrá que ver qué tecnologías concretas.

## 3. Lenguaje PHP

### 3.1 Sintaxis básica, comentarios y variables superglobales

**Variables superglobals**: `$_POST`, `$_GET`, `$_SERVER`, `$_FILES`, `$_COOKIE`, `$_SESSION`, `$_REQUEST`, etc.

```php
<html>
  ...
  <?php
     echo "...";
  ?>
  ...
</html>
```

**Comentarios**: `//` o `#` para comentarios de una sola línea. `/* ... */` para comentarios de varias líneas.

**Motores de persistencia (ORM)**: **Laravel** usa **Eloquent** y **Symfony** usa **Doctrine**.

### 3.2 Operadores

| Operador | Símbolo | Detalle |
|---|---|---|
| Concatenación | `.` | `$var3 = $var1.'script';` |
| Igualdad | `==` | compara **valor** |
| Idéntico | `===` | compara **valor y tipo** |
| Nave espacial | `<=>` | `$a <=> $b` → **-1** si `$a < $b`; **0** si `$a = $b`; **1** si `$a > $b` |
| Fusión de null (null coalescing) | `??` | `$usu = $_GET['usuario'] ?? 'nadie';` |

```php
$usu = $_GET['usuario'] ?? 'nadie';
// equivale al if en línea:
$usu = isset($_GET['usuario']) ? $_GET['usuario'] : 'nadie';
```

### 3.3 Variables, tipos de datos y funciones de arrays

```php
$var1 = 'PHP';
$var2 = 5;
$var3 = $var1.'script';
$datos = array('uno', 2, '3');
```

- **Tipos de datos**: Integer, Float, String, Array, Object, Boolean, NULL, Resource (ej.: `$f = fopen("f1.txt", "r"); var_dump($f);`).
- **Funciones**: `print` (funciona con o sin paréntesis); `sort` (ascendente), `rsort` (descendente), `asort` (por valor), `ksort` (por clave), `arsort`, `krsort`.
- `$productos['categoria1']` → **array asociativo ≈ hash table**. No accedes a la posición del array, sino a la **clave**.

> [!important] Comillas simples vs dobles
> Variables entre **comillas simples** NO las resuelve. Entre **comillas dobles** SÍ las resuelve:
> `echo '$var1';` → `$var1` · `echo "$var1";` → `30` (valor de la variable en el ejemplo del PDF).

### 3.4 Clases y objetos, constructores y herencia

```php
<?php
  class Cuadrado {
     public $lado = 2;
     public function f() {...}
  }
?>
```

Uso:

```php
<?php
  require "Cuadrado.php";
  $obj = new Cuadrado;
  echo $obj->f();   // Llama al método
?>
```

| Elemento | PHP | Equivalente en Java |
|---|---|---|
| Constructor | `public function __construct() { $this->...; }` | Nombre de la clase |
| Destructor | `__destruct()` | `finalize` |
| Referencia al objeto actual | `$this->...` | `this` |
| Eliminar objeto | `unset($obj)` | — |
| Miembros estáticos | `Clase::f()`; `self::atributoEstatico` (desde dentro de la clase) | `this` pero para cosas estáticas |
| Herencia | `class Empleado extends Persona { parent::... }` | `super` |
| Interfaces | `implements` | igual |
| Operador de tipo | `instanceof` | igual |
| `require` | incluir fichero | `import` |

- **No hay herencia múltiple.**
- **Visibilidad**: `public`, `private`, `protected`, `final` (evita sobrescrituras de clases y métodos).
- Para evitar muchos `require` en PHP se creó la función **autoload** `spl_autoload_register(...)`, similar a los **ClassLoader** de Java.

### 3.5 Magic methods

Empiezan por `__xxx` (doble guion bajo). Permiten realizar acciones en objetos cuando suceden determinados **eventos** que los activan. Se usan para acceder a *properties* no accesibles directamente. Ejemplos: `__construct()`, `__destruct()`, `__sleep()`, `__wakeup()`, `__get()`, `__set()`, `__call()`, etc.

### 3.6 Traits (rasgos / tratos)

Se usan para poder ofrecerle a alguien una serie de métodos **sin tener que usar herencia**. Es **programación por composición** (ver [[Composición sobre herencia]]). Elimina posibles ambigüedades, por ejemplo si "heredas" varias clases que contienen métodos que se llaman igual. Permite crear **alias** de métodos de clases.

> [!important] Orden de preferencia en caso de método con el mismo nombre
> **(+) Clase – Trato (trait) – Herencia (−)**
> - Si un método de la clase que usa un trait se llama igual que el del trait, tiene preferencia el **método de la clase**.
> - El método del trait tiene preferencia sobre el método de la **herencia**.

```php
trait Juego {
  function play(){
     echo "Jugando a un juego.".PHP_EOL;
  }
}

trait Musica {
  function play(){
     echo "Escuchando música".PHP_EOL;
  }
}

class Reproductor {
  use Juego, Musica {
     Musica::play insteadof Juego;
  }
}

$reproductor = new Reproductor;
$reproductor->play(); // Devuelve: Escuchando música.
```

`insteadof` resuelve la colisión indicando qué `play()` usar.

## 4. Arquitectura: PHP bajo Apache (`mod_php` vs FCGI/FPM)

```
                     Browser
                        |  GET /index.php
                     APACHE2
              /                     \
         mod_php                mod_proxy_fcgi
            |                         |
   (procesos Apache)                 FPM
            |                         |
       Apache fork            Pool de FPM Process
```

Si tengo una página PHP y la quiero ejecutar, tengo que instalar en el servidor **Apache2**, el **módulo php** o el **módulo proxy FCGI**.

| | `mod_php` | `mod_proxy_fcgi` (FCGI + FPM) |
|---|---|---|
| A nivel funcional | Sirve páginas HTML después de ejecutar el código PHP | Igual |
| A nivel de rendimiento | **Muy diferentes** | **Muy diferentes** |
| Cómo funciona | Hace un **fork del propio Apache** cada vez que se le pide algo PHP | Se generan **forks del intérprete de PHP**. **FPM es el gestor de FCGI** (pool de procesos FPM). Apache solo tiene que servir **recursos estáticos** |

## 5. Laravel: principales componentes

| Elemento | Qué es / comando | Equivalente (Angular/Java) |
|---|---|---|
| `laravel` | Se usa para **crear el proyecto**: `laravel new nominas` → crea el proyecto *nominas* | `ng new nominas` |
| `php artisan` | Se usa para **todo lo demás**. `artisan` es una **CLI** (herramienta de línea de comandos). `php artisan serve` → levanta el proyecto | `ng serve nominas` |
| **Seeder** | Llenar la BD con datos de prueba que **codificamos manualmente**. `php artisan make:seeder FacturasSeeder` | — |
| **Factory** | Llenar la BD con datos de prueba **de forma masiva**. Usa la librería **Faker** (datos inventados). `Profesor::factory(10)->create` | — |
| **Model** | Típicas **clases de negocio**: usuarios, pedidos, clientes, etc. | — |
| **Controller** | Recibe las **peticiones http** (≈ **servlet**). `php artisan make:controller FacturasController --invokable` → crea una clase con ese nombre. Dentro defines un método "xxx" con el código que sea. La URL del servicio será `/Facturas/xxx` | servlet |
| **Migrations** | **Versionar los scripts de BD**. Se programan los métodos `up` y `down`: el de ida y el de vuelta, el que hace y el que deshace. `php artisan migrate` → coge todas las migraciones que no se hayan ejecutado y las ejecuta | — |

> [!note] Ampliación (conocimiento general, no viene del PDF)
> La estructura Model / Controller de Laravel responde al patrón [[MVC (Model-View-Controller)]] (en Laravel la tercera pieza son las vistas, plantillas Blade). Las migraciones cumplen en la BD el mismo papel que el control de versiones en el código fuente (ver [[B3 - T9 METODOLOGIAS Y VERSIONADO]]).

## 🔑 Resumen ultra-rápido

- Scripting = lenguajes **interpretados**; backend = se ejecuta en el **servidor**.
- Package manager: PHP **Composer** (`composer.json`, carpeta `vendor`, packagist.org) · Ruby **Gems** (`Gemfile`) · Python **Pip** (`setup.py`, pypi.org) · Perl **PPM** · JavaScript **npm** (`package.json`). Bajan dependencias transitivas.
- Frameworks: PHP → Laravel, Symfony, Cake PHP, CodeIgniter · Ruby → Rails, Roda, Cuba · Python → Django, Pyramid, Flask (microservicios) · Perl → Catalyst · JS → Express (sobre Node).
- Runtimes: PHP **Zend Engine** (≈ JVM) · JS **V8**.
- Productos PHP: Moodle (cursos), phpBB (foros), Alfresco (gestor documental), Magento/OSCommerce/Prestashop (ecommerce), WordPress/Joomla!/Drupal (CMS).
- XAMPP/LAMP/WAMP/MAMP/LEMP/WIMP: 1ª letra SO (L, W, M, X multiplataforma) · 2ª servidor web (A Apache, **E Nginx**, **I IIS**) · 3ª M MySQL/MariaDB · 4ª P PHP (o Perl o Python) · 5ª P PHP y Perl. EasyPHP: contenedor.
- MEAN = MongoDB + Express + Angular (Google) + Node; MERN = React (Facebook); MEVN = Vue.js. **JavaScript end-to-end**: JSON de extremo a extremo, sin transformaciones. MongoDB = NoSQL documental.
- PHP: superglobals `$_POST $_GET $_SERVER $_FILES $_COOKIE $_SESSION $_REQUEST`. `==` valor, `===` valor y tipo, `<=>` nave espacial (-1/0/1), `??` null coalescing, `.` concatenación.
- Comillas simples no resuelven variables, dobles sí. Array asociativo ≈ hash table. `sort/rsort/asort/ksort/arsort/krsort`.
- POO PHP: `__construct`/`__destruct` (≈ constructor/finalize), `$this`, `parent::`, `self::`, `instanceof`, `unset`, `require` ≈ `import`, `spl_autoload_register`, **sin herencia múltiple**, visibilidad public/private/protected/final.
- Magic methods `__xxx` (`__get`, `__set`, `__call`, `__sleep`, `__wakeup`...).
- **Traits** = composición, sin herencia; preferencia **Clase > Trait > Herencia**; `insteadof` resuelve colisiones; admiten alias.
- ORM: Laravel → **Eloquent**; Symfony → **Doctrine**.
- Apache + PHP: `mod_php` (fork de Apache por petición) vs `mod_proxy_fcgi` + **FPM** (pool de procesos del intérprete PHP; Apache sirve solo estático). Misma función, distinto rendimiento.
- Laravel: `laravel new` (crear) · `php artisan` (todo lo demás; `serve`, `make:seeder`, `make:controller --invokable`, `migrate`) · Seeder (datos manuales) · Factory (masivo, Faker) · Model · Controller (≈ servlet) · Migrations (`up`/`down`).

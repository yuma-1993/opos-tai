## 1. Introducción

Historia: **Mocha → LiveScript → JavaScript → ECMAScript 262 / ES6 / ES2015 → estandarización de JavaScript**.

| | EDGE | CHROME | OPERA | FIREFOX | SAFARI |
|---|---|---|---|---|---|
| **Motor JS** | V8 | V8 | V8 | SpiderMonkey | Nitro |
| **Motor de renderizado** | Blink | Blink | Blink | Gecko → Quantum | Webkit |

Al navegador ya le llega todo traducido, así que **solo tiene que ejecutarlo**.

### 1.1 Estándares ECMA relacionados

| Estándar | Qué es |
|---|---|
| **ECMA 262** / ES6 / ES2015 | **JS** |
| **ECMA 334** | **C#** |
| **ECMA 335** | **CLI** |
| **ECMA 404** | **JSON** (ver [[B3 - T7.3 XML]]) |

### 1.2 Nuevos lenguajes, transpiladores y preprocesadores

- Nuevos lenguajes: **TypeScript** (Microsoft), **Dart** (Google), **CoffeeScript**, **ClojureScript** → **transpiladores**: **Babel**, **Traceur**, etc.
- El código se **transpila** porque algunos navegadores no entienden nuestro código, por eso debemos pasarlo a JavaScript.

| Se transforma a | Herramientas | Tipo |
|---|---|---|
| CSS | **Less, Sass, Stylus** | **Preprocesadores** |
| HTML | **Pug, Handlebars, Mustache** | **Motores de plantillas** |

- El compilador transforma el código en **código objeto**, no legible por humanos. `.java` → `javac` → `.class`.
- **HTML5** llama al código JS con la etiqueta `<script>` dentro de las páginas y **por eventos** (`onClick`, `onFocus`, etc.).
- **Node** es como la **JRE** de JS. **V8** es como la **JVM** dentro de la JRE.

> [!tip] Equivalencias con Java
> Node ≈ JRE · V8 ≈ JVM · transpilar ≈ `javac` de otro lenguaje a JS · npm/yarn ≈ gestor de dependencias tipo Maven.

### 2.1 npm y yarn

Ya no se usa Bower, sino **yarn** o **npm**. Ambas tiran del fichero **`package.json`**, donde están todas las dependencias. La utilidad de dependencias que se instala junto a Node es **npm**. **Yarn** descarga la dependencia y la guarda en **`node_modules`**.

| Herramienta | Comandos |
|---|---|
| **npm** | `init` (crea un nuevo proyecto), `install`, `update` |
| **yarn** | `init`, `install`, `upgrade`, `add` |

### 2.2 Empaquetadores y linters

- Bower, Gulp y Grunt ya no se usan en frontend porque por encima están los **package bundlers / empaquetadores**: **Webpack, Browserify, Fusebox, Rollup, Parcel** (diagrama del PDF de Webpack: *bundle your assets*, módulos con dependencias `.js`, `.hbs`, `.sass`, `.cjs`, `.png`... → activos estáticos `.js`, `.css`, `.jpg`, `.png`).
- **Linters**: herramientas de mejora del código mediante **análisis del código fuente**, con el objetivo de identificar fallos o problemas en el sistema. Productos: **ESLint, JSHint**.

> [!important] Qué sustituye a qué
> Bower → npm/yarn (dependencias). Gulp/Grunt → empaquetadores (Webpack, Rollup, Parcel...). Yeoman → CLI de cada framework (`ng new`...).

## 4. AJAX

- Es un nuevo **objeto dentro del navegador**. Es una **técnica de desarrollo** que favorece la creación de aplicaciones web **RIA**.
- Objeto **`XMLHttpRequest` (XHR)** presente en todos los navegadores. Realiza **peticiones HTTP asíncronas**: eventos. Mandas una petición y el navegador **no se queda esperando** la respuesta. **Peticiones en segundo plano. Recargas parciales de la página.**
- Existen guías específicas de accesibilidad para esto: **WAI-ARIA** (*Web Accessibility Initiative - Accessible Rich Internet Applications*).
- Desde AJAX se hace una petición a una URL del servidor. El servidor devuelve código **JSON** o **XML** (ver [[B3 - T7.3 XML]]).

### 4.1 `XMLHttpRequest`

| Categoría | Miembro | Descripción |
|---|---|---|
| **Estado** (indica si hay o no respuesta y el resultado) | `readyState` | Devuelve el estado del objeto. Valores importantes: **0 = sin inicializar; 4 = completado** (ha llegado respuesta, buena o mala) |
| | `status` | Devuelve el estado como número (ej.: **404 "Not Found"**, **200 "Ok"**). Con `readyState = 4` se comprueba con `status` si el resultado fue correcto |
| **Respuesta** (datos de la llamada) | `responseText` | Si devuelve **JSON** lo devolverá aquí |
| | `responseXML` | Si devuelve **XML** lo devolverá aquí |
| **Métodos** (`open` + `send`: primero se prepara la llamada y luego se manda) | `open(método, URL [, asíncrono [, nombreUsuario [, clave]]])` | Especifica método, URL y otros atributos opcionales. El método puede tomar los valores `"GET"`, `"POST"` o `"PUT"`. El parámetro asíncrono especifica si la petición se gestionará asíncronamente; en el caso asíncrono se especifican **manejadores de eventos**, ejecutados ante cada cambio de estado, que permiten tratar los resultados o gestionar errores |
| | `send([datos])` | Envía la petición |
| **Evento** (detectar cambios de estado) | `onreadystatechange` | Se dispara con **cada cambio de estado** |

### 4.2 Alternativas actuales: Fetch y Axios

Ya no se usa `open` + `send`. Ahora hay 2 opciones principalmente:

| Opción | Qué es |
|---|---|
| **Fetch** | Nueva API que **sustituye al XHR**. **No es un estándar** pero todos los navegadores lo incluyen. Internamente **devuelve una promesa** |
| **Axios** | Es una **librería** para hacer peticiones asíncronas |

```javascript
const request = fetch("/robots.txt");        // Realizamos la petición y guardamos la promesa
request.then(function(response) { ... });    // Si es resuelta, entonces ejecuta esta función...
```

> [!important] XHR → Fetch/Axios
> XHR = `open` + `send` + `onreadystatechange` (hoy en desuso). Fetch = promesas, nativo pero no estándar. Axios = librería.

## 5. Promesas, `async` y `await`

- Son **código asíncrono**. Objeto **`Promise`**. Te permite indicar qué hacer **tanto si va bien como si va mal**.
- Una promesa puede estar en estado **`pending`**, **`fulfilled`** (cumplida) o **`rejected`**.
- `.then` → cuando termine de ejecutarse, entonces hará otra cosa.
- Si encadenas muchos `then` se hace difícil de entender. Por eso ahora se usan **`async`** y **`await`**, para abandonar ese modelo de encadenamiento de `then`'s:
  - **`async`** se utiliza para **convertir una función en asíncrona**.
  - **`await`** se utiliza para **esperar el resultado** de una función asíncrona. Así no utilizamos el `then`.

```javascript
async function xx () {…}

const val = xx();               // Promise { <fulfilled>: 42 }
const val_async = await xx();   // 42
```

```javascript
const p1 = fetch("/robots.txt");
const p2 = fetch("/index.css");
const p3 = fetch("/index.js");

Promise.all([p1, p2, p3])
  .then(responses => {
    responses.forEach(response => {
      console.log(response.status, response.url);
    })
  });
```

```javascript
// pasas la función de cuando va bien (resolve) y mal (reject)
const myPromise = new Promise((resolve, reject) => {
  setTimeout(() => { resolve("foo"); }, 300);
});

myPromise
  .then(handleFulfilledA, handleRejectedA)
  .then(handleFulfilledB, handleRejectedB);

myPromise
  .then(handleFulfilledA)     // cuando vaya bien irá por aquí
  .then(handleFulfilledB)
  .catch(handleRejectedAny);  // cuando vaya mal irá por aquí
```

## 6. El lenguaje JavaScript

### 6.1 Características

| Característica | Detalle |
|---|---|
| Naturaleza | **Interpretado**, **dinámico**, **orientado a eventos** |
| Tests unitarios | Herramientas: **Jest, Mocha, Jasmine** |
| Orientación a objetos | JS **es un lenguaje orientado a objetos (POO)**. Objetos: `Navigator` → `Window` → `Document` |
| **Basado en prototipos** | Las funciones son objetos. Se les añade la propiedad **`prototype`** (herencia, constructor). Añade funciones a un objeto |
| **Funciones de primera clase** | Se tratan como cualquier otra variable: se pueden **asignar** a una variable, **pasar como parámetro** y **retornar desde otra función** |
| Expresiones regulares | `test` → devuelve `true/false`; `exec` → **extrae el patrón** indicado |
| **Clausuras o Closures** | Las funciones pueden acceder a valores fuera de su contexto |
| Promesas | (sección 5) |
| Clases | Añadido por **ES6** |
| *Array functions* (`forEach`, `map`, `filter`) | Añadido por **ES6** |
| *Arrow functions* ≈ lambda | Añadido por **ES6**: `function (a) {return a + 100}` → `a => a + 100` (`parámetros => expresión`) |

> [!note] Actualización 20/05/2026
> "**JS sí es un lenguaje orientado a objetos (POO)**." Aplicado: figura así en la tabla (el PDF original ya lo recoge con esa redacción).

> [!tip] Cuidado con el "¿es POO?"
> JS es POO **pero basado en prototipos** (no en clases como Java; las clases de ES6 son una adición). Los objetos del navegador se jerarquizan `Navigator` → `Window` → `Document`.

> [!note] Ampliación (conocimiento general, no viene del PDF)
> Las clases de ES6 son azúcar sintáctico sobre el sistema de prototipos (la propia cheatsheet lo indica: `class B extends A () { } class sugar syntax`).

### 6.2 Closures (clausuras)

> [!example] Ejemplo del PDF
> ```javascript
> function saltos(valor) {
>   var acumulado = 0;
>   return function () {
>     acumulado += valor;   // la función accede a la variable acumulado que está
>     return acumulado;     // fuera de la propia función. La variable acumulado
>   }                       // no se inicializa en cada llamada.
> }
> var quintos = saltos(5);
> quintos();  // Retorna 5
> quintos();  // Retorna 10
> ```

**Clausura**: técnica de programación funcional que sirve para **añadirle a una función un cierto contexto con datos**.

### 6.3 Variables

| Declaración | Ámbito / comportamiento |
|---|---|
| `var i = 10` → `typeof(i)` → `number` | `i` existe a **nivel de función** |
| `let nombre = 'pepe'` | `nombre` existe a **nivel de bloque** |
| `const nombre` | Para declarar **constantes** |
| `var numero = 3; numero = 3;` | **No es necesario declarar** las variables |

El nombre de una variable solo puede estar formado por **letras, números y los símbolos `$` y `_`**. **No puede empezar por un número.**

| **Boolean** | |
| **Array** | Ver tabla siguiente |
| **Object** | |
| **null** | |
| **Undefined** | Cuando no le has dado valor |

| Método de Array | Qué hace |
|---|---|

## 7. Eventos

### 7.1 Eventos principales

| Evento | Cuándo se produce |
|---|---|
| `focus` | Cuando haces click en el elemento o recibe el foco con el tabulador |
| `blur` | Cuando **pierde** el foco |
| `click` | Cuando haces click |
| `keypress` | Cuando pulsas una tecla |
| `input` | Cuando introduces texto en una caja de texto |
| `select` | Cuando seleccionas una parte del texto dentro de un objeto de tipo texto |
| `change` | Cuando cambias el valor de un *combo box* (objeto de tipo `select`). También al perder el foco tras cambiar el contenido del objeto |

### 7.2 Fases de propagación del evento

| Fase | Nombre | Qué ocurre |
|---|---|---|
| **1** | **Captura** | Se recoge el evento en el *root* y **baja** hasta el objeto desde el que se ha generado el evento |
| **2** | **Target** | Gestionamos el evento **en el propio objeto** que lo ha generado |
| **3** | **Burbujeo o propagación** | El evento **sube** por todos los padres desde el objeto que lo ha generado hasta el *root* |

(Diagrama del PDF: `Window` → `Document` → `html` → `body` → `table` → `tbody` → `tr` → `td`; capture phase bajando, target phase en el `td`, bubbling phase subiendo.)

- La captura y el burbujeo sirven para hacer **manejadores generales**. Por ejemplo, si quieres trazar todos los clicks, no los programas en cada uno de los objetos, sino **en la raíz**.
- **`stopPropagation()`** → no burbujear. **Puedes parar el burbujeo pero no la captura.**
- **`preventDefault()`** → previene el **comportamiento por defecto**. Podemos controlar o cancelar el comportamiento por defecto. Por ejemplo, cuando pinchamos en un enlace, podemos evitar que se abra dicho enlace y, por ejemplo, mostrar un mensaje.
- Ya que podemos estar subiendo o bajando en el árbol, tenemos las **propiedades**:

| Propiedad | Qué es |
|---|---|
| `event.target` | **Objeto original** que ha provocado el evento |
| `event.currentTarget` | **Objeto actual** en el que estamos tratando el evento |

> [!note] Actualización 20/05/2026 (entrada del 30/08/2024)
> Corrección: `evento.target` y `evento.currentTarget` son **propiedades, no métodos**. Aplicado.

> [!tip] Cómo distinguir
> `target` = quien originó el evento (el más profundo). `currentTarget` = el elemento en el que se está ejecutando ahora el manejador (cambia mientras burbujea).

> [!note] Ampliación (conocimiento general, no viene del PDF)
> Es el patrón [[Observer (patrón GoF)]] (suscripción a eventos) y el burbujeo recuerda a una cadena de manejadores como [[Chain of Responsibility (patrón GoF)]] (el evento pasa por los padres hasta que alguien lo trata o se detiene con `stopPropagation()`).

### 7.3 Eventos de marco/objeto HTML (tabla del PDF)

| Categoría | Tipo | Atributo | Descripción | Burbujeo (`stopPropagation()`) | Cancelable (`preventDefault()`) |
|---|---|---|---|---|---|
| Marco / Objeto HTML | `load` | `onload` | Cuando el agente de usuario termina de cargar todo el contenido de un documento, incluidas ventanas, marcos, objetos e imágenes. Para los elementos, se activa cuando el elemento de destino y todo su contenido han terminado de cargarse | No | No |
| | `unload` | `onunload` | Cuando el agente de usuario elimina todo el contenido de una ventana o marco. En el caso de los elementos, se activa cuando se elimina el elemento de destino o cualquiera de sus contenidos | No | No |
| | `abort` | `onabort` | Se activa cuando se detiene la carga de un objeto/imagen antes de que se cargue por completo | Sí | No |
| | `error` | `onerror` | Se dispara cuando un objeto/imagen/marco no se puede cargar correctamente | Sí | No |
| | `resize` | `onresize` | Se activa cuando se cambia el tamaño de la vista de un documento | Sí | No |
| | `scroll` | `onscroll` | Se activa cuando se desplaza la vista de un elemento o documento | No, excepto que un evento de desplazamiento en el documento debe aparecer en la ventana | No |

## 8. Funciones y operadores

### 8.1 Funciones

- Son **objetos** a los que se les añade una propiedad llamada **`prototype`** (herencia, constructor).
- **En JS lo más importante son las funciones.** Se pueden **asignar a una variable**, **pasar como parámetro** y **retornar desde otra función**.

| Definición de función | Sintaxis |
|---|---|
| Declaración | `function [nombre] ([param], …) { cuerpo }` |
| Flecha | `([param], …) => { cuerpo }` |
| Constructor `Function` | `new function (arg1, arg2, …, argN, "cuerpo")` |
| **Autoejecutable (IIFE)** | `(function () { cuerpo }) ();` — **Expresión de función invocada inmediatamente** |
| Clausura | `function (…) { var x; return function interna (…) }` |

### 8.2 Resumen de operadores y comparación

| Aspecto | Detalle |
|---|---|
| Exponenciación | `**` ≈ `Math.pow(a, b)` |
| Resto de la división | `%` (módulo) |
| **`===`** | Compara **valor y tipo** |
| **`==`** | Compara valor **pero no tipo** |
| Ejemplo | `1 == "1"` → **true** · `1 === "1"` → **false** |
| Asignación | `=` |
| Aritméticos | `+`, `-`, `*`, `/`, `%`, `**` |
| Lógicos | `!`, `&&`, `\|\|` (**cortocircuito**) |
| Relacionales | `>`, `<`, `>=`, `<=`, `==`, `!=` |
| Otros | `typeof`, `instanceof`, `delete`, `void`, `in` |

> [!important] `==` vs `===`
> `==` compara solo el valor (hace conversión de tipos): `1 == "1"` es `true`. `===` compara valor y tipo: `1 === "1"` es `false`. Sobre `typeof`/`instanceof` en otros lenguajes (Java/.NET): [[instanceof vs isInstance vs typeof]].

### 8.3 Operadores aritméticos

| Nombre | Operador | Descripción |
|---|---|---|
| Suma | `a + b` | Suma el valor de a al valor de b |
| Resta | `a - b` | Resta el valor de b al valor de a |
| Multiplicación | `a * b` | Multiplica el valor de a por el valor de b |
| División | `a / b` | Divide el valor de a entre el valor de b |
| Módulo | `a % b` | Devuelve el resto de la división de a entre b |
| Exponenciación | `a ** b` | Eleva a a la potencia de b, es decir, a^b. Equivalente a `Math.pow(a, b)` |

### 8.4 Operadores de asignación

| Nombre | Operador | Descripción |
|---|---|---|
| Asignación | `c = a + b` | Asigna el valor de la parte derecha (en este ejemplo, una suma) a c |
| Suma y asignación | `a += b` | Equivale a `a = a + b` |
| Resta y asignación | `a -= b` | Equivale a `a = a - b` |
| Multiplicación y asignación | `a *= b` | Equivale a `a = a * b` |
| División y asignación | `a /= b` | Equivale a `a = a / b` |
| Módulo y asignación | `a %= b` | Equivale a `a = a % b` |
| Exponenciación y asignación | `a **= b` | Equivale a `a = a ** b` |

### 8.5 Operadores unarios

| Nombre | Operador | Descripción |
|---|---|---|
| Incremento | `a++` | Usa el valor de a y luego lo incrementa. También llamado **postincremento** |
| Decremento | `a--` | Usa el valor de a y luego lo decrementa. También llamado **postdecremento** |
| Incremento previo | `++a` | Incrementa el valor de a y luego lo usa. También llamado **preincremento** |
| Decremento previo | `--a` | Decrementa el valor de a y luego lo usa. También llamado **predecremento** |
| Resta unaria | `-a` | Cambia de signo (niega) a a |

### 8.6 Operadores de comparación

| Nombre | Operador | Descripción |
|---|---|---|
| Igualdad | `a == b` | Comprueba si el valor de a es igual al de b. **No comprueba tipo de dato** |
| Desigualdad | `a != b` | Comprueba si el valor de a no es igual al de b. **No comprueba tipo de dato** |
| Mayor que | `a > b` | a mayor que b |
| Mayor/igual que | `a >= b` | a mayor o igual que b |
| Menor que | `a < b` | a menor que b |
| Menor/igual que | `a <= b` | a menor o igual que b |
| Identidad | `a === b` | Comprueba si el **valor y el tipo de dato** de a es igual al de b |
| No idéntico | `a !== b` | Comprueba si el **valor y el tipo de dato** de a no es igual al de b |

### 8.7 Operadores binarios (a nivel de bit)

| Nombre | Operador | Descripción |
|---|---|---|
| AND | `a & b` | Devuelve 1 si ambos operandos son 1 |
| OR | `a \| b` | Devuelve 1 si al menos un operando es 1 |
| XOR (OR exclusivo) | `a ^ b` | Devuelve 1 si ambos operandos son diferentes |
| NOT (unario) | `~a` | Invierte los bits del operando (ej.: `000101` pasa a `111010`). **Trunca a 32 bits** |
| LEFT SHIFT | `a << b` | Desplazamiento de bits a la izquierda. Ej.: `11` (3) pasa a `110` (6) |
| RIGHT SHIFT | `a >> b` | Desplazamiento a la derecha. Ej.: `11` (3) pasa a `1` (1). **Metemos el valor del signo** |
| RIGHT SHIFT sin signo | `a >>> b` | Desplazamiento a la derecha como operador sin signo. **Metemos ceros.** Siempre dará un valor positivo. CA2 → -1 → CA1 → (-1) × valor positivo |

| Asignación a nivel de bit | Operador | Equivale a |
|---|---|---|
| Desplazamiento a la izquierda y asignación | `a <<= b` | `a = a << b` |
| Desplazamiento a la derecha y asignación | `a >>= b` | `a = a >> b` |
| Desplazamiento a la derecha sin signo y asignación | `a >>>= b` | `a = a >>> b` |
| AND y asignación | `a &= b` | `a = a & b` |
| OR y asignación | `a \|= b` | `a = a \| b` |
| XOR y asignación | `a ^= b` | `a = a ^ b` |
| AND lógico y asignación | `a &&= b` | `a && (a = b)` |
| OR lógico y asignación | `a \|\|= b` | `a \|\| (a = b)` |

### 8.8 Operadores lógicos

| Nombre | Operador | Descripción |
|---|---|---|
| AND lógico | `a && b` | `true` si ambas son verdaderas; `false` si alguna es falsa |
| Ternario `?:` | `a ? b : c` | Si a es `true`, devuelve b, si no devuelve c |
| OR lógico | `a \|\| b` | `true` si alguna es `true`; `false` si ambas son falsas |
| **Nullish coalescing** | `a ?? b` | Devuelve b si a es `null` o `undefined`, si no devuelve a |
| Asignación lógica nula `??=` | `a ??= b` | Equivale a `a ?? (a = b)` |
| **Encadenamiento opcional** `?.` | `data?.name` | Permite intentar acceder a una propiedad, aunque su padre no exista |
| NOT lógico | `!a` | Invierte el valor. Si es `true` devuelve `false` y viceversa |

> [!note] Ampliación (conocimiento general, no viene del PDF)
> Con `a ?? b` un valor como `0` o `""` **no** se sustituye (solo `null`/`undefined`), a diferencia de `a || b`, que sustituye cualquier valor "falsy".

## 🔑 Resumen ultra-rápido (para repaso)

- Historia: Mocha → LiveScript → JavaScript → ECMAScript 262 / ES6 / ES2015. Motores: V8 (Edge, Chrome, Opera), SpiderMonkey (Firefox), Nitro (Safari). Renderizado: Blink, Gecko→Quantum, Webkit. ECMA 262 = JS · 334 = C# · 335 = CLI · 404 = JSON.
- Node ≈ JRE; V8 ≈ JVM. Transpiladores (Babel, Traceur) para TypeScript/Dart/CoffeeScript/ClojureScript. Preprocesadores CSS: Less, Sass, Stylus. Motores de plantillas HTML: Pug, Handlebars, Mustache.
- Obsoletos: Bower (dependencias, `bower.json`), Gulp/**Grunt** (tareas), Yeoman (estructura de proyecto ≈ archetypes Maven). Hoy: **npm** / **yarn** (`package.json`, `node_modules`), CLI de cada framework (`ng new`, `ng serve`), empaquetadores (Webpack, Browserify, Fusebox, Rollup, Parcel) y linters (ESLint, JSHint).
- DOM API: modificar/crear/eliminar nodos. `onclick` (método JS) vs `onClick` (atributo HTML); `addEventListener("click", ...)`.
- AJAX = XHR; peticiones HTTP asíncronas en segundo plano, recargas parciales; devuelve JSON o XML. `readyState` 0 = sin inicializar / 4 = completado; `status` 200/404; `responseText` (JSON) / `responseXML`; `open` + `send`; `onreadystatechange`. WAI-ARIA para accesibilidad.
- Hoy: **Fetch** (sustituye a XHR, no estándar, devuelve promesa) y **Axios** (librería).
- Promesas: `pending`, `fulfilled`, `rejected`; `.then`, `.catch`; `async` (función asíncrona) + `await` (espera resultado, sin `then`); `Promise.all`.
- JS: interpretado, dinámico, orientado a eventos, **POO basada en prototipos**, funciones de primera clase, closures, regex (`test` true/false; `exec` extrae). ES6: clases, array functions, arrow functions. Tests: Jest, Mocha, Jasmine.
- Variables: `var` (función), `let` (bloque), `const`. Nombre: letras, números, `$`, `_`; no empieza por número. Tipos: Number (Infinity, NaN), String, Boolean, Array, Object, null, Undefined.
- Array: `push`/`pop` (final), `forEach`, `map` (nuevo array), `reduce` (un valor), `filter`, `slice` (rango), `splice` (añade/borra/reemplaza). `JSON.stringify` (objeto → cadena) / `JSON.parse` (cadena → objeto).
- Eventos: `focus`, `blur`, `click`, `keypress`, `input`, `select`, `change`. Fases: 1 captura (baja) → 2 target → 3 burbujeo (sube). `stopPropagation()` para el burbujeo (no la captura); `preventDefault()` cancela el comportamiento por defecto. `event.target` (origen) y `event.currentTarget` (actual) son propiedades.
- Eventos HTML: `load`/`unload` no burbujean; `abort`/`error`/`resize` sí; ninguno cancelable; `scroll` no burbujea (salvo en el documento).
- Funciones: objetos con `prototype`; IIFE `(function(){...})()`; clausura = función + contexto con datos.
- Operadores: `**` ≈ `Math.pow`; `==` (valor) vs `===` (valor y tipo); `&&` `||` con cortocircuito; `??` (nullish), `?.` (optional chaining), `??=`; `>>` mete signo, `>>>` mete ceros; `~` trunca a 32 bits.
- Cheatsheet Manz: API de `Number`, `String`, `Array`, `Regexp`, `Date`, `Function`, `Math`, `Object`, `Promise`, `Proxy`, `Symbol`, `Set`/`Map`, `Generator`, módulos ES, `window`, `screen`, `console`, `navigator`, `location`, `history`, `localStorage`/`sessionStorage`, `document`, `Element`, `Node`, `Event`.

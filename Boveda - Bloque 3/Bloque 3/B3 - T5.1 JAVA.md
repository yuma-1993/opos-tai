**Ecosistema Java SE** = Infraestructura de ejecución + Lenguaje + Herramientas/Librerías de terceros.

### 2. Ejecución: JRE (Java Runtime Environment)

**JRE** = Intérprete (Máquina Virtual Java) + librerías de clases BASE (`rt.jar`: *RunTime*, contiene los `.class`). Usado en entornos de producción. **JVM** es el software que sirve para ejecutar el código Java compilado (bytecode). Ahora, en lugar de `rt.jar`, está el **módulo `java.base`**.

Esquema de la JRE (diagrama del PDF):

```
JRE
└── JVM
    ├── Class Loader  ── carga en memoria los .class
    ├── Memoria: Heap (Obj1, Obj2, ...) | Stack (info de los hilos: Thread1, ...) | Registros
    ├── JIT (Just In Time Compiler)  ·  GC (Garbage Collector)
    └── Motor de Ejecución (Threads)
+ RT.jar
```

> [!important]
> **JDK** = construir (javac, jar, javadoc...). **JRE** = ejecutar (JVM + librerías base). La compilación produce **bytecode**, no código nativo: el programa se compila para un procesador **virtual** (JVM), no para uno concreto.

- **Java Virtual Machine Specifications**: existen para que cualquiera pueda hacer una JVM propia.
- **Write once, run anywhere**: los programas Java son portables. No se compilan para un procesador concreto, sino para uno virtual (JVM).

#### CLASSPATH

`java` (intérprete). **CLASSPATH**: variable de entorno que usa la JVM para localizar y cargar clases que usa tu programa (ni las tuyas propias, ni las del `rt.jar`). En realidad se manejan **tres "classpath"** (ver concepto de *ClassLoader* dentro de la JRE). Formas de informar un classpath:

| Nº | Forma |
|---|---|
| 1 | Variable de entorno `CLASSPATH` |
| 2 | *Property* que estableces cuando se llama al intérprete, en el momento de lanzar la app. Ej: `java -classpath /.../.../lib.jar` |
| 3 | En el fichero `Manifest.mf` existe un campo llamado `Class-Path: ruta(s)` (dentro de un fichero `.jar`). El `.jar` contiene los `.class` y `/META-INF/MANIFEST.MF` |

#### Threads o hilos

Son los recursos encargados de que los distintos métodos se ejecuten: ejecutan las instrucciones del programa. La JVM tiene algoritmos de planificación para hilos. Las apps con método `main()` son **monohilo**; las apps web sí tienen más hilos. Existen hilos predefinidos (como el *Garbage Collector*, `System.gc()`), pero también podríamos crear nuestros propios Threads (en web no es normal).

> [!tip]
> El **método** es pasivo y el **Thread** es activo. El método es la receta y el hilo el cocinero. El hilo es la única entidad capaz de ejecutar el código de los métodos.

Los hilos en sistemas operativos (conceptos generales de planificación, pila por hilo, etc.) se estudian en [[B2 - T4.1 SISTEMAS OPERATIVOS]].

## Parte II — El lenguaje

Java es **orientado a objetos**. Conceptos: clase, objeto, encapsulación, herencia, sobrecarga y polimorfismo/ligadura dinámica (ver [[Polimorfismo (POO)]] y [[Sobrecarga (overloading) vs Sobreescritura (overriding)]]).

### 3. Conceptos de POO en Java

| Concepto | Qué dice el PDF |
|---|---|
| Encapsulación | Es una interface, un procedimiento para solo poder acceder a los atributos mediante los métodos. Nadie puede acceder a los atributos directamente desde fuera de la clase. Cuanto más desacoplados estén dos partes de un programa, más fácil es su mantenimiento; cuanto menos conozcan los detalles una de otra. El polimorfismo persigue que dos módulos vean lo mínimo posible el uno del otro |
| Herencia | Sin herencia no hay sobrescritura. La herencia en Java es **simple**: un único padre. Se pueden implementar más de un interface, pero solo se puede heredar de **una** clase (ver [[Composición sobre herencia]]) |
| `Object` | Cualquier clase de Java hereda de `Object`. Es la "clase cósmica" |
| Objeto | Instancia de una clase en memoria. `this`: elemento actual. `super`: referencia al objeto padre. Superclase: la clase de la que heredas |
| Constructor | Método utilizado para inicializar. También se lanzan los constructores de los padres. Java crea uno por defecto, pero si nosotros codificamos uno, elimina el constructor por defecto |
| `finalize()` | Encargado de eliminar el objeto de memoria; lo llama el *Garbage Collector* |
| Referencias | En Java todo son referencias, excepto los tipos de datos primitivos |
| `==` | Compara **referencias**, no contenidos. No se usa para igualar objetos. Para comparar contenido se sobrescribe el método `equals` de `Object` |
| Casting | Proceso de convertir un objeto de una clase a otra |

```java
public abstract class Ciudadano extends Persona implements Guardable, Clonable {...}
```

| Relación | Palabra clave |
|---|---|
| Entre clases | `extends` |
| Entre interfaces | `extends` |
| Entre clase e interface | `implements` |

> [!important]
> Clase → clase: `extends`. Interface → interface: `extends`. Clase → interface: `implements`. Herencia simple de clases, pero **múltiples interfaces**.

### 4. Genericidad

**Tipos genéricos**: cuando mi clase es un grupo de cosas, pero no especifico qué tipo de cosas. Cuando se usa la clase hay que indicar qué tipo de cosa va a contener. Letras convencionales: **E**: Element; **K**: Key; **T**: Type; **N**: Number; **V**: Value.

```java
public class Box<T> {...}
```

**Bounded** (acotados): en tipos genéricos, restringes el tipo de cosa (*Bounded Wildcard*).

```java
public class NaturalNumber<T extends Integer>   // tipos que hereden de Integer
```

| Familia | Subfamilia | Tipos |
|---|---|---|
| Primitivos | Numéricos enteros | `byte`, `short`, `int`, `long` |
| Primitivos | Numéricos en punto flotante | `float`, `double` |

### 6. Elementos de programación básicos

#### Clases y modificadores

**Clases**: atributos de datos, métodos y atributos de relación (≈ TAD). Suelen empezar por mayúscula. Modificadores principales:

| Modificador | Significado |
|---|---|
| `final` | No permite heredar la clase, o el atributo no puede modificarse y actúa como constante, o no puede sobrescribirse un método |
| `static` | Los métodos de instancia se ejecutan sobre un objeto concreto. Los métodos de clase o estáticos no están asociados a ninguna instancia: son globales, pertenecen a la clase. Los hijos de la clase que define un método estático no tienen acceso a lo estático: lo estático es solo de la clase que lo define. La herencia es solo para los métodos de instancia, no para los estáticos |
| `abstract` | No sabemos implementar un método, pero sí que esa clase debe tenerlo. Obliga a que la clase también sea abstracta. De una clase abstracta **no se pueden crear objetos** (no puede instanciarse): es una base para usarla mediante herencia. El hijo debe implementar el método o definirlo de nuevo como `abstract` y pasar la responsabilidad al nieto. Se usa la anotación `@Override` encima de la definición del método para sobrescribirlo |
| `private` | El atributo o método solo se puede usar dentro de la clase. Se hereda pero no se puede usar en los hijos (no es accesible). Los métodos de la clase que implementan los atributos private sí pueden acceder a ellos; los hijos acceden a los atributos private a través de los métodos |
| `public` | Se puede usar desde cualquier sitio, dentro o fuera de la clase, dentro o fuera del paquete |
| `protected` | Puede usarse en la herencia, pero no fuera, a menos que esté dentro del mismo paquete. Protegido para la herencia y para el paquete |
| `native` | Defino un método que no va a definirse en Java, sino en otro lenguaje (ej. C++ en librerías de terceros). **JNI** es la API utilizada |
| `volatile` | Una variable dentro de un método es una variable local; cada hilo tiene en una zona de memoria las variables locales. Con `volatile` indicas al hilo que el valor de la variable debe buscarlo en **memoria principal**, no en su caché, ya que si hay concurrencia ese valor en caché puede estar desactualizado. Eliminamos inconsistencias. Usado para atributos |
| `transient` | Usado para atributos. Java permite guardar un objeto de la memoria en el disco o mandarlo por la red: a ese proceso se le llama **serialización**. `transient` es para **no serializar** un atributo. Por defecto se puede serializar todo |
| `synchronized` | Por defecto, en Java, atravesando un método, puede haber varios hilos. `synchronized` hace que un método o una parte de código de un método solo sea ejecutado por un hilo cada vez; el resto de hilos se bloquean y quedan a la espera en una cola |
| `default` | Si no especificas la visibilidad, usa una por defecto: visibilidad a nivel **paquete**. No hay visibilidad en subpaquetes ni en paquetes diferentes. La herencia solo daría visibilidad si la clase y subclase están en el mismo paquete |

#### Tabla de visibilidad

| Desde dónde | Default | Private | Protected | Public |
|---|---|---|---|---|
| Misma clase | Sí | Sí | Sí | Sí |
| Mismo paquete, clase heredada | Sí | No | Sí | Sí |
| Mismo paquete, clase no heredada | Sí | No | Sí | Sí |
| Diferente paquete, clase heredada | No | No | Sí | Sí |
| Diferente paquete, clase no heredada | No | No | No | Sí |

> [!tip]
> Regla mnemotécnica de lectura: `public` = siempre Sí. `private` = solo la misma clase. `default` = solo el mismo paquete. `protected` = mismo paquete + subclases de otros paquetes (única diferencia con `default`: la fila "diferente paquete, clase heredada").

#### Otros elementos

- **Paquetes**: agrupación de clases. Hay que importarlos para usar sus clases salvo los del paquete `java.lang`. Los paquetes en Java se organizan físicamente dentro del jar en carpetas/directorios.
- **Modules**: técnica de agrupación por encima de los paquetes.
- **Interfaces**: definición funcional pura, sin código (hasta la versión 1.7). Es un esqueleto funcional, una clase con métodos vacíos. ≈ Clase abstracta pero sin atributos. Es un **contrato funcional** enumerado: obliga a cumplir el 100 % de una especificación funcional. Obliga a implementar.
- **Enum**: valores enumerados.

```java
public enum Demarcacion {Portero, Defensa, Centrocampista, Delantero}
Demarcacion delantero = Demarcacion.Delantero;
```

- **Record**: usado para almacenar valores y agruparlos en un único identificador. Implementación del patrón **DAO** (ver [[Patrones J2EE (DAO, Intercepting Filter, Composite View)]]). Desde la **JDK 14** y estable desde la **17**. (*Actualización 20/05/2026: añadido como elemento de programación básico.*)
- **Anotaciones**: usadas para configurar el código. Metainformación. Sustituyen a los ficheros XML de configuración.

```java
public @interface xxx            // crea una anotación propia
@Target({ElementType.METHOD})    // en qué lugares se puede aplicar la anotación
@Retention(RetentionPolicy.RUNTIME)
```

| Anotación | Función |
|---|---|
| `@Target` | Indica en qué lugares se puede aplicar la anotación |
| `@Retention` | Especifica la política de retención: el tiempo que una anotación está presente durante el proceso de compilación y despliegue. `RUNTIME` = disponible para la **reflexión**. Valores: `SOURCE`, `CLASS`, `RUNTIME` |

### 9. Java Collections (`java.util`)

`Iterable` es el **padre de todas las colecciones**.

#### Arrays

`Arrays.asList(T... a)` → `List<T>` (donde "..." representa un nº variable de argumentos). Métodos: `binarySearch(int[], int)`, `fill()`, `sort()`.

#### Jerarquía (diagrama del PDF)

```
Iterable
  └── Collection
        ├── List   ◄── ArrayList, LinkedList, Vector (◄── Stack)
        ├── Queue  ◄── PriorityQueue
        │     └── Deque ◄── LinkedList, ArrayDeque
        └── Set    ◄── HashSet, LinkedHashSet
              └── SortedSet ◄── TreeSet

Map (no hereda de Collection ni de Iterable)
  ├── ◄── Hashtable, LinkedHashMap, HashMap
  └── SortedMap ◄── TreeMap
```

| Elemento | Detalle del PDF |
|---|---|
| Heredan del interface `Collection` | `List` (lista); `Set` → `SortedSet` (conjunto); `Queue` → `Deque` (cola) |
| Clases concretas | `Array` es fijo; `ArrayList` es dinámico. `ArrayList`, `LinkedList` (doblemente enlazada: lista y doble cola), `ArrayDeque` (*Actualización 20/05/2026: errata, no es ArrayDequeue*) |
| `Vector` → `Stack` | `push(E)`; `pop(): E`; `empty(): boolean`; `search(Obj): int`; `peek(): E` |
| `Map<K, V>` | Es una colección, pero **no hereda de `Collection` ni de `Iterable`**. Métodos: `put(K, V)`, `get(K)` → `V`, `keySet()` → `Set<K>`, `values()` → `Collection<V>` |
| Implementaciones de `Map` | `HashMap`: permite nulos, no sincronizado. `HashTable`: Dictionary. `TreeMap` |

Esquema de un Map: tabla de pares clave (K) → valor (V), por ejemplo `int` → `Factura`, `String` → `Empleado`.

Métodos según el nivel de la jerarquía (diagrama del PDF):

| Nivel | Métodos |
|---|---|
| (1) `Iterable` | `iterator()` → `Iterator<T>` |
| (2) `Collection` | `add(E)`, `size()` → `int`, `remove(Obj)`, `clear()`, `toArray()` → `Obj[]`, `contains(Obj)` → `boolean`, `isEmpty()` → `boolean` |
| (3) `List` | `get(int indice)` → `Object` (no tiene sentido para un árbol, por eso no se define en `Collection`, sino a nivel `List`), `indexOf(Obj)`, `remove(int indice)`, `subList(int, int)` → `List<T>` |

En el diagrama, `ArrayList<T>` hereda de `AbstractList<T>` (que hereda de `AbstractCollection`, clases) e implementa `List`; `Vector<T>` también implementa `List`.

Las estructuras de datos que hay por debajo (pila, cola, lista enlazada, tabla hash) se estudian en [[B2 - T3 ESTRUCTURAS DE DATOS Y ALGORITMOS]]: [[Pila (Stack)]], [[Cola (Queue)]], [[Lista enlazada (TAD)]] y [[Tabla Hash]] (base conceptual de `HashMap`).

> [!note] Ampliación (conocimiento general, no viene del PDF)
> `Hashtable` y `Vector` son clases históricas sincronizadas; `HashMap` y `ArrayList` no lo son, por lo que son la opción habitual cuando no hay concurrencia.

## Parte IV — Excepciones

**Excepciones de Java**: mecanismo del programa para controlar posibles errores y para comunicar situaciones entre dos partes del programa. Es un sistema/mecanismo de **notificaciones**. Dentro del `try` ponemos las instrucciones potencialmente peligrosas. Palabras clave: `try`, `catch`, `throw`, `throws`, `finally`.

### 10. Checked vs Unchecked

| | **Checked** | **Unchecked** |
|---|---|---|
| Heredan de | `Exception` | `RuntimeException` |
| Obligación | Hay que hacer algo con ellas (propagar o capturar) | No obligas a los métodos intermedios a usar try/catch, solo al que le interesa tratar la excepción |
| Efecto | Ensucian el código: casi nunca puedes recuperarte del error y solo se saca a un log | Código más legible |
| Si no hay manejador general | — | Aborta la ejecución de forma no controlada |

#### Checked, opción 1 (propagación)

En el llamante usamos `try / catch (ObjExcepcion)`. La clase A permite que la excepción siga subiendo (`throws`); la clase B la lanza con `throw`.

```java
// Llamante: main() / doGet / f()
ClaseA objA = new ClaseA();
try {
    objA.g();
} catch (LogicaException e) {
    ...
}

// Clase A
g() throws LogicaException {      // permite que la excepción siga subiendo
    objB.h();
}

// Clase B
h() throws LogicaException {
    ...
    throw new LogicaException(...);   // throw lanza excepciones
}
```

#### Checked, opción 2

El llamante **no se entera** de que ha habido un error, porque se ha recuperado fuera del código, dentro de otro método (`m()` no tiene `throws`, por eso debe tratarlo):

```java
// Llamante
objA.m();

// Clase A: m() sin throws, debe tratar la excepción
m() {
    try {
        objB.h();
    } catch (LogicaException e) {
        ...
    }
}

// Otro modo de implementar m()
m() throws LogicaException {
    try {
        objB.h();
    } catch (LogicaException e) {
        throw (e);
    }
}
```

```java
class LogicaException extends Exception {
    ...
}   // Para notificar situaciones.
```

Varias formas de capturar:

```java
catch (SegEx | ValEx e) { ... }      // multicatch

catch (SegEx e) { ... }
catch (ValEx e) { ... }

catch (Exception e) { ... }          // captura cualquier tipo de excepción
```

> [!important]
> Pasos para una excepción checked: 1) Definir la clase que hereda de `Exception`. 2) Crear el objeto de la nueva clase. 3) Lanzarlo (`throw`) cambiando la definición del método (`throws clase_excep`). 4) Modificar la llamada al método para meterla dentro del `try/catch/finally`.

#### Unchecked

```java
class ProyectoException extends RuntimeException {
    public ProyectoException(String mensaje) {
        super(mensaje);
    }
}
```

- **Opción 1 (opcional)**: el llamante puede hacer `try { objA.g(); } catch (ProyectoException e) { ... }`; `g()` llama a `objB.h()` sin `throws`; `h()` hace `throw new ProyectoException(...)`.
- **Opción 2**: el llamante invoca `objA.g();` sin try/catch. Si no ponemos un manejador general y hay un error, **aborta la ejecución de forma no controlada**.

### 11. Throwable

`Throwable` es la **superclase de los errores y las excepciones** (jerarquía: `Object` → `Throwable` → `Error` / `Exception` → `RuntimeException`). **No puedes recuperarte de un error**, por eso no se hace try/catch.

- `VirtualMachineError` → `OutOfMemoryError` y `StackOverFlowError`.
- `IOError`.

> [!note] Ampliación (conocimiento general, no viene del PDF)
> Ejemplos habituales: `IOException` es checked (hereda de `Exception`); `NullPointerException` es unchecked (hereda de `RuntimeException`).

## Parte V — Logging

**Logging en Java**: una parte del lenguaje para mensajes de log.

| Opción | Valoración |
|---|---|
| **Java API Logging** (`java.util.logging`) | Tiene poca potencia, por lo que no se usa |
| **SLF4J API Logging** | Librería de terceros. **Fachada** que te independiza de lo que uses por debajo (API). "Te casas con la fachada, no con las librerías" |

**Implementaciones** (con cualquiera de estas 4 librerías podemos generar ficheros/mensajes de log): **Log4J**, **LogBack**, **TinyLog**, **Apache Common Logging**. Log4J permite comportamientos diferentes en cada entorno (desarrollo, pre, producción): `log4j.properties`.

El diagrama de SLF4J del PDF muestra la llamada desde el código cliente a la API SLF4J (`slf4j-api.jar`), que delega en el sistema de logging subyacente según el *binding*: `logback-classic`, `slf4j-log4j12.jar` → log4j, `slf4j-jdk14.jar` → java.util.logging (JUL), `slf4j-simple.jar` → simple, `slf4j-nop.jar` → NOP, `slf4j-jcl.jar` → Jakarta Commons Logging (JCL).

### 12. Conceptos de logging

| Concepto | Significado |
|---|---|
| **Logger** | Entidad asociada a una clase o paquete. Permite sacar cada tipo de mensaje a un fichero distinto |
| **Appender** | Indica el destino de los mensajes de los loggers (consola, fichero, bbdd, etc.) |
| **Layout/Encoder** | Formato visual de cada mensaje |
| **Level** | Del logger. Solo se procesarán mensajes del nivel con el que esté configurado **o superiores** |

> [!example]
> Orden de niveles: `ALL < TRACE < DEBUG < INFO < WARN < ERROR < FATAL < OFF`. Ejemplo en producción con nivel **WARN**: sacará los WARN, ERROR y FATAL, pero no los inferiores.

## Parte VI — Hilos (Threads)

En Java hay hilos siempre.

### 13. Creación: 2 formas

| 1. Herencia de `Thread` y sobrescritura de `run()` | 2. "Cuerpos" de hilos implementando la interface `Runnable` |
|---|---|
| `class TareaBackup extends Thread` | `class TareaBackup implements Runnable` |
| Lanzamiento: `TareaBackup t1 = new TareaBackup(); t1.start();` | Lanzamiento: `Thread h1 = new Thread(new TareaBackup()); h1.start();` |

```java
// Forma 1
class TareaBackup extends Thread {
    // Puede tener atributos y constantes.
    @Override
    public void run() {
        // Cuerpo del hilo.
    }
}

class LanzadorDeTareas {
    ...
    TareaBackup t1 = new TareaBackup();
    t1.start(); // JRE lanza un nuevo hilo contra el método run() sobrescrito.
                // Tú no llamas a run, sino a start. El planificador es quien llama a run.
}
```

```java
// Forma 2
class TareaBackup implements Runnable {
    // Puede tener atributos y constantes.
    @Override
    public void run() { // lo mismo que en la opción 1 (usa implements en vez de extends)
        // Cuerpo del hilo.
    }
}

class LanzadorDeTareas {
    ...
    Thread h1 = new Thread(new TareaBackup());
    h1.start();
}
```

> [!important]
> `start()` pone el hilo en la cola de ejecución: llama al planificador y, cuando éste elija nuestro hilo, llamará al método `run()`. **Tú no llamas a `run`, sino a `start`.**

### 14. Sincronización

Un objeto contiene información. Cualquier clase de Java hereda de `Object`, heredando los métodos `wait()` y `notify()` para funcionar como **monitor** (concepto de concurrencia), para gobernar el flujo de ejecución de todos los hilos que comparten un mismo objeto/recurso.

- **Problema del Productor/Consumidor**: si la cola no tiene datos, al siguiente consumidor le decimos `wait()`. Cuando haya datos avisaremos con `notify()`. (Esquema del PDF: consumidores h1, h2, h3 y productores h4, h5, h6 sobre un objeto con `prod() {...}` y `cons() {...}`.)
- Si declaramos un método como `synchronized`, solo puede usar ese objeto un hilo al mismo tiempo. También puede ponerse a nivel de bloque de código: `synchronized (lockObj) { ... }`. Evita problemas de concurrencia en esa **sección crítica**.

**Funcionamiento**: para saber qué hilo está pasando por una zona de código podemos llamar a `Thread.currentThread.getId()` y `getName()`.

| Memoria | Qué contiene | Riesgo |
|---|---|---|
| **Stack** (por hilo) | Cada hilo tiene su propia variable `x`, su propia copia, su propio espacio de memoria | Sin problema |
| **Heap** (compartido) | Todos los hilos comparten los atributos de `obj1`: único espacio de memoria | **Peligro de concurrencia**. Solución: `synchronized` |

## Parte VII — Persistencia en Java/JEE

Otro nombre de estos productos es **ORM** (Object Relational Mapping), que traduce el mundo de la Orientación a Objetos al mundo de las tablas (Objeto ↔ Fila). Funciona si sigues la **convención de nomenclatura** entre clases y tablas, atributos y campos; por eso la librería puede construir sentencias automáticamente.

### 15. Alto nivel (JPA) vs bajo nivel (JDBC)

| | Bajo nivel: API **JDBC** | Alto nivel: API **JPA** |
|---|---|---|
| Objetos | `DataSource` (interface) → `Driver` (interface) → BBDD. `Connection`, `PreparedStatement`, `ResultSet` (cursor). Árbol **JNDI** (Java Naming and Directory Interface) | `Entity Manager (EM)` → `DataSource` → `Driver` → BBDD. **SQL generado automáticamente** |
| Manejo | Más manual, con tratamiento directo con las tablas | La app le pasa objetos de negocio al EM y éste, en base a la clase a la que pertenece ese objeto, sabe construir el SQL (API *Reflection*: acceder y modificar clases en tiempo de ejecución). Usado mucho en apps web |
| Implementaciones | — | Hibernate, TopLink → EclipseLink, OpenJPA |
| Consultas | SQL | **JPQL** (Java Persistence Query Language): SQL usando clases y atributos |

- La parte crítica es que en la App **se pierde el control** de esas sentencias SQL.
- **JPA es la especificación (API)** e **Hibernate y OpenJPA son 2 de sus implementaciones** (*Actualización 20/05/2026, registro 14/10/2024*).
- En los dos métodos tenemos dos objetos Java: **DataSource** y **Driver**. JPA mete una capa más de abstracción.

| Objeto | Función |
|---|---|
| **Driver** | Hay un `.jar` para cada fabricante |
| **DataSource** | Crea X conexiones a BD según arranca y establece un límite. Las primeras conexiones se asignan muy rápido al estar ya creadas; las siguientes tardan un poco más. El Driver no limita el nº de conexiones, así que puedes tumbar la BD: por eso se crea DataSource. Si se llega al límite de conexiones, se hace `wait()` a la siguiente petición de conexión |

Para el lado SQL de JDBC (sentencias, cursores) ver [[B3 - T3 SQL]] y [[Cursor (SQL)]]. El detalle de JPA (EntityManager, anotaciones, EAGER/LAZY) está en [[B3 - T5.2 ARQUITECTURA JEE]].

## Parte VIII — Maven

**MAVEN**: herramienta independiente hecha en Java (puede usarse por línea de comandos) aunque ya la llevan todos los IDE.

| Función | Detalle |
|---|---|
| Automatización de la construcción (*building*) | Localiza el código fuente y ficheros de configuración, lo compila, lo empaqueta y pasa los tests |
| Gestor de dependencias | Se basa en **repositorios** y dependencias. También existen *archetypes* (plantillas de proyectos) |

- Fichero principal: **`POM.xml`** (Project Object Model), donde se declara la dependencia. Maven descarga el `.jar` (directorio local `.m2`) y lo usa para compilar.
- Cualquier artefacto de Maven tiene **3 coordenadas**: `groupId`, `artifactId` y `version`. `groupId` y `artifactId` son únicos para cada fabricante de software; el fabricante publica su código en `http://repo.maven.apache.org`.

```xml
<dependency>
    <groupId>com.google.code.gson</groupId>
    <artifactId>gson</artifactId>
    <version>2.3.1</version>
</dependency>
```

- Obliga a usar un árbol de directorios concreto: `src/main/java` para guardar los `.java`.
- `mvn package` realiza todos los pasos/fases necesarias para construir un jar/war en el directorio `target`. `mvn` puede lanzarse desde donde tengas el fichero `POM.xml`.
- Maven trabaja con una **versión concreta**: no deja indicar que use la última versión de una librería.
- **Maven y Ant son de Apache, pero Ant no tiene gestor de dependencias.**

switch (expresion) {

}

Las sentencias de **ramificación** en Java son: `break` para salir de bloque de sentencias; `continue` para ir directamente al siguiente bloque.

Esquema del bucle `for` (imagen del PDF): 1) inicialización, 2) condición (verdadera → bloque de sentencias; falsa → fin), 3) bloque de sentencias, 4) actualización, y vuelta a 2). Un `while` equivalente: inicialización; `while (condición) { bloque_de_sentencias; actualización; }`. Observaciones: la condición en `for` se evalúa igual que en `while` y `do-while`; el bloque debe ir entre llaves si tiene 2 o más instrucciones (opcionales si solo tiene una); las instrucciones del bloque deben sangrarse a la derecha.

| `void notifyAll()` | Reinicia la ejecución de todos los hilos en espera en el objeto que realiza la llamada |
| `String toString()` | Devuelve una cadena que describe el objeto |
| `void wait()`, `wait(long miliseg)`, `wait(long miliseg, int nanoseg)` | Espera en otro subproceso de ejecución |

### 21. Paradigmas de programación

Formas de clasificar los lenguajes de programación en función de sus características. Los comunes son:

| Paradigma | Descripción |
|---|---|
| Imperativo | El programador dice a la máquina qué hacer en un orden |
| Procedimental | Agrupa las instrucciones en procedimientos |
| Orientado a objetos | Agrupa las instrucciones con la parte del estado en objetos. Suelen ser imperativos |
| Declarativo | El programador declara el resultado deseado |
| Funcional | El resultado deseado se declara como el valor de una serie de aplicaciones de función |
| Lógico | El resultado deseado se declara como la respuesta a una pregunta sobre un sistema de hechos y reglas |
| Matemático | El resultado deseado se declara como la solución de un problema de optimización |
| Reactivo | El resultado deseado se declara con flujos de datos y la propagación del cambio |

## 🔑 Resumen ultra-rápido (para repaso)

- Java SE = infraestructura (JDK + JRE) + lenguaje + herramientas/librerías de terceros. Añadido al ecosistema → JEE.
- JDK (construir): `javac` (compilador a bytecode), `java` (intérprete), `jshell` (REPL, Java 9), `javadoc`, `jar`, `jarsigner`, `keytool`, `wsimport` (cliente SOAP), `xjc` (clases desde XSD), `rmic`/`rmiregistry` (RMI), `javap` (desensamblador), `jdb`, `jdeps`, `jconsole`/`jmc` (jmc ha desaparecido), `jjs`.
- JRE (ejecutar) = JVM + librerías base (`rt.jar` → ahora módulo `java.base`). JVM: Class Loader, Heap, Stack, Registros, JIT, GC, Motor de ejecución. "Write once, run anywhere".
- CLASSPATH: variable de entorno, propiedad `-classpath` al lanzar, o `Class-Path` en `MANIFEST.MF`.
- Hilo = cocinero activo; método = receta pasiva. Apps con `main()` = monohilo.
- Herencia simple de clases, múltiples interfaces. Clase→clase y interface→interface: `extends`; clase→interface: `implements`. Todo hereda de `Object`.
- `==` compara referencias; `equals` compara contenido. Todo son referencias salvo primitivos.
- Modificadores: `final`, `static`, `abstract` (no instanciable), `private`, `public`, `protected` (herencia + paquete), `native` (JNI), `volatile` (lee de memoria principal), `transient` (no serializar), `synchronized` (un hilo a la vez), `default` (paquete).
- Visibilidad: `default` = mismo paquete; `protected` = mismo paquete + subclases de otro paquete; `private` = solo la clase; `public` = todo.
- Interfaces = contrato funcional (sin código hasta 1.7; `default` desde 1.8). Enum, Record (JDK 14, estable 17; patrón DAO), Anotaciones (`@Target`, `@Retention`: SOURCE/CLASS/RUNTIME).
- Genéricos: E, K, T, N, V; `<T extends Integer>` = bounded.
- Colecciones: `Iterable` → `Collection` → List / Set (SortedSet) / Queue (Deque). `Map` NO hereda de `Collection` ni `Iterable`. `ArrayList` dinámico, `LinkedList` doblemente enlazada, `ArrayDeque` (errata: no ArrayDequeue), `Vector` → `Stack`, `HashMap` permite nulos y no está sincronizado.
- Excepciones: Checked (hereda de `Exception`, obligan a tratar/propagar) vs Unchecked (hereda de `RuntimeException`). `Throwable` = superclase de `Error` y `Exception`; de un `Error` no se recupera.
- Logging: SLF4J = fachada; implementaciones Log4J, LogBack, TinyLog, Apache Commons Logging. Niveles: ALL < TRACE < DEBUG < INFO < WARN < ERROR < FATAL < OFF (nivel WARN en producción saca WARN, ERROR y FATAL). Logger / Appender / Layout-Encoder / Level.
- Hilos: `extends Thread` o `implements Runnable`; se llama a `start()`, no a `run()`. `wait()`/`notify()` (monitor), `synchronized`. Stack propio por hilo; heap compartido.
- Persistencia: ORM (Objeto ↔ Fila). JPA = especificación; Hibernate y OpenJPA = implementaciones. JPQL. JDBC más manual. DataSource (pool de conexiones, `wait()` al llegar al límite) y Driver (un .jar por fabricante).
- Maven: `POM.xml`, coordenadas groupId/artifactId/version, `.m2`, `src/main/java`, `mvn package` → target. Ant (sin gestor de dependencias), Gradle, Ivy, Jenkins.
- Novedades: Streams, lambdas, try-with-resources + multicatch (1.7), `@FunctionalInterface`, métodos `default` (1.8), `java.time`, `Optional`, `CompletableFuture`, Modules/`module-info.java` (1.9), GraalVM (sustituye al motor de script).
- Operadores: `&&`/`||` con cortocircuito; `>>` conserva signo, `>>>` entra cero; `i++` usa y luego incrementa, `++i` incrementa y luego usa. `break`/`continue` = ramificación.
- Paradigmas: imperativo, procedimental, orientado a objetos, declarativo, funcional, lógico, matemático, reactivo.

# Tema 4.2 · Bloque 2 — Windows y Sistemas Operativos Móviles

> [!abstract] De qué va este tema
> Segunda parte de la teoría de Sistemas Operativos (continúa a [[B2 - T4.1 SISTEMAS OPERATIVOS|T4.1]]): la arquitectura y administración de **Windows** (versiones, Active Directory, seguridad, registro, comandos), los **Sistemas Operativos Móviles** (Android, iOS, herramientas multiplataforma, MDM) y **macOS**.

## 1. Sistema Operativo Windows

### 1.1 Arquitectura y versiones

**Versiones Workstation**: 95, 98, ME, XP, Vista, W7, W8, W10, W11.

**Interfaces gráficas:**

| Interfaz | Versión |
|---|---|
| Luna | XP |
| Aero | Vista y W7 |
| ModernUI o Metro | W8, Windows Phone |
| Continuum | W10 |
| Fluent Design | W10 |
| WinUI 3 | W11 |

**Arquitectura MS-DOS o NT**: el Kernel (µKernel) tiene muy pocas cosas y el resto son módulos, servicios ejecutivos. NT incluye el **HAL** (Hardware Abstraction Layer), una capa de abstracción del hardware, ≈ VFS.

> [!note] Diagrama de arquitectura (transcrito del PDF)
> De arriba abajo:
> - **Modo Usuario**: Aplicaciones → Win32 → API Nativa de Windows.
> - **Modo Kernel**: Executive Services → (Drivers | µKernel, en paralelo) → Hw Abstraction Layer (HAL).
> - **Hardware**.

**API Nativa de Windows**: similar al `int 80h` de Linux. Win32 es lo que está encima de este API.

**W10**: Microsoft Edge (Chromium), Cortana (asistente personal), Windows Subsystem for Linux (WSL).

> [!note] Ampliación (conocimiento general, no viene del PDF)
> El HAL y el VFS no son lo mismo funcionalmente: el **HAL** abstrae el *hardware* (para que el kernel no dependa del chipset concreto), mientras que el **VFS** (Virtual File System, propio de Linux) abstrae *sistemas de ficheros* distintos bajo una interfaz común. El "≈ VFS" del PDF es una analogía conceptual — ambos son capas de abstracción dentro del kernel — no una equivalencia funcional literal.
>
> El `int 80h` era la forma clásica (anterior a las instrucciones `sysenter`/`syscall`) de invocar una llamada al sistema en Linux x86. En Windows, la **API Nativa** (funciones `Nt*`/`Zw*` de `ntdll.dll`) es la capa mínima que habla directamente con el kernel; Win32 (`kernel32.dll`, `user32.dll`...) es la API pública que casi todas las aplicaciones usan, construida encima de esa API nativa no documentada oficialmente para uso directo.

### 1.2 Versiones Server y roles

**Versiones Server**: 2000, 2003, 2008, 2012, 2016, 2019, 2022.

Permite activar **roles**, que especifican las características funcionales del Windows Server:

| Rol | Función |
|---|---|
| **Active Directory** | Controlador de dominio |
| **Hyper-V** | Máquinas virtuales |
| **File Services** | SMB/CIFS para sistema de ficheros compartidos y servicios de impresión |
| **Web Server** | IIS. También es servidor FTP y servidor de aplicaciones ASP.NET |
| **DHCP Server / DNS Server** | — |

**Server Core** (2008) y **Nano Server** (2016): versiones sin pantallas, tipo Linux, con menos funcionalidades. Orientados a la nube y contenedores.

> [!note] Diagrama: acceso a datos vía File Services vs SAN (transcrito del PDF)
> El PDF ilustra dos tramos de acceso al mismo fichero (`f.pdf`): un usuario en la **VLAN de usuarios** accede a `\\Servidor\Carpeta\f.pdf` (recurso compartido SMB, servido por `Servidor_1`, un Windows Server con el rol **File Services**, en la **VLAN de servidores**, conectado por tarjeta Ethernet). Ese mismo servidor, mediante una tarjeta **[[HBA (Host Bus Adapter)|HBA]]**, accede físicamente al fichero (`C:\Carpeta\f.pdf`) alojado en una cabina/switch de una **[[SAN (Storage Area Network)|SAN]]** por Fibre Channel. Es decir: el cliente ve el fichero por red local vía SMB/CIFS, pero el servidor lo tiene realmente montado desde una SAN.

> [!note] Ampliación (conocimiento general, no viene del PDF)
> **Nano Server** dejó de ofrecerse como sistema operativo instalable de forma independiente a partir de Windows Server 2019, quedando reservado como imagen base ultraligera para contenedores; **Server Core** sigue existiendo como opción de instalación completa sin GUI.

### 1.3 Active Directory

**Servicio de Directorio Activo (AD)**: sirve para empresas pequeñas y grandes.

- **Controlador de Dominio (DC) + SAM**:
  - **DC**: máquina con software para que nos validemos con usuario y contraseña en un dominio concreto.
  - **SAM**: BD almacenada como un fichero donde se guardan contraseñas de los usuarios en formato hash.
- **Tipos de grupos** dentro del AD: locales, globales y universales.
- **Tecnologías** usadas: **LDAP**, **Kerberos** (token) y **DNS** (se gestionan dominios).
- **Relaciones de confianza**: para que usuarios de un dominio accedan a recursos de otro dominio.

**Estructura lógica del AD** (es una base de datos):
- **Objetos**: objetos LDAP con atributos. `ObjectClass` indica el tipo de objeto (device, person, ou...):
  - **Recursos**: impresoras, etc.
  - **Security Principal**: usuario, grupo, PC.
- **Dominios / Bosques**: un **bosque** es una manera de unir distintos árboles de dominio. No comparten raíz. Se necesita al menos un controlador de dominio por cada dominio.
- **Unidades Organizativas (OU)**: sirven para organizar objetos jerárquicamente. Son las ramas del árbol (ej. para aplicar políticas de grupo).

**Estructura física del AD**: el objetivo es configurar cómo queremos la replicación entre DCs, en qué DC deben autenticarse los clientes, etc.
- **Site**, **Subnet** (dentro de un site), **Site-Link** (quién está conectado con quién).

> [!note] Diagrama de jerarquía (transcrito del PDF)
> Un **Forest** (bosque) contiene varios **Domain Tree** (árboles de dominio); cada árbol contiene varios **Dominios**; cada dominio contiene **Unidades Organizativas**, y dentro de estas los **Objetos**.

> [!note] Ampliación (conocimiento general, no viene del PDF)
> **Kerberos** es un protocolo de autenticación por *tickets*: el usuario se autentica una vez ante el **KDC** (Key Distribution Center, integrado en el DC) y recibe un **TGT** (Ticket Granting Ticket); con ese TGT solicita tickets de servicio concretos sin volver a teclear la contraseña. **LDAP** (Lightweight Directory Access Protocol) es el protocolo que se usa para consultar y modificar esos objetos del directorio, típicamente por el puerto 389 (o 636 para LDAPS cifrado).

### 1.4 Seguridad

**Gestión de Políticas — GPO (Group Policy Object)**: tanto para usuarios como para computadoras (ej. compartir carpetas, ejecutar programas al iniciar sesión, etc.).

- **LGP** (Local Group Policy): aplicadas a la política local del equipo.
- **Orden de procesamiento** (de menor a mayor precedencia): **Local** (comando `gpedit.msc` para editar las directivas de la máquina) → **Site** (AD, ubicación física, oficina, país, etc.) → **Domain** → **OU** (la más prioritaria).
- Consultar el resultado de este procesamiento: `gpresult /r`.
- Forzar que se actualicen y apliquen las directivas: `gpupdate /force`.

**SAM (Security Account Manager)**: BD con las contraseñas locales y remotas (a nivel de dominio). Ruta: `%SystemRoot%/system32/config/SAM`. Montada en `HKLM/SAM`. Con el comando `syskey` se puede mejorar la seguridad de la SAM (encriptación).

**BitLocker**: herramienta de cifrado de volúmenes. Usa AES. Tiene 3 modos:
- **Transparente**: utiliza el módulo **TPM** (módulo de plataforma de confianza), un chip de cifrado integrado, hardware de criptografía.
- **De autenticación de usuario**: mediante el uso de un PIN o contraseña.
- **USB**: requiere del uso de un USB para desencriptar la unidad.

**EFS** (Encrypted File System): permite cifrar parte del volumen, no necesariamente todo como BitLocker.

**AppLocker**: bloquea la ejecución de ciertas aplicaciones. Es una especie de AntiMalware. Permite tener reglas para ejecutables, instaladores, ficheros de script y ficheros empaquetados. Hay una guía del ENS para su implementación. Tres medidas de seguridad asociadas: Configuración de Seguridad; Gestión de la Configuración; Protección frente a código dañino.

**UAC** (User Account Control): si está activado, cuando una app va a realizar una modificación en el registro de Windows, pide autorización.

> [!important] SAM vs BitLocker vs EFS — qué protege cada uno
> **SAM** guarda las credenciales de los usuarios (hashes). **BitLocker** cifra el volumen entero. **EFS** cifra ficheros/carpetas concretos dentro de un volumen ya montado. Son capas distintas: autenticación, cifrado de disco completo, cifrado selectivo.

> [!note] Ampliación (conocimiento general, no viene del PDF)
> El "formato hash" de la SAM corresponde históricamente a los hashes **LM** (muy débil, obsoleto) y **NTLM**, derivados de la contraseña del usuario sin guardarla en claro. El **TPM** no solo cifra: es un chip aparte de la CPU que guarda las claves criptográficas de forma que, aunque alguien extraiga el disco, no puede leer la clave de BitLocker sin ese chip físico — de ahí que el modo "Transparente" no pida ni PIN ni USB y siga siendo seguro.

### 1.5 Administración

- **VBScript**: Windows Script Host es el intérprete.
- **PowerShell** (.NET): versión 7.0. Convergencia multiplataforma. Formato Nombre-Nombre (generalmente Verbo-Nombre). Se puede administrar Linux con cmdlets. **[[cmdlet (PowerShell)|Cmdlet]]**: elemento de administración. Hay *modules* para ampliar funcionalidades (ej. Active Directory).
- **MMC** (Microsoft Management Console) / **MS Config**: permite añadir complementos para gestionarlos desde la herramienta. Ej: Servicios (`services.msc`), Certificados Digitales (`certmgr.msc`), etc.

> [!note] Ampliación (conocimiento general, no viene del PDF)
> El formato **Verbo-Nombre** de los cmdlets (`Get-Process`, `New-Item`, `Set-ExecutionPolicy`...) no es un capricho estilístico: existe una lista cerrada de verbos aprobados (consultable con `Get-Verb`) precisamente para que el nombre de cualquier cmdlet sea predecible y descubrible sin necesidad de memorizarlo.

| **FAT** (16 o 32) | No permisos |
| **exFAT** | Flash Memory |

| **HPFS** | — |

### 1.7 Servicios (≈ Demonios de Linux)

- `services.msc`: para configurar los servicios, arrancarlos, pararlos, etc.
- Para servicios que comparten procesos: `svchost.exe`.
- Para instalar/crear un servicio: `installutil` o `sc.exe create`.
- Algunos servicios conocidos: Windows Update, Windows Firewall, Windows Defender, Acceso remoto, Programador de tareas.
- **WMI** (Windows Management Instrumentation): ≈ SNMP. Gestiona ese Windows. Es un MIB de ese equipo. `wmic` es la herramienta. Ej: `wmic cpu get caption, name, numberofcores, status`.
- **Windows Search**: resta rendimiento al indexar toda la información para que las búsquedas sean más rápidas.

| Gestor | Ejemplo |
|---|---|
| **WinGet** | `winget install vscode` |
| **Chocolatey** | `choco install notepadplusplus` |
| **Scoop** | `scoop install 7zip` |

### 1.9 Creación de imágenes/maquetas (clonación)

- **Norton Ghost**, **Acronis True Image**.
- **Microsoft Sysprep**: la opción `/generalize` limpia todos los drivers y otros datos de la instalación, dejando el sistema preparado para iniciar por primera vez y detectar el hardware en un equipo diferente, para posteriormente instalar los drivers adecuados. También limpia el **SID** (identificador único de seguridad).

> [!note] Ampliación (conocimiento general, no viene del PDF)
> Clonar un Windows sin pasar por Sysprep deja el mismo SID en todos los equipos, lo que puede causar conflictos al unirlos al mismo dominio (el SID identifica de forma única al equipo/usuario ante el AD) — es la razón práctica por la que Sysprep es obligatorio antes de generar una imagen maestra.

### 1.10 Arranque o inicio

- Antes: **NTLDR**, que leía del fichero `boot.ini`.
- Ahora: **bootmgr**.
  - `winload.exe` lee del fichero **BCD** (Boot Configuration Data).
  - `winresume.exe` si el equipo estaba hibernado.

### 1.11 Registro de Windows

Es una base de datos jerárquica con información de configuración, de bajo nivel (kernel, drivers, etc.), SAM, etc. Formato clave/valor. Antes eran archivos `.ini`. La herramienta de edición del registro es `regedit.exe`. La importación y exportación se hace en ficheros `.reg`.

**Estructura:**

| Hive | Nombre completo | Contenido |
|---|---|---|
| **HKLM** | Local Machine | Configuración del equipo local: SAM, Security, System, Software, etc. |
| **HKCR** | Classes Root | Información sobre aplicaciones instaladas/registradas |
| **HKCU** | Current User | Información sobre el usuario actualmente conectado (`ntuser.dat`) |
| **HKU** | — | Es el HKCU de cada usuario que se ha logado alguna vez en la máquina |
| **HKCC** | Current Config | Se carga dinámicamente al inicio con los datos sobre el hardware. ≈ `/proc` de Linux |

## 2. Comandos de Windows

### 2.1 Directivas de grupo (GPO)

| Comando | Función |
|---|---|
| `gpedit.msc` | Editor de GPOs o directivas de grupo locales |
| `gpresult` | Muestra las GPOs de usuario y/o computadora que están siendo aplicadas |
| `gpupdate` | Actualiza las directivas locales y del dominio en el equipo local |

- `gpresult /r` — resumen tanto del USER como del COMPUTER
- `gpresult /r /scope USER`
- `gpresult /r /scope COMPUTER`
- `gpresult /z` — información súper detallada
- `gpresult /h informe_fichero.html`
- `gpresult /x informe_fichero.xml`
- `gpresult /s remote-pc-name`
- `gpupdate /force` — forzamos la actualización
- `gpupdate /boot` — reinicia después de la actualización
- `gpupdate /logoff` — cierra la sesión después de la actualización
- `gpupdate /target USER` — solo se actualizan las directivas del usuario
- `gpupdate /target COMPUTER` — solo se actualizan las directivas del equipo

> [!note] Ampliación (conocimiento general, no viene del PDF)
> Aunque no haga falta forzarlo con `gpupdate`, las GPO también se refrescan solas de forma periódica: cada 90-120 minutos (con un desfase aleatorio) en equipos normales, y cada 5 minutos en controladores de dominio.

### 2.2 Active Directory: dsquery, dsget, dsadd, dsmod, dsmove, dsrm

| Comando | Función |
|---|---|
| `dsquery` | Búsqueda/consulta del AD |
| `dsget`, `dsadd`, `dsmod`, `dsmove`, `dsrm` | Visualizar, añadir, modificar, mover y borrar objetos del AD |
| `net` | Administrar recursos compartidos, usuarios, grupos, servicios, etc. |

**Consultas (`dsquery`):**
- `dsquery server domainroot` — lista todos los controladores de dominio
- `dsquery computer OU=Sales,DC=Contoso,DC=Com` — busca todos los equipos de esa OU
- `dsquery computer domainroot -name ServFichero*` — busca en el dominio actual todas las máquinas cuyo nombre comience con "ServFichero"
- `dsquery user domainroot -name *smith -inactive 3` — muestra a todos los usuarios cuyo nombre termina en "smith" y que llevan más de 3 semanas de inactividad
- `dsquery user ... -disabled` — que la cuenta esté desactivada
- `dsquery user ... -stalepwd 30` — que no haya cambiado la contraseña desde hace al menos 30 días

**Combinando `dsquery` con `dsget` (tubería):**
- `dsquery user –samid "username" | dsget user -email` — obtener el email de un usuario
- `dsquery user -samid "username" | dsget user -memberof -expand` — obtener todos los grupos de un usuario, incluidos los anidados
- `dsquery group -samid "DEVELOPERS" | dsget group -members -expand | dsget user -samid` — obtener los miembros de un grupo

**Otras opciones de `dsget`:**
- `dsget user ... -effectivepso` — obtener las PSO (Políticas sobre la configuración de las contraseñas)
- `dsget user ... -acctexpires` — obtener la fecha de expiración de la cuenta
- `dsget user ... -disabled` — si está o no desactivada
- `dsget user ... -mustchpwd` — si el usuario debe cambiar la contraseña en el siguiente inicio de sesión
- `dsquery computer -inactive 4 | dsmod computer -disabled yes` — deshabilita todos los equipos inactivos durante 4 o más semanas

**Altas y modificaciones (`dsadd`, `dsmod`):**
- `dsadd user "CN=Carlos,OU=Marketing,DC=ruinosa,DC=com"` — añade un usuario en una OU
- `dsadd computer "CN=SALESWKSTN1,OU=Ventas,DC=ruinosa,DC=com"` — alta de un equipo en una OU
- `dsmod group "CN=Marketing Users,CN=users,DC=ruinosa,DC=com" -addmbr "CN=Sara,OU=Marketing,DC=ruinosa,DC=com"` — añade usuario a un grupo
- `dsmod user "CN=Pepe,OU=Ventas,DC=ibm,DC=com" -pwd Abcd123 -mustchpwd yes` — cambia la contraseña y política de un usuario

**Borrado (`dsrm`):**
- `dsrm -subtree -noprompt -c "OU=Marketing,DC=ruinosa,DC=com"` — borra toda una OU

> [!note] Ampliación (conocimiento general, no viene del PDF)
> Los comandos `ds*` (`dsquery`, `dsget`, `dsadd`, `dsmod`, `dsrm`) son las herramientas clásicas de línea de comandos de Windows Server para AD, anteriores a PowerShell. Hoy su función la cubre el módulo **ActiveDirectory** de PowerShell (`Get-ADUser`, `New-ADUser`, `Set-ADUser`, `Remove-ADObject`...), mencionado en el apartado de administración — el mismo concepto de "cmdlet" que sustituye a estos comandos independientes.

### 2.3 `net` — administración de recursos, usuarios, grupos y servicios

| Comando | Función |
|---|---|
| `net user` | Muestra usuarios locales creados en la máquina |
| `net accounts` | Modifica políticas de cuentas y password |
| `net computer` | Añade o borra una máquina al dominio |
| `net session` | Lista usuarios y máquinas conectadas a un recurso |
| `net print` | Gestión de colas e impresión |
| `net share` | Gestión de recursos compartidos |
| `net group` / `net localgroup` | Gestión de grupos de dominio / locales |
| `net view` | Muestra máquinas del dominio y sus recursos compartidos |
| `net use` | Gestión de unidades hacia recursos compartidos |
| `net config server` | Configuración del servidor (ej. desconexión automática) |
| `net start`/`stop`/`pause`/`continue` | Gestión de servicios |
| `net time` | Sincronización horaria |

**`net user`:**
- `net user pepe` — muestra info del usuario pepe (último cambio de password, si la contraseña expira, última sesión iniciada, grupos locales a los que pertenece, directorio principal, etc.)
- `net user juan 1234 /add` — alta del usuario local juan
- `net user juan 1234 /add /domain` — alta del usuario juan en el dominio
- `net user fer *` — cambiar la password del usuario
- Otras opciones: `/passwordreq:yes/no`, `/passwordchg:yes/no`, `/expires:fecha/never`, `/active:yes/no`, `/times:momentos`, `/workstations:lista de equipos`

**`net accounts`:**
- `net accounts /MINPWLEN:longitudMinimaDeLaPassword`
- `net accounts /MAXPWAGE:maximoDeDiasQueLaPasswordEsValida`
- `net accounts /UNIQUEPW:numeroDePasswordUnicasCuandoSeCambia`
- Con `/DOMAIN` estos comandos afectan al dominio en lugar de a la máquina local

**`net computer`:**
- `net computer \\equipo /add` o `/del` — añade o borra una máquina al dominio

**`net session`:**
- `net session \\servidorNominas` — listado de usuarios y máquinas conectadas al servidorNominas

**`net print`:**
- `net print \\equipo` — muestra las colas de impresión compartidas
- `net print \\equipo\ShareName` — muestra la cola de impresión de ese share
- `net print \\equipo NumeroDeJob` — gestión de un job particular; opciones `/hold` o `/release` (retrasa/libera el job), `/delete` (borra el job)

**`net share`:**
- `net share` — sin parámetros muestra los recursos actualmente creados
- `net share DataCompartido=c:\Data` — comparte el directorio `c:\Data` con el nombre público DataCompartido
- Opciones: `/users:numeroMaximoUsuariosSimultaneos`, `/delete`

**`net group` / `net localgroup`:**
- `net group desarrolladores /add` — añade grupo al dominio
- `net localgroup desarrolladores /add` — añade grupo local a la máquina
- `net group desarrolladores pepe luis /add` — añade usuarios al grupo

**`net view`:**
- `net view` — lista de máquinas del dominio actual (o con `/domain` el que se especifique)
- `net view \\equipo /ALL` — muestra todos los recursos compartidos del equipo (el `$` en el nombre del recurso indica que son ocultos)

**`net use`:**
- `net use e: \\financiero\cartas` — en la máquina "cliente" nos enganchamos contra el share creado en el servidor `\\financiero`
- `net use [LPTx:] \\ComputerName\printer_share /persistent:yes`
- Opciones: `/delete` (borrar el mapeo), `/persistent:yes` (mapeo en cada inicio de sesión), `/user:usuario password` (mapeo con credenciales concretas)

**Otros:**
- `net config server /autodisconnect:minutos` — cierra sesiones inactivas al pasar x minutos
- `net start`/`stop`/`pause`/`continue nombreDelServicio` — gestión de servicios
- `net time /domain[:dominio] /set` — sincroniza la hora del equipo con la del dominio
- `net time /rstdomain[:dominio] /set` — ídem pero contra un servidor de tiempos

### 2.4 `netsh` — utilidad de configuración de red

Sintaxis general: `netsh (contexto) (subcontexto) comando`

- `netsh advfirewall set currentprofile state on` — activar el firewall
- `netsh advfirewall firewall add rule name="Open Port 80" dir=in action=allow protocol=TCP localport=80` — regla para abrir el puerto 80 de entrada
- `netsh advfirewall firewall set rule group="remote desktop" new enable=Yes` — activar el servicio de RDP
- `netsh interface ip show config` — muestra configuración TCP/IP
- `netsh interface ip delete arpcache` — borra la caché de ARP
- `netsh interface ip set address name="Local Area Connection" source=static addr=192.168.0.10 mask=255.255.255.0 gateway=192.168.0.1 gwmetric=1` — configuración IP estática
- `netsh interface ip set address name="Local Area Connection" source=dhcp` — configuración IP dinámica
- `netsh interface ip add dnsservers "Local Area Connection" 10.0.0.1` — añadir servidor de DNS
- `netsh set machine servidorNominas` — trabajar contra ese servidor
- `netsh wlan add filter permission=block ssid="WLAN name" networktype=infrastructure` — bloquea la WIFI por SSID
- `netsh http add iplisten address=1.1.1.1` — publicar nueva IP de escucha
- `netsh http add sslcert ipport=1.1.1.1:443 certhash=... appid={...}` — asocia un [[Certificado TLS-SSL (X.509)|certificado]] con una IP+puerto determinados
- `netsh dump > copia_configuracion.txt` — copia de seguridad de la configuración
- `netsh exec copia_configuracion.txt` — restauración de la configuración

### 2.5 Comandos de red y diagnóstico

| Comando | Función |
|---|---|
| `arp` | Gestión de la tabla/caché ARP |
| `ipconfig` | Configuración de interfaces |
| `robocopy (origen) (destino)` | Copia/backup de ficheros |
| `netstat` | Conexiones TCP/UDP |
| `nslookup` | Resolución de peticiones DNS |
| `getmac` | Obtener la dirección física/MAC de las interfaces de red |
| `route` | Administración de la tabla de enrutamiento |
| `tracert` / `pathping` | Muestra la ruta que siguen los datagramas IP entre dos extremos |

**`arp`:**
- `-a` — muestra las entradas de la tabla
- `-d direccion_ip` — elimina el host especificado (o todos con `*`)
- `-s direccion_ip direccion_mac` — agrega una entrada a la tabla

**`ipconfig`:**
- `/displaydns` — muestra las resoluciones DNS de la caché
- `/flushdns` — borra la caché del DNS
- `/renew` — renueva la dirección IP
- `/release` — libera conexiones

**`robocopy`:**
- `/S` — copia subcarpetas
- `/E` — copia subcarpetas incluso vacías
- `/MIR` — modo espejo: copia de forma recursiva pero al terminar elimina en destino los archivos que ya no existen en origen
- `/MOV` — mueve archivos y los elimina del origen tras copiarlos
- `/MOVE` — mueve archivos y carpetas y los elimina del origen tras copiarlos
- `/L` — hace una simulación
- `/MAX:bytes` o `/MIN:bytes` — filtra por tamaño
- `/MAXAGE:dias` o `/MINAGE:dias` — filtra por antigüedad
- `/Z` — modo reiniciable
- `/SEC` (conservar permisos) o `/COPYALL`
- `/R:numeroReintentos`
- `/XF patron` — excluye los archivos indicados

**`netstat`:**
- `-a` — muestra todas las conexiones y puertos de escucha
- `-p protocolo` — filtra por TCP, UDP
- `-r` — muestra el contenido de la tabla de rutas
- `-o` — muestra el PID del proceso asociado
- `-n` — muestra los puertos y direcciones en formato numérico

**`nslookup`:**
- `nslookup -querytype=TXT -timeout=10 inap.es 8.8.8.8` — consulta de los registros TXT de inap.es usando Google DNS
- `nslookup -type=TXT -timeout=10 inap.es 8.8.8.8` — equivalente

**`tracert` / `pathping`:**
- `-d` — no convierte direcciones en nombres de host
- `-h` — número máximo de saltos en la búsqueda
- `-w milisegundos` — tiempo para esperar cada respuesta
- `-6` — forzar usando IPv6

> [!note] Ampliación (conocimiento general, no viene del PDF)
> **ARP** (Address Resolution Protocol) es el protocolo que resuelve direcciones IP a direcciones MAC dentro de la misma red local — necesario porque a nivel de enlace (Ethernet/WiFi) los paquetes se entregan por MAC, no por IP; la tabla que gestiona este comando (igual que la caché de resoluciones que borra `ipconfig /flushdns`) es un [[Caching|caché]] de esas resoluciones ya conocidas, para no tener que preguntar por ARP-broadcast (o por DNS) en cada paquete.
>
> El flag `-o` de `netstat` (PID del proceso que tiene abierta cada conexión) conecta directamente con el concepto de proceso/PID visto en [[B2 - T4.1 SISTEMAS OPERATIVOS|T4.1]]: es la forma práctica de averiguar qué proceso concreto está usando un puerto determinado.

## 3. Sistemas Operativos Móviles

**Panorama general**: Android, iOS, Windows Phone, BlackBerryOS, Symbian, FirefoxOS/KaiOS, Ubuntu Touch, AliOS (Cars & IoT), OxygenOS, WebOS, Tizen, SailfishOS.

### 3.1 Android

- Basado en **Linux Kernel**.
- Almacenamiento: **SQLite**.
- Navegador web.
- Soporte Java: RunTime **Dalvik** (JIT — compilación en tiempo de ejecución). Ahora RunTime **ART** (AOT — compilación anticipada).
- Videollamadas con Hangout de Google.
- **Tethering**: teléfono como Access Point.

**Últimas versiones (RSTUVB):**

| Versión | Nombre en clave |
|---|---|
| 11 | Red Velvet Cake |
| 12 | Snow Cone |
| 13 | Tiramisu |
| 14 | Upside Down Cake |
| 15 | Vanilla Ice Cream |
| 16 | Baklava |

**Desarrollo:**
- **Android SDK**: herramientas, depurador, simulador de teléfono basado en QEMU, librerías.
- **Android Studio**: IDE.
- **Android Debug Bridge (ADB)**: herramienta de consola para enviar comandos al smartphone en modo depuración USB.
  - `adb install (apk)`
  - `adb push` (PC → file → Teléfono)
  - `adb pull` (Teléfono → file → PC)
- **Lenguajes**: Java, Kotlin.

**Arquitectura del `.APK`:**
- Recursos.
- `classes.dex`: único fichero con todo el código de la app. DEX (Dalvik Extension).
- `AndroidManifest.xml`: permisos.
- `Lib`: librerías de terceros.
- `Manifest.mf`: metadatos (autor, fecha, etc.).

**Archivos `.AAB`**: son un empaquetado, un formato de publicación que incluye el código compilado para cada plataforma y todos los recursos necesarios para la app; se instala solo el código que sirve para la plataforma concreta del dispositivo.

**Opciones de software**: **Jetpack Compose**, librería para crear interfaces gráficas de forma declarativa.

> [!important] .APK vs .AAB
> `.APK` es el paquete instalable final, con todo el contenido. `.AAB` es un formato de *publicación* (usado en Google Play): contiene el código compilado para cada plataforma/configuración y Play Store genera y entrega al dispositivo solo el `.APK` optimizado que necesita, en vez de un único paquete "todo incluido".

> [!note] Ampliación (conocimiento general, no viene del PDF)
> Android usó nombres públicos de postre desde Cupcake hasta Android 10 (Q); a partir de ahí Google dejó de usarlos de cara al público, aunque —como recoge la tabla del PDF— siguió habiendo nombres en clave internos de postre para cada versión mayor.

### 3.4 Gestión de dispositivos móviles (MDM)

**MDM** (Mobile Device Management): gestión de dispositivos móviles.
- **Gestión de terminales**: gestionar datos y configuraciones.
- **Gestión de despliegue**: control de aplicaciones instaladas (**MAM**).
- **Gestión de seguridad**: autenticación y encriptación.

**Plataformas/Productos**: MobileIron, Microsoft Intune, Samsung Knox, FAMOC, VMware AirWatch, Dialogs smartMan.

**Tipos de gestión:**
- **MAM**: gestión de las aplicaciones del teléfono.
- **EMM**: gestión empresarial (Enterprise Mobility Management).
- **MIM**: para configurar la información que hay en el teléfono.

**Maneras de operar la gestión de los teléfonos:**
- **BYOD** (Bring Your Own Device): dispositivos de personal externo, invitados, etc.
- **CYOD** (Choose Your Own Device): elige tu propio dispositivo entre los validados por la empresa.
- **COPE**: dispositivo propiedad de la empresa, con uso personal permitido.
- **COBO**: solo está permitido el uso corporativo.

**Guías CCN sobre seguridad en dispositivos móviles:**
- Serie **CCN-STIC-45X** dedicada a seguridad en dispositivos móviles, especialmente la **457**, dedicada al MDM.
- **CCN-STIC-496**, sobre la seguridad de las comunicaciones móviles.

> [!note] Diagrama UEM (transcrito del PDF)
> El PDF incluye un diagrama circular con la jerarquía de la gestión de endpoints, de fuera adentro:
> - **UEM** (Unified Endpoint Management) — envuelve a todo lo demás ("Manage Endpoints").
> - **EMM** (Enterprise Mobility Management), que agrupa: **MAM** (Mobile Application Management), **MIM** (Mobile Information Management), **MCM** (Mobile Content Management) y **BYOD**.
> - En el centro, **MDM** (Mobile Device Management), con: Device Security, Device Provisioning, Device Grouping, Device Health Monitoring y Location Tracking.

> [!important] MDM ⊂ EMM ⊂ UEM
> Según el propio diagrama del PDF, MDM es el núcleo (gestión del propio dispositivo), EMM añade la capa de aplicaciones/información/contenido/BYOD alrededor del MDM, y UEM es el concepto más amplio que engloba la gestión unificada de todos los tipos de endpoint (móviles, portátiles, IoT...).

## 🔑 Resumen ultra-rápido

- **Windows arquitectura**: µKernel + servicios ejecutivos + HAL (NT). API Nativa (≈int 80h Linux) por debajo de Win32.
- **Server**: roles (AD, Hyper-V, File Services/SMB, IIS, DHCP/DNS); Server Core y Nano Server sin GUI, para nube/contenedores.
- **AD**: DC+SAM, grupos locales/globales/universales, LDAP+Kerberos+DNS. Lógico: Objetos/Dominios/Bosques/OU. Físico: Site/Subnet/Site-Link.
- **Seguridad Windows**: GPO (orden Local→Site→Domain→OU, OU máxima prioridad), SAM (hash de contraseñas), BitLocker (AES, TPM/PIN/USB), EFS (cifrado parcial), AppLocker (bloqueo de apps), UAC.
- **Administración**: VBScript (WSH), PowerShell (.NET, cmdlets Verbo-Nombre, modules), MMC (`services.msc`, `certmgr.msc`).
- **Ficheros**: FAT(sin permisos), exFAT(flash), NTFS(seguridad/quota/compresión), ReFS, HPFS.
- **Servicios**: `services.msc`, `svchost.exe`, WMI≈SNMP (`wmic`), Windows Search.
- **Gestores de paquetes Windows**: WinGet, Chocolatey, Scoop. Clonación: Ghost/Acronis + Sysprep `/generalize` (limpia drivers y SID).
- **Arranque**: bootmgr → winload.exe (BCD) / winresume.exe (hibernación).
- **Registro**: HKLM, HKCR, HKCU/HKU, HKCC (≈/proc). `regedit.exe`, ficheros `.reg`.
- **Comandos clave**: GPO (`gpresult`, `gpupdate`), AD (`dsquery/dsget/dsadd/dsmod/dsrm`), `net` (user/accounts/share/view/use/group...), `netsh` (firewall/interface/wlan), red (`arp`, `ipconfig`, `netstat`, `nslookup`, `tracert`/`pathping`, `route`, `getmac`), sistema (`certutil`, `sc`, `robocopy`, `tasklist`, `bcdedit`, `whoami`, `mstsc`, `runas`, `ntdsutil`).
- **Android**: Linux kernel, SQLite, Dalvik(JIT)→ART(AOT), ADB (install/push/pull), .APK (classes.dex, manifest) vs .AAB (empaquetado multi-plataforma para publicación).
- **iOS**: deriva de BSD vía macOS. Cocoa Touch (UIKit/SwiftUI) → Foundation. Objective-C/Swift.
- **Multiplataforma**: Xamarin(C#), Flutter(Dart), híbridas (WebView+Native Bridge: React Native/IONIC/Cordova/PhoneGap), PWA (sin instalación).
- **MDM**: MDM⊂EMM⊂UEM. Tipos: MAM/EMM/MIM/MCM. Operativa: BYOD/CYOD/COPE/COBO. Guías CCN-STIC-45X (457=MDM) y CCN-STIC-496.
- **macOS**: kernel XNU (Mach+BSD, híbrido), HomeBrew, Llaveros, Finder, .dmg, Bootcamp, FileVault, TimeMachine, hfs+/apfs, Aqua, Cocoa/Carbon.

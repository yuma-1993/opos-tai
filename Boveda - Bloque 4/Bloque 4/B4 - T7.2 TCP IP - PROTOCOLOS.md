# Tema 7.2 · Bloque 4 — Protocolos TCP/IP - OSI

> [!abstract] De qué va este tema
> Catálogo de protocolos de la pila TCP/IP ordenados por capa OSI (red 3, interfaz de red 2/3 y 2, transporte 4, aplicación 5/6/7), cada uno con su abreviatura, descripción y puerto. Es la tabla de consulta que complementa la teoría de [[B4 - T7.1 TCP IP]]; lo que hay que memorizar sobre todo son los puertos y el par "protocolo ↔ qué hace".

---

## 1. Capa de red (OSI 3)

| Protocolo | Nombre | Descripción | Puerto |
|---|---|---|---|
| IP | Internet Protocol | Proporciona encapsulación y entrega sin conexión de mensajes de la capa de transporte a través de una red TCP/IP. También responsable de las funciones de direccionamiento y enrutamiento | |
| IPv6 | Internet Protocol Version 6 | Envío de paquetes de datos tanto a nivel local como a través de redes. Última versión del protocolo IP | |
| IP NAT | IP Network Address Translation | Permite que las direcciones en una red privada se traduzcan automáticamente a diferentes direcciones en una red pública, lo que brinda beneficios de seguridad y uso compartido de direcciones. (No todos consideran que IP NAT sea un protocolo en el sentido estricto de la palabra) | |
| IPSec | IP Security | Conjunto de protocolos relacionados con IP que mejoran la seguridad de las transmisiones de IP autenticando y/o cifrando cada paquete IP en un flujo de datos. AH (51), ESP (50), IKE | |
| Mobile IP | Internet Protocol Mobility Support | Protocolo estándar creado por la IETF y diseñado para permitir a los usuarios de dispositivos móviles moverse de una red a otra manteniendo permanentemente su dirección IP | |
| ICMP / ICMPv4 / ICMPv6 (niveles 2, 3) | Internet Control Message Protocol (Protocolo de mensajes de control de Internet) | "Protocolo de soporte" para IP (1) e IPv6 que brinda capacidades de notificación de errores y solicitud y respuesta de información a los hosts. Control y notificación de errores del Protocolo de Internet que se envían a la dirección IP de origen del paquete | |
| NDP | Neighbor Discovery Protocol (Protocolo de descubrimiento de vecinos) | Neighbor Discovery (ND) es un protocolo de IPv6, y es equivalente al protocolo ARP en IPv4, aunque se distingue porque también incorpora funcionalidades de ICMP | |

> [!important] Números de protocolo IP
> IPSec: AH = 51, ESP = 50. ICMP = protocolo IP 1. Ver la lista completa del campo Protocol en [[B4 - T7.1 TCP IP]].

### 1.1 Protocolos de enrutamiento (capa de red)

Protocolos utilizados para apoyar el enrutamiento de datagramas IP y el intercambio de información de enrutamiento.

| Protocolo | Tipo | Descripción | Puerto |
|---|---|---|---|
| RIP (Routing Information Protocol, "contador de saltos, máx. 15") | IGP | Protocolo tipo Interior Gateway Protocol utilizado por los routers para intercambiar información acerca de redes IP a las que se encuentran conectados. Algoritmo de encaminamiento basado en el vector de distancia: calcula la métrica o ruta más corta posible hasta el destino a partir del número de "saltos" o equipos intermedios que los paquetes IP deben atravesar. El límite máximo de saltos es 15: al llegar a 16 se considera una ruta inalcanzable o no deseable. A diferencia de otros protocolos, RIP es un protocolo libre, es decir, puede ser usado por diferentes routers y no únicamente por un solo propietario, como es el caso de IGRP y EIGRP, que son de Cisco Systems | 520 udp |
| RIPng | IGP | Versión de RIP para IPv6 | 521 udp |
| OSPF (Open Shortest Path First) | IGP | Protocolo de red tipo IGP que usa el algoritmo Dijkstra para calcular la ruta más corta entre dos nodos (protocolo IP 89). Ver [[Algoritmo de Dijkstra]] | |
| IGRP (Interior Gateway Routing Protocol) | Vector-distancia (Cisco) | Protocolo de enrutamiento basado en el algoritmo vector-distancia, aunque también tiene en cuenta el estado del enlace. Utiliza una métrica compuesta para determinar la mejor ruta basándose en el ancho de banda, el retardo, la confiabilidad y la carga del enlace. Protocolo propietario de CISCO Systems, no hay implementaciones para equipos de otros fabricantes. No mantenido actualmente por CISCO | |
| EIGRP (Enhanced Interior Gateway Routing Protocol) | Vector-distancia (Cisco) | Versión mejorada de IGRP. Protocolo de enrutamiento de vector distancia que ofrece lo mejor de los algoritmos de vector de distancias. EIGRP es algo más fácil de configurar que OSPF. Protocolo propietario de CISCO Systems, no hay implementaciones para equipos de otros fabricantes | |
| BGP (Border Gateway Protocol) | Exterior | Protocolo mediante el cual se intercambia información de encaminamiento entre Sistemas Autónomos (AS). Por ejemplo, los proveedores de servicio (ISP) registrados en Internet suelen componerse de varios sistemas autónomos y para este caso es necesario un protocolo como BGP para comunicarse entre ellos | 179 tcp |
| EGP (Exterior Gateway Protocol) | Exterior | Protocolo estándar usado para intercambiar información de encaminamiento entre sistemas autónomos en los primeros años de Internet, hasta que fue completamente reemplazado por BGP a mediados de los 90 | |

> [!important] Comparación rápida
> RIP (UDP 520, máx. 15 saltos, libre) frente a IGRP/EIGRP (propietarios de Cisco). BGP es el único de la lista que va sobre TCP (179). La comparación RIP/OSPF con algoritmo, distancia administrativa, etc. está en [[B4 - T7.1 TCP IP]].

## 2. Capa interfaz de red / red (OSI 2 y 3)

| Protocolo | Nombre | Descripción | Puerto |
|---|---|---|---|
| ARP | Address Resolution Protocol (Protocolo de resolución de direcciones) | Protocolo de comunicaciones de la capa de enlace de datos responsable de encontrar la dirección de hardware (Ethernet MAC) que corresponde a una determinada dirección IP | |
| RARP | Reverse Address Resolution Protocol (Protocolo de resolución de direcciones inverso) | Protocolo de comunicaciones utilizado para resolver la dirección IP de una dirección hardware dada (como una dirección Ethernet) | |
| LDP | Label Distribution Protocol (Protocolo de distribución de etiquetas) | Protocolo para la distribución de etiquetas MPLS entre los equipos de la red | 646 UDP-TCP |

## 3. Capa interfaz de red (OSI 2)

| Protocolo | Nombre | Descripción |
|---|---|---|
| SLIP | Serial Line Internet Protocol (transmisión de datagramas IP no estándar en líneas serie). Obsoleto, sustituido por PPP | Provides basic TCP/IP functionality by creating a layer-two connection between two devices over a serial line |
| PPP | Point-to-Point Protocol (Protocolo punto a punto) | Provides layer-two connectivity like SLIP, but is much more sophisticated and capable. PPP is itself a suite of protocols ("sub-protocols" if you will) that allow for functions such as authentication, data encapsulation, encryption and aggregation, facilitating TCP/IP operation over WAN links |

(Las descripciones de SLIP y PPP están en inglés en el PDF y se transcriben tal cual.)

## 4. Capa de transporte (OSI 4)

| Protocolo | Nombre | Descripción |
|---|---|---|
| TCP | Transmission Control Protocol (Protocolo de control de transmisión) | El principal protocolo de capa de transporte para TCP/IP. Establece y gestiona conexiones entre dispositivos y garantiza una entrega de datos fiable y controlada mediante IP (6). Hay envío de acuses de recepción |
| UDP | User Datagram Protocol (Protocolo de datagramas de usuario) | Protocolo de transporte que puede considerarse una versión "muy simplificada" de TCP. Se utiliza para enviar datos de forma sencilla entre procesos de aplicación, sin las muchas características de fiabilidad y gestión de flujo de TCP, pero a menudo con mayor eficiencia. No fiable (17) |

Los números entre paréntesis son el valor del campo Protocol de IP: TCP = 6, UDP = 17 (ver [[B4 - T7.1 TCP IP]]).

## 5. Capa de aplicación (OSI 5, 6, 7)

### 5.1 Nombres, direcciones, directorio y configuración

| Protocolo | Nombre | Descripción | Puerto |
|---|---|---|---|
| DNS | Domain Name System | Brinda la capacidad de referirse a dispositivos IP usando nombres en lugar de solo direcciones IP numéricas. Permite que las máquinas resuelvan estos nombres en sus direcciones IP correspondientes | 53 udp - tcp (sobre TLS 853) |
| LDAP | Lightweight Directory Access Protocol (Protocolo ligero de acceso a directorios) | Protocolo a nivel de aplicación que permite el acceso a un servicio de directorio ordenado y distribuido para buscar diversa información en un entorno de red. Habitualmente almacena la información de autenticación (usuario y contraseña) y es utilizado para autenticarse, aunque es posible almacenar otra información. Última versión: LDAPv3 | Sin seguridad 389; con seguridad 636 |
| NFS | Network File System | Permite que los archivos se compartan sin problemas a través de redes TCP/IP. Usado con XDR y RPC | |
| BOOTP | Bootstrap Protocol | Desarrollado para abordar algunos de los problemas con RARP y utilizado de manera similar: para permitir la configuración de un dispositivo TCP/IP al inicio. Generalmente reemplazado por DHCP | |
| DHCP (IPv4) | Dynamic Host Configuration Protocol | Protocolo completo para configurar dispositivos TCP/IP y gestionar direcciones IP. El sucesor de RARP y BOOTP, incluye numerosas características y capacidades | 67 y 68 UDP |
| DHCP6 (IPv6) | Dynamic Host Configuration Protocol v6 | Protocolo cliente-servidor que proporciona una configuración administrada de dispositivos sobre IPv6 | Cliente 546 udp; servidor 547 udp |
| SNMP | Simple Network Management Protocol | Protocolo completo para la gestión remota de redes y dispositivos | 161 y 162 udp |
| RMON | Remote Monitoring | "Protocolo" de diagnóstico (realmente una parte de SNMP) utilizado para el monitoreo remoto de dispositivos de red | 560 udp |

> [!important] Primitivas DHCP (orden)
> DHCP Discovery → DHCP Offer → DHCP Request → DHCP Acknowledge.

> [!tip] Mnemotecnia DHCP
> DORA: Discovery, Offer, Request, Acknowledge. (Acrónimo habitual; el PDF solo lista las cuatro primitivas.)

### 5.2 Transferencia de ficheros

Protocolos diseñados para permitir la transferencia de todo tipo de archivos de un dispositivo a otro.

| Protocolo | Nombre | Descripción | Puerto |
|---|---|---|---|
| FTP | File Transfer Protocol (Protocolo de transferencia de ficheros) | Protocolo de red para la transferencia de archivos entre sistemas conectados a una red TCP basado en la arquitectura cliente-servidor. Desde un equipo cliente se puede conectar a un servidor para descargar archivos desde él o para enviarle archivos, independientemente del sistema operativo utilizado en cada equipo | 20/TCP (data port); 21/TCP (control port) |
| FTPS (FTP/SSL) | FTP/SSL | Nombre usado para abarcar un número de formas en las cuales el protocolo FTP puede realizar transferencias de ficheros seguras. Cada forma conlleva el uso de una capa SSL/TLS debajo del protocolo estándar FTP para cifrar los canales de control y/o datos | 989 data; 990 control |
| SFTP | SSH File Transfer Protocol (Protocolo seguro de transferencia de ficheros) | Protocolo seguro de transferencia de ficheros SFTP, el cual suele ser usado con SSH | 22 tcp |
| TFTP | Trivial File Transfer Protocol (Protocolo de transferencia de archivos trivial) | Protocolo de transferencia muy simple semejante a una versión básica de FTP. Se utiliza a menudo para transferir pequeños archivos entre computadoras en una red de manera sencilla, por lo que no cuenta con funciones complejas de transferencia | 69 udp |

Modos activo y pasivo de FTP: ver [[B4 - T7.1 TCP IP]]. SSH/SFTP: ver [[B4 - T1.2 ADMON SSOO - SSH]] y [[scp y sftp (transferencia de ficheros por SSH)]].

> [!important] FTP vs FTPS vs SFTP
> FTP = 20/21 TCP, sin cifrar. FTPS = FTP + capa SSL/TLS (989/990). SFTP = va sobre SSH, puerto 22 (no es FTP sobre SSL). TFTP = UDP 69, versión básica.

### 5.3 Correo electrónico

Protocolos que definen el formateo, entrega y almacenamiento de mensajes de correo electrónico en redes TCP/IP.

| Protocolo | Nombre | Descripción | Puerto |
|---|---|---|---|
| MIME | Multipurpose Internet Mail Extensions (NO ES UN PROTOCOLO) | Serie de especificaciones dirigidas al intercambio a través de Internet de todo tipo de archivos (texto, audio, vídeo...) de forma transparente para el usuario. Una parte importante del MIME está dedicada a mejorar las posibilidades de transferencia de texto en distintos idiomas y alfabetos. Muy relacionado con SMTP | |
| SMTP | Simple Mail Transfer Protocol (Protocolo para transferencia simple de correo) | Protocolo de aplicación usado en combinación con POP3 e IMAP, otorgando a SMTP la tarea específica de enviar correos y delegando la de recibirlos a los protocolos mencionados. Los mensajes de correo electrónico en Internet están tan cercanamente asociados con SMTP y MIME que usualmente se les llama mensaje SMTP/MIME | 25/TCP, 2525/TCP, 587/TCP, 465/TCP (SMTPS) |
| POP3 | Post Office Protocol (Protocolo de Oficina Postal) | Protocolo utilizado por clientes locales de correo electrónico para obtener los mensajes almacenados en un servidor remoto (servidor POP). Tras la conexión descarga los mensajes al equipo local pudiendo ser revisados tras desconectarnos. Normalmente los mensajes descargados del servidor se eliminan del servidor, aunque se pueden mantener. Última versión: POP3 | 110/tcp; si es cifrado, 995/tcp |
| IMAP4 | Internet Message Access Protocol (Protocolo de acceso a mensajes de Internet) | Protocolo de aplicación que permite el acceso a mensajes almacenados en un servidor de Internet de manera remota sin necesidad de descargarlos. Última versión: IMAP4 | 143/tcp-udp; si es cifrado, 993/tcp |

> [!important] POP3 vs IMAP
> POP3 descarga los mensajes al equipo local (normalmente se borran del servidor, aunque pueden mantenerse). IMAP los consulta en remoto sin descargarlos. SMTP solo envía. Cifrados: POP3 995, IMAP 993, SMTPS 465.

### 5.4 Noticias y web

| Protocolo | Nombre | Descripción | Puerto |
|---|---|---|---|
| NNTP | Network News Transfer Protocol | Permite el funcionamiento de la comunidad en línea de Usenet mediante la transferencia de mensajes de noticias de Usenet entre hosts | |
| HTTP (el PDF lo rotula "HTTP3.0") | Hypertext Transfer Protocol (Protocolo de transferencia de hipertexto) | Transfiere documentos de hipertexto entre hosts; implementa la World Wide Web. Es un protocolo sin estado, por lo que no guarda ninguna información sobre conexiones anteriores. El desarrollo de aplicaciones web necesita frecuentemente mantener estado; para esto se usan las cookies, que es información que un servidor puede almacenar en el sistema cliente. Última versión: HTTP 3.0 (2018) | 80/TCP |
| HTTPS | Hypertext Transfer Protocol Secure (Protocolo seguro de transferencia de hipertexto) | Versión segura del protocolo HTTP destinada a la transferencia segura de datos de hipertexto. Utiliza un cifrado basado en la seguridad de textos SSL/TLS para crear un canal cifrado (cuyo nivel de cifrado depende del servidor remoto y del navegador utilizado por el cliente) más apropiado para el tráfico de información sensible que el protocolo HTTP | 443/TCP |

> [!note] Ampliación (conocimiento general, no viene del PDF)
> HTTP/3 se transporta sobre QUIC (que va sobre UDP, ver [[B4 - T7.1 TCP IP]]), por lo que en la práctica no usa el puerto TCP 80 de la tabla; el PDF solo indica 80/TCP para HTTP en general. Un servidor Apache que sirve HTTPS usa certificados TLS: ver [[B4 - T1.3 ADMON SSOO - APACHE]] y [[Certificado TLS-SSL (X.509)]].

### 5.5 Acceso remoto y seguridad

| Protocolo | Nombre | Descripción | Puerto |
|---|---|---|---|
| Telnet | Telnet Protocol | Permite a un usuario en una máquina establecer una sesión de terminal remota en otra | TCP 23 |
| SSH | Secure SHell (Intérprete de órdenes seguro) | Protocolo que facilita las comunicaciones seguras entre dos sistemas usando una arquitectura cliente/servidor y que permite a los usuarios conectarse a un host remotamente. Utiliza cifrado. Se puede considerar la versión cifrada de Telnet | TCP 22 |
| SSL / TLS | Secure Sockets Layer (Capa de puertos seguros) / Transport Layer Security (Seguridad de la capa de transporte) | Protocolos criptográficos que proporcionan comunicaciones seguras por una red, normalmente Internet. Se usan certificados X.509. TLS es un protocolo de la IETF definido por primera vez en 1999. Se basa en las especificaciones previas de SSL, desarrolladas por Netscape Communications para agregar el protocolo HTTPS a su navegador Netscape Navigator. Última versión: TLS 1.3 (2018) | |

Vulnerabilidades de SSL/TLS citadas: BEAST, CRIME, BREACH, POODLE, RC4, renegociación...

Ver [[B4 - T1.2 ADMON SSOO - SSH]] (SSH), [[Certificado TLS-SSL (X.509)]] y [[Criptografía asimétrica (clave pública y privada)]] (base criptográfica).

> [!tip] Telnet vs SSH
> Telnet (23) = sesión remota sin cifrar; SSH (22) = su versión cifrada. SFTP también usa el 22.

### 5.6 Impresión

| Protocolo | Nombre | Descripción | Puerto |
|---|---|---|---|
| IPP | Internet Printing Protocol (Protocolo de impresión en Internet) | Protocolo de nivel de aplicación seguro que se utiliza para la impresión en red. Protocolo de impresión y gestión de los trabajos a imprimir, el tamaño del medio, la resolución, etc. Puede ser usado localmente o sobre Internet para comunicarse con impresoras locales o remotas, y soporta el control de acceso, la autenticación y el cifrado, siendo así una solución de impresión más capaz y segura | 631 |
| LPD/LPR | Line Printer Daemon / Line Printer Remote protocol | Protocolo originalmente implementado en la plataforma "BDS Unix" (tal como figura en el PDF). Utiliza TCP/IP para establecer conexiones entre impresoras y ordenadores en una red. Normalmente escucha peticiones en el puerto TCP 515 y consta de dos componentes: LPR (Line printer remote) es el proceso cliente de envío de trabajos de impresión a una impresora o cola de impresión; la estación que envía el trabajo es cliente LPR. LPD (Line printer daemon) es el proceso de recepción de trabajos desde un cliente LPR; las impresoras o servidores de impresión que los reciben se llaman servidores LPD | 515 TCP |

### 5.7 Tiempo real y multimedia

| Protocolo | Nombre | Descripción | Puerto |
|---|---|---|---|
| RTP | Real-time Transport Protocol (Protocolo de transporte en tiempo real) | Protocolo de nivel de aplicación utilizado para la transmisión de información en tiempo real, como audio y vídeo en una videoconferencia. Representa la base de la industria de VoIP | 5004 |
| RTCP | Real Time Control Protocol (Protocolo de control en tiempo real) | Protocolo de comunicación que proporciona información de control asociada con un flujo de datos para una aplicación multimedia (flujo RTP). Trabaja junto con RTP en el transporte y empaquetado de datos multimedia, pero no transporta ningún dato por sí mismo. Recoge estadísticas de la conexión | 5005 |
| SIP | Session Initiation Protocol (Protocolo de inicio de sesión) | Permite el establecimiento de sesiones multimedia entre dos o más usuarios, mediante el intercambio de mensajes entre las partes que quieren comunicarse. Estándar para la iniciación, modificación y finalización de sesiones interactivas de usuario donde intervienen elementos multimedia como vídeo, voz, mensajería instantánea, juegos en línea y realidad virtual | 5060 |

### 5.8 Escritorio remoto, procedimientos remotos, sincronización y compartición

| Protocolo | Nombre | Descripción | Puerto |
|---|---|---|---|
| RDP | Remote Desktop Protocol (Protocolo de escritorio remoto) | Protocolo propietario desarrollado por Microsoft que permite la comunicación en la ejecución de una aplicación entre un terminal (mostrando la información procesada que recibe del servidor) y un servidor Windows (recibiendo la información dada por el usuario en el terminal mediante el ratón o el teclado). Se utiliza frecuentemente para el acceso remoto en la administración de equipos | 3389 |
| RPC | Remote Procedure Call (Llamada a procedimiento remoto) | Permite a un programa de ordenador ejecutar código en otra máquina remota sin tener que preocuparse por las comunicaciones entre ambos | 530 |
| RSYNC | Remote Sync | Protocolo de sincronización de archivos (o datos) remotos que permite sincronizar un archivo almacenado en una computadora local con un archivo almacenado en una computadora remota, de modo que después de la sincronización, los archivos locales y remotos sean idénticos | 873 |
| SMB/CIFS | Server Message Block / Common Internet File System | Protocolo de red que permite compartir archivos, impresoras, etcétera, entre nodos de una red de computadoras que usan el sistema operativo Microsoft Windows. En 1998, Microsoft renombró SMB a CIFS. Vulnerabilidad: EternalBlue | 445/TCP |
| NTP | Network Time Protocol (Protocolo de tiempo de red) | Protocolo de Internet para sincronizar los relojes de los sistemas informáticos a través del enrutamiento de paquetes en redes con latencia variable. Última versión: NTPv4. Ver [[NTP (Network Time Protocol)]] | 123 udp |
| NetBIOS (nivel OSI 5) | Network Basic Input/Output System | Protocolo de red que viene activado por defecto en las tarjetas de red en Windows. Está algo obsoleto y hoy en día no es muy utilizado. Sin embargo puede tener vulnerabilidades que son aprovechadas por los piratas informáticos para llevar a cabo diferentes métodos de ataques. Provee los servicios de sesión descritos en la capa 5 del modelo OSI. Se encarga de establecer la sesión y mantener las conexiones. Debe transportarse entre máquinas a través de otros protocolos, porque por sí mismo no es suficiente para transportar los datos en redes LAN o WAN (ej.: en redes LAN el protocolo NetBEUI, en redes WAN el protocolo TCP/IP) | 137 |

> [!important] Idea clave
> NetBIOS es el único protocolo de la tabla de aplicación cuyo nivel OSI es solo el 5 (sesión); el resto figura como 5, 6, 7. Necesita otro protocolo de transporte (NetBEUI en LAN, TCP/IP en WAN).

## 🔑 Resumen ultra-rápido

- Capa 3: IP, IPv6, NAT, IPSec (AH 51, ESP 50, IKE), Mobile IP, ICMP, NDP (≈ ARP en IPv6). Capas 2/3: ARP (IP → MAC), RARP (MAC → IP), LDP (MPLS, 646). Capa 2: SLIP (obsoleto), PPP. Capa 4: TCP (fiable, protocolo 6), UDP (no fiable, protocolo 17).
- Enrutamiento: RIP (vector-distancia, UDP 520, máx. 15 saltos, libre), RIPng (521), OSPF (Dijkstra, protocolo 89), IGRP/EIGRP (propietarios Cisco), BGP (entre AS, TCP 179), EGP (sustituido por BGP a mediados de los 90).
- Nombres y configuración: DNS 53 (853 sobre TLS), LDAP 389/636, DHCP 67-68 (Discovery, Offer, Request, Acknowledge), DHCP6 546/547, BOOTP (sustituido por DHCP), NFS (con XDR y RPC), SNMP 161/162, RMON 560.
- Ficheros: FTP 20/21 TCP, FTPS 989/990, SFTP 22, TFTP 69 UDP.
- Correo: SMTP 25/2525/587/465 (envía), POP3 110/995 (descarga), IMAP4 143/993 (consulta remota); MIME no es un protocolo.

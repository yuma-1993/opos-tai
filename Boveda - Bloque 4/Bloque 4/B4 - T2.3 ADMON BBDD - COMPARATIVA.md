# Tema 2.3 · Bloque 4 — Administración de BBDD: comparativa de sintaxis

> [!abstract] De qué va este tema
> Tablas comparativas de cómo se escribe lo mismo en los cuatro SGBD del temario: **MySQL/MariaDB**, **Postgres**, **Oracle** y **SQL-Trasact** (Transact-SQL de SQL Server). Cubre funciones de fecha y hora (con los especificadores de formato de MySQL), DDL/DML (bases de datos, tablas, índices, vistas, procedimientos, usuarios y roles, restricciones `CHECK`, cursores), cadena de conexión JDBC y funciones de cadena. Se apoya en [[B4 - T2.1 ADMON BBDD]] y [[B4 - T2.2 ADMON BBDD - SGBD]]; la base de SQL está en [[B3 - T3 SQL]].

> [!note] Sobre la transcripción
> Las celdas vacías del PDF significan que **ese SGBD no tiene función equivalente listada** en el documento. Se respetan tal cual los ejemplos (incluidas erratas evidentes del original, señaladas con *sic*).

### 1.5 Especificadores de formato (MySQL: `DATE_FORMAT`, `TIME_FORMAT`, `STR_TO_DATE`)

| Especificador | Significado |
|---|---|
| `%a` | Abreviatura del día (Sun–Sat) |
| `%b` | Abreviatura del mes (Jan–Dec) |
| `%c` | Número de mes (1–12) |
| `%M` | Nombre completo del mes (January–December) |
| `%m` | Mes (01–12) |
| `%p` | AM o PM |
| `%D` | Día del mes con sufijo (1st, 2nd, 3rd, ...) |
| `%d` | Día del mes a dos dígitos (01, 02, ...) |
| `%e` | Día del mes (1, 2, 3, ...) |
| `%W` | Nombre del día (Sunday–Saturday) |
| `%w` | Día de la semana (0–6, 0 = domingo, 6 = sábado) |
| `%j` | Día del año (001–366) |
| `%X` | Año de cuatro dígitos con el domingo como primer día de la semana |
| `%x` | Año de cuatro dígitos con el lunes como primer día de la semana |
| `%Y` | Año de cuatro dígitos |
| `%y` | Año de dos dígitos |
| `%H` | Hora (00–23) |
| `%h` | Hora (01–12) |
| `%I` | Hora (01–12) |
| `%i` | Minuto (00–59) |
| `%k` | Hora (0–23) |
| `%l` | Hora (1–12) |
| `%r` | Hora en 12 h (hh:mm:ss AM o PM) |
| `%S` o `%s` | Segundos (00–59) |
| `%T` | Hora en 24 h (hh:mm:ss) |
| `%U` | Número de semana (00–53, domingo primer día de la semana) |
| `%u` | Número de semana (00–53, lunes primer día de la semana) |
| `%V` | Número de semana (01–53, domingo primer día de la semana) |
| `%v` | Número de semana (01–53, lunes primer día de la semana) |
| `%%` | Un literal `%` |

> [!tip] Mayúscula/minúscula en los formatos
> En `%Y%m%d %h%i` (ejemplo de `STR_TO_DATE`) `%m` es mes y `%i` minuto; `%M` es el **nombre** del mes y `%h`/`%H` horas en 12/24 h. Los pares mayúscula/minúscula (`%D`/`%d`, `%W`/`%w`, `%X`/`%x`, `%U`/`%u`, `%V`/`%v`) significan cosas distintas.

### 2.1 Crear base de datos

|---|---|---|---|
| `CREATE DATABASE [IF NOT EXISTS] database_name [CHARACTER SET charset_name] [COLLATE collation_name];` | `CREATE DATABASE hrdb WITH ENCODING='UTF8' OWNER=hr CONNECTION LIMIT=25;` | — (en Oracle no se crean BBDD, ver [[B4 - T2.1 ADMON BBDD]]) | `CREATE DATABASE database_name;` |

### 2.2 Crear tabla, `ALTER` y `UPDATE`

`CREATE TABLE account` con clave autoincremental:

```sql
-- MySQL/MariaDB
CREATE TABLE account(
  user_id serial AUTO-INCREMENT PRIMARY KEY,
  username VARCHAR (50) UNIQUE NOT NULL,
  email VARCHAR(30),
  last_login TIMESTAMP
);

-- Postgres
CREATE TABLE account(
  user_id serial PRIMARY KEY,
  username VARCHAR (50) UNIQUE NOT NULL,
  email VARCHAR(30),
  last_login TIMESTAMP
);

-- Oracle
CREATE TABLE ot.persons(
  user_id NUMBER GENERATED BY DEFAULT AS IDENTITY,
  username VARCHAR2(50) NOT NULL,
  email VARCHAR(30),
  last_login SYSTIMESTAMP,
  PRIMARY KEY(person_id)
);

-- SQL-Trasact
CREATE TABLE account (
  user_id INT PRIMARY KEY IDENTITY (1, 1),
  username VARCHAR (50) NOT NULL,
  email VARCHAR(30),
  last_login
);
```

| Aspecto | MySQL/MariaDB | Postgres | Oracle | SQL-Trasact |
|---|---|---|---|---|
| Autoincremental | `AUTO-INCREMENT` (en otro ejemplo del PDF `AUTO_INCREMENT`) | tipo `serial` | `GENERATED BY DEFAULT AS IDENTITY` | `IDENTITY (1, 1)` |
| Tipo de texto | `VARCHAR` | `VARCHAR` | `VARCHAR2` | `VARCHAR` |
| `ALTER TABLE account` | `ADD fnac DATE;` | `ADD COLUMN fnac DATE;` | `ADD fnac DATE;` | `ADD fnac DATE;` |
| `UPDATE account` | `SET last_login = DEFAULT WHERE last_login IS NULL;` | igual | igual | igual |

> [!important] Diferencias a recordar
> Solo **Postgres** exige la palabra `COLUMN` en `ALTER TABLE ... ADD COLUMN`. El autoincremental es distinto en cada uno: `AUTO_INCREMENT` (MySQL), `serial` (Postgres), `GENERATED ... AS IDENTITY` (Oracle), `IDENTITY(1,1)` (SQL Server). Oracle usa `VARCHAR2`. En Oracle clásico se hacía con `CREATE SEQUENCE` (ver [[B4 - T2.1 ADMON BBDD]]).

Más ejemplos de `CREATE TABLE` del PDF:

```sql
-- MySQL/MariaDB
CREATE TABLE IF NOT EXISTS tasks (
  user_id INT AUTO_INCREMENT PRIMARY KEY,
  username VARCHAR(50) NOT NULL,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Postgres
CREATE TABLE account(
  user_id serial PRIMARY KEY,
  username VARCHAR (50) UNIQUE NOT NULL,
  last_login TIMESTAMP
);

-- Oracle
CREATE TABLE ot.persons(
  user_id NUMBER GENERATED BY DEFAULT AS IDENTITY,
  username VARCHAR2(50) NOT NULL,
);

-- SQL-Trasact (con clave foránea)
CREATE TABLE sales.visits (
  user_id INT PRIMARY KEY IDENTITY (1, 1),
  username VARCHAR (50) NOT NULL,
  visited_at DATETIME,
  store_id INT NOT NULL,
  FOREIGN KEY(store_id) REFERENCES sales.stores(store_id)
);
```

### 2.3 `INSERT` con conflicto / `MERGE` (UPSERT)

| MySQL/MariaDB | Postgres | Oracle | SQL-Trasact |
|---|---|---|---|
| — (sin sentencia listada) | `INSERT ... ON CONFLICT (username) DO UPDATE SET email = ...` | `MERGE INTO` | `MERGE target_table USING source_table` |

```sql
-- Postgres
INSERT INTO account (username, email)
VALUES ('Microsoft', 'hotline@microsoft.com')
ON CONFLICT (username)
DO UPDATE SET email = EXCLUDED.email || ';' || account.email;

-- Oracle
MERGE INTO target_table
USING source_table
ON merge_condition
WHEN MATCHED THEN
  UPDATE SET col1 = value1,
  WHERE update_condition
  DELETE WHERE delete_condition
WHEN NOT MATCHED THEN
  INSERT (col1)
  values(value1)
  WHERE insert_condition;

-- SQL-Trasact
MERGE target_table USING source_table
ON merge_condition
WHEN MATCHED
  THEN update_statement
WHEN NOT MATCHED
  THEN insert_statement
WHEN NOT MATCHED BY SOURCE
  THEN DELETE;
```

> [!important] `MERGE`
> MySQL/MariaDB no lo tiene en el PDF; Postgres lo resuelve con `INSERT ... ON CONFLICT ... DO UPDATE`; Oracle y Transact-SQL usan `MERGE` (solo Transact-SQL añade `WHEN NOT MATCHED BY SOURCE THEN DELETE`). Concepto en [[MERGE (UPSERT)]].

### 2.5 Vistas

Concepto: [[Vista (VIEW) SQL]].

```sql
-- MySQL/MariaDB
CREATE VIEW customerPayments
AS
SELECT customerName, checkNumber, paymentDate, amount
FROM customers
INNER JOIN payments USING (customerNumber);

-- Postgres
CREATE VIEW customer_master AS
SELECT cu.customer_id AS id,
  cu.first_name || ' ' || cu.last_name AS name,
  a.address,
  a.postal_code AS "zip code",
  city.city,
FROM customer cu INNER JOIN address a USING (address_id)
INNER JOIN city USING (city_id)
INNER JOIN country USING (country_id);

-- Oracle
CREATE VIEW sales AS
SELECT customer_id,
  SUM(unit_price * quantity) total,
  ROUND(SUM(unit_price * quantity) * 0.05) credit
FROM order_items
INNER JOIN orders USING (order_id)
WHERE status = 'Shipped'
GROUP BY customer_id;

-- SQL-Trasact
CREATE VIEW sales.product_info
AS
SELECT product_name, brand_name, list_price
FROM production.products p
INNER JOIN production.brands b
ON b.brand_id = p.brand_id;
```

### 2.6 Procedimientos almacenados

Concepto: [[Procedimiento almacenado (Stored Procedure)]]; dialectos en [[SQL-PSM, PL-SQL y Transact-SQL]].

```sql
-- MySQL/MariaDB (se llama con CALL)
DELIMITER $$
CREATE PROCEDURE sp_name()
BEGIN
  -- statements
END $$
DELIMITER ;

-- Postgres (se llama con CALL)
CREATE OR REPLACE PROCEDURE transfer(INT, INT, DEC)
LANGUAGE plpgsql
AS $$
BEGIN
  UPDATE accounts
  SET balance = balance - $3
  WHERE id = $1;
  UPDATE accounts
  SET balance = balance + $3
  WHERE id = $2;
  COMMIT;
END;
$$;

-- Oracle (se llama con EXEC o EXECUTE)
CREATE [OR REPLACE] PROCEDURE procedure_name (parameter_list)
IS
  [declaration statements]
BEGIN
  [execution statements]
  EXCEPTION
    [exception handler]
END [procedure_name];
/

-- SQL-Trasact (se llama con EXEC o EXECUTE; PROCEDURE = PROC)
CREATE PROCEDURE uspProductList
AS
BEGIN
  SELECT product_name, list_price
  FROM production.products
  ORDER BY product_name;
END;
```

| | MySQL/MariaDB | Postgres | Oracle | SQL-Trasact |
|---|---|---|---|---|
| Se invoca con | `CALL` | `CALL` | `EXEC` o `EXECUTE` | `EXEC` o `EXECUTE` (`PROCEDURE` = `PROC`) |
| Particularidad | `DELIMITER $$ ... DELIMITER ;` | `LANGUAGE plpgsql`, cuerpo entre `$$` | `IS` antes del bloque; sección `EXCEPTION`; termina con `/` | `AS BEGIN ... END;` |

> [!tip] Truco para la llamada
> `CALL` = MySQL y Postgres; `EXEC`/`EXECUTE` = Oracle y SQL Server.

### 2.7 Usuarios, roles y permisos

Tipo de sentencias DCL (ver [[Sublenguajes SQL (DDL, DML, DCL, TCL)]]).

```sql
-- MySQL/MariaDB
CREATE USER bob@localhost identified by 'Secure1pass!';
CREATE ROLE manager;
GRANT INSERT, UPDATE, DELETE ON db_name.* TO manager;
GRANT manager TO bob@localhost
REVOKE INSERT, UPDATE ON db_name.* FROM bob@localhost;

-- Postgres
CREATE USER alice PASSWORD 'abcde';
CREATE ROLE doe WITH PASSWORD 'pgSecpas1970' VALID UNTIL '2020-01-01';
CREATE ROLE group_role;
GRANT group_role to user_role;
REVOKE group_role FROM user_role;

-- Oracle
CREATE USER alice IDENTIFIED BY abcd1234;
CREATE ROLE order_entry IDENTIFIED BY xyz123;
GRANT SELECT, INSERT, UPDATE, DELETE ON orders TO order_entry;
GRANT order_entry TO alice;

-- SQL-Trasact
CREATE USER user_name FOR LOGIN login_name;
CREATE ROLE role_name [ AUTHORIZATION owner_name ]
GRANT privileges ON object TO user
REVOKE privileges ON object FROM user;
```

### 2.9 Cursores

Concepto: [[Cursor (SQL)]].

```sql
-- MySQL/MariaDB
DECLARE finished INTEGER DEFAULT 0;
DECLARE emailAddress varchar(100) DEFAULT "";
DECLARE curEmail CURSOR FOR
  SELECT email FROM employees;
OPEN curEmail;
getEmail: LOOP
  FETCH curEmail INTO emailAddress;
  IF finished = 1 THEN
    LEAVE getEmail;
  END IF;
  SET emailList = CONCAT(emailAddress,";",emailList);
END LOOP getEmail;
CLOSE cursor_name;

-- Postgres
DECLARE
  cur_films CURSOR FOR SELECT * FROM film;
  cur_films2 CURSOR (year integer)
    FOR SELECT * FROM film WHERE release_year = year;
OPEN cur_films;
OPEN cur_films2(year:=2005);
FETCH cur_films INTO row_film;
FETCH LAST FROM row_film INTO title, release_year;
CLOSE cur_films;
CLOSE cur_films2;

-- Oracle
DECLARE
  CURSOR cpaises IS
    SELECT CO_PAIS, DESCRIPCION, CONTINENTE FROM PAISES;
  co_pais VARCHAR2(3);
  descripcion VARCHAR2(50);
  continente VARCHAR2(25);
BEGIN
  OPEN cpaises;
  FETCH cpaises INTO co_pais,descripcion,continente;
  DBMS_OUTPUT.PUT_LINE(continente);
  CLOSE cpaises;
END;

-- SQL-Trasact
DECLARE cursorEmp cursor for SELECT EmpID, LastName, FirstName FROM Employees;
OPEN cursorEmp;
FETCH cursorEmp;
CLOSE cursorEmp;
DEALLOCATE cursorEmp;
```

> [!important] Ciclo de vida del cursor
> `DECLARE` -> `OPEN` -> `FETCH` -> `CLOSE`. Solo **Transact-SQL** añade `DEALLOCATE` al final. En Oracle el cursor se declara con `CURSOR nombre IS SELECT ...`; en MySQL/Postgres/T-SQL con `CURSOR FOR SELECT ...`. Postgres admite cursores con parámetros (`CURSOR (year integer) FOR ...`).

## 🔑 Resumen ultra-rápido

- Fecha-hora actual: MySQL `NOW()`/`SYSDATE()`; Postgres `NOW()`; Oracle `SYSDATE` (`FROM DUAL`); Transact-SQL `GETDATE()`/`SYSDATETIME()`. `CURRENT_TIMESTAMP` en los cuatro.
- Sumar fechas: MySQL `DATE_ADD`/`ADDDATE`; Postgres no tiene (usa `+ INTERVAL '1 day'`); Oracle `ADD_MONTHS`; T-SQL `DATEADD(datepart, n, date)`.
- Diferencia de fechas: MySQL `DATEDIFF`; Postgres `AGE`; Oracle `MONTHS_BETWEEN`; T-SQL `DATEDIFF(datepart, start, end)`.
- Truncar fecha: MySQL/Oracle `TRUNC`/`ROUND`; Postgres `DATE_TRUNC`. Extraer: `EXTRACT` (MySQL, Postgres, Oracle) / `DATEPART` (T-SQL).
- MySQL es el que más funciones de fecha trae (`DAYNAME`, `WEEK`, `TIMEDIFF`, `TIMESTAMPADD`...). Formatos `%Y %m %d %H %i %s`; `%M` nombre del mes, `%W` nombre del día, `%j` día del año.
- Crear BD: MySQL con `IF NOT EXISTS`, `CHARACTER SET`, `COLLATE`; Postgres con `ENCODING`, `OWNER`, `CONNECTION LIMIT`; Oracle no crea BBDD.
- Autoincremental: `AUTO_INCREMENT` (MySQL), `serial` (Postgres), `GENERATED BY DEFAULT AS IDENTITY` (Oracle), `IDENTITY(1,1)` (T-SQL). Oracle: `VARCHAR2`. Solo Postgres: `ADD COLUMN`.
- UPSERT: Postgres `INSERT ... ON CONFLICT DO UPDATE`; Oracle y T-SQL `MERGE` (T-SQL añade `WHEN NOT MATCHED BY SOURCE`).
- Procedimientos: `CALL` en MySQL y Postgres (`DELIMITER $$`; `LANGUAGE plpgsql ... $$`); `EXEC`/`EXECUTE` en Oracle (`IS ... EXCEPTION ... /`) y T-SQL (`PROC`).
- Usuarios y roles: `CREATE USER ... IDENTIFIED BY` (MySQL, Oracle), `CREATE USER ... PASSWORD` (Postgres), `CREATE USER ... FOR LOGIN` (T-SQL); `GRANT`/`REVOKE`; Postgres `VALID UNTIL`.
- Cursores: `DECLARE`/`OPEN`/`FETCH`/`CLOSE`; T-SQL añade `DEALLOCATE`; Oracle `CURSOR x IS SELECT`.
- JDBC: `jdbc:mysql://localhost:3306/...`, `jdbc:postgresql://...`, `jdbc:oracle:thin:@localhost:1521:orcl`, `jdbc:sqlserver://localhost:1433;database=...`.
- Cadenas: longitud `CHAR_LENGTH`/`LENGTH`/`LEN`; posición `INSTR`/`CHARINDEX`; concatenar `CONCAT`, `||` (Oracle/Postgres) y `+` (T-SQL); exclusivas T-SQL: `PATINDEX`, `SPACE`, `STR`, `STUFF`; exclusivas Postgres/Oracle: `INITCAP`, `LPAD`, `RPAD`, `TRANSLATE`.

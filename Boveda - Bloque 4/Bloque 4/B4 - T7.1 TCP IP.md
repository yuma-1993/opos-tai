# Tema 7.1 · Bloque 4 — TCP/IP

> [!abstract] De qué va este tema
> Recorre la pila de comunicaciones de arriba abajo: el modelo OSI y su equivalencia con TCP/IP, el nivel de enlace (ARP, VLAN), el nivel de red (datagrama IPv4 e IPv6, direccionamiento classful/classless/subnetting, NAT, protocolos de enrutamiento, ICMP) y el nivel de transporte (TCP, UDP), con FTP como ejemplo de protocolo de aplicación y el método VLSM como ejercicio de subnetting. La tabla completa de protocolos por capa y puertos está en [[B4 - T7.2 TCP IP - PROTOCOLOS]].

## 1. Modelo OSI

El modelo OSI (ISO/IEC 7498-1 o ITU-T X.200) es un patrón de arquitectura planteado para el software, para que 2 equipos de la red se conecten y comuniquen con reglas estandarizadas. Es un modelo pila/stack de protocolos. El 90% se corresponde con software; hay una pequeña parte hardware dentro del nivel físico. No en todos los equipos intervienen todos los niveles: mi PC tiene los 7 niveles, pero el router de casa solo los niveles 1, 2 y 3. Mi PC se comunica con el router a nivel 2.

### 1.1 Capas y unidades de datos

El diagrama del PDF agrupa las capas en "capas del anfitrión" (aplicación, presentación, sesión, transporte) y "capas del medio" (red, enlace de datos, físico), con su unidad de datos:

| Nivel | Capa | Unidad de datos | Qué hace / protocolos que cita el PDF |
|---|---|---|---|
| 7 | Aplicación | Dato | Servicios de red a aplicaciones. CMIS/CMIP (~SNMP), FTAM (~FTP), X.500 (~LDAP), X.400 (~SMTP) |
| 6 | Presentación | Dato | Representación de los datos: compresión, cifrado, codificación (audio, vídeo, caracteres: UTF-8) |
| 5 | Sesión | Dato | Gestión de conexiones (comunicación entre dispositivos) |
| 4 | Transporte | Segmento | Transporte host-to-host (conexión de extremo a extremo y control de flujo de datos). TP0, TP1, TP2, TP3, TP4 |
| 3 | Red | Paquete | Encaminamiento entre no adyacentes (determinación de ruta y direccionamiento lógico, IP). Grafos, caminos. CLNS (CLNP ≈ IP, IS-IS ≈ OSPF), CONS |
| 2 | Enlace | Trama | Flujo entre entidades adyacentes, acceso al medio y gestión del enlace (direccionamiento físico, MAC y LLC). Es la primera capa que gobierna el flujo de información entre máquinas. HDLC, LAPB |
| 1 | Físico | Bit | Señal y transmisión binaria |

> [!important] Capas 5 y 6
> Protocolos de las capas 5 y 6: no es fácil su diferencia. Ejemplo: SSL.

> [!important] Transporte OSI vs TCP/UDP
> TP0, TP1, TP2, TP3, TP4: TP1, TP3 y TP4 son fiables ≈ TCP. TP0 y TP2 son no fiables ≈ UDP.

La capa de red usa grafos y caminos (ver [[Grafo (conceptos básicos)]] y [[Algoritmo de Dijkstra]], el algoritmo que usa OSPF, sección 6).

### 1.2 Terminología de interfaz entre capas

Diagrama del PDF: entre la capa N+1 y la capa N hay una interfaz; la IDU (Interface Data Unit) que cruza el SAP está formada por ICI + SDU.

| Sigla | Significado |
|---|---|
| SAP | Service Access Point. Funciones lenguaje C |
| IDU | Interface Data Unit |
| SDU | Service Data Unit: paquete que se intercambia en vertical |
| ICI | Interface Control Information. Solo usado en el SAP |
| PDU | Protocol Data Unit. Formato de datos de cada capa (segmento, paquete, etc.). PDU(N) = SDU(N+1) + ICI. Se intercambia en horizontal |

(En el diagrama: SDU se marca con flecha vertical y PDU con flecha horizontal.)

- Cada capa impone un formato de datos de intercambio (PDU). La finalidad era la seguridad.
- Desventaja: tiene una sobrecarga (overhead) enorme.
- Cada capa se ocupa de una serie de funcionalidades.
- MAC y LLC son subcapas del modelo IEEE, no de OSI. Su equivalencia es nivel 2.

### 1.3 Equivalencia con el modelo TCP/IP

| Pila OSI | Pila TCP/IP |
|---|---|
| Aplicación, Presentación, Sesión (5, 6 y 7) | Aplicación |
| Transporte (4) | Transporte |
| Red (3) | Internet |
| Enlace (2) y Físico (1) | Acceso a red |

> [!tip] Regla rápida
> TCP/IP tiene 4 capas: Acceso a red (1 y 2), Internet (3), Transporte (4) y Aplicación (5, 6 y 7).

Diagrama del PDF "DoD (TCP/IP) – OSI – Internet Suite Protocols", transcrito:

| DoD (TCP/IP) | OSI | Protocolos |
|---|---|---|
| Process / Application | Application | FTP, NNTP, TELNET, NFS, XDR, RPC, SNMP, TFTP, BOOTP, DHCP |
| | Presentation | SMTP, NIS |
| | Session | SSH, ASP, HTTP, DNS, NetBIOS, RTP, RTCP, DNS |
| Host to Host | Transport | TCP, UDP |
| Internet | Network | IP, ICMP, IGMP, IPSec, RIP, OSPF, EIGRP, BGP, ARP, RARP |
| Network Access | Data Link / Physical | IEEE 802.3 (Ethernet), IEEE 802.5 (Token Ring), 802.11 (Wi-Fi), HDLC, PPP, Frame Relay, ATM, etc. (hasta que sea binario) |

(La colocación exacta de cada protocolo en las filas Application/Presentation/Session está tomada del diagrama del PDF, que no es del todo legible.)

Otro esquema del PDF sitúa TELNET, FTP, SMTP, DNS, RIP, SNMP sobre TCP o UDP (TCP: Telnet, FTP, SMTP; UDP: DNS, RIP, SNMP), con ARP e IP (IGMP, ICMP) en la capa de red y Ethernet, Token Ring, Frame Relay y ATM en enlace/físico.

## 2. Nivel de enlace

- El nivel de red es el último nivel de encaminamiento. Direcciones físicas (MAC de 48 bits). Para poder llegar lejos (red), antes tengo que dar un paso (enlace).
- Switching: técnica que se ocupa del direccionamiento físico. Es el routing del nivel 2.

¿Cómo garantizamos que la información llega a mi vecino inmediato?

| Subcapa | Función |
|---|---|
| LLC | Encapsula los protocolos de red, controla los errores y sincroniza las tramas. Es la parte más lógica |
| MAC | Controla el acceso de los dispositivos al medio y los permisos para transmitir datos. Es la parte más física. Algoritmos para difusión sin bucles (árboles de difusión): STP, MSTP, RSTP, SPB |

### 2.1 ARP y VLAN

- Protocolo ARP: obtiene la dirección MAC de una IP. Usa broadcast (MAC FF FF FF FF FF FF). Caché ARP (IP - MAC). RARP hace lo inverso (ver [[B4 - T7.2 TCP IP - PROTOCOLOS]]).
- VLAN (802.1Q): podemos definir un nivel lógico que no tiene por qué corresponderse con las conexiones físicas y aislar unas zonas de otras (seguridad, rendimiento). Gestión de tráfico. Las VLAN se configuran en los switches. Los routers se encargan de encaminar tráfico entre VLANs. La VLAN es una etiqueta dentro de la PDU.

> [!note] Ampliación (conocimiento general, no viene del PDF)
> La idea de aislar zonas lógicas independientemente de la topología física es la misma que usa el zoning de una SAN Fibre Channel: ver [[Zoning (SAN)]] (que el propio tema [[B4 - T1.1 ADMON SSOO]] compara con las VLAN).

## 3. Nivel de red: generalidades

- Un interfaz de red físico tiene varias direcciones IP para que tenga alcance desde distintos ámbitos (IPv6) o global (IPv4).
- Tabla de encaminamiento / routing table: 3 tipos de rutas: directamente conectadas (DC), estáticas y dinámicas (aprendidas).
- Otros protocolos importantes: NTP, SMB/CIFS, LDAP, H.323/SIP, RDP, IPP.

## 4. Datagrama IPv4

El datagrama IPv4 es la PDU del nivel de red. Un datagrama fragmentado se divide en "paquetes IP" (MTU del N2 – Payload Ethernet). Fragment offset = desplazamiento. Cabecera de 20 a 60 bytes.

### 4.1 Campos de la cabecera (diagrama del PDF)

| Campo | Tamaño |
|---|---|
| Version | 4 bits |
| IHL | 4 bits |
| DSField (DSCP) | 6 bits |
| ECN | 2 bits |
| Total Length | 16 bits |
| Identification | 16 bits |
| Flags | 3 bits |
| Fragment Offset | 13 bits |
| Time-to-Live (TTL) | 8 bits |
| Protocol | 8 bits |
| Header Checksum | 16 bits |
| Source IP Address | 32 bits |
| Destination IP Address | 32 bits |
| Options (si las hay) | longitud variable, hasta 320 bits / 40 bytes |
| IP Data (si hay) | longitud variable, hasta 524.120 bits / 65.515 bytes |

### 4.2 Campos destacados

| Campo | Significado |
|---|---|
| Flags: MF (More fragments) | 0 = último o único fragmento |
| Flags: DF (Don't fragment) | Algoritmo de descubrimiento de MTU |
| TTL (Time to live o número de saltos) | Los routers lo van decrementando. Si llega a cero lo eliminan y notifican su eliminación al origen con ICMP "Tiempo excedido" |
| Protocol | Indica qué estamos transportando del nivel superior |
| DSCP (Differentiated Services Code Point) | Diferenciación de servicios / QoS. Sustituye al antiguo campo TOS (tipo de servicio), que ahora tiene otro sentido |
| ECN (Explicit Congestion Notification) | Notifica congestión de red sin borrar paquetes |

### 4.3 Valores del campo Protocol

| Valor | Protocolo |
|---|---|
| 1 | ICMP |
| 2 | IGMP |
| 6 | TCP |
| 17 | UDP |
| 50 | ESP (IPSec) |
| 51 | AH (IPSec) |
| 89 | OSPF |

> [!tip] Mnemotecnia
> 1-2-6-17 (ICMP, IGMP, TCP, UDP), luego 50/51 = IPSec (ESP/AH), 89 = OSPF.

### 4.4 Otros protocolos mencionados junto al datagrama

| Protocolo | Para qué |
|---|---|
| ICMP | Mensajes de control |
| IGMP | Gestión de grupos multicast |
| NTP | Fecha y hora de servidores (ver [[NTP (Network Time Protocol)]]) |
| SMB/CIFS | Almacenamiento en red. Compartición de archivos e impresoras |
| LDAP | Servicio de directorio |
| H.323/SIP | Videoconferencia/VoIP |
| RDP | Protocolo de escritorio remoto |
| IPP | Protocolo de impresión |

> [!important] NFS, XDR y RPC
> RPC y el sistema de archivos de red (NFS) usan XDR para describir sus formatos de datos. Siempre van los 3 de la mano.

## 5. Direccionamiento IPv4

### 5.1 Classful

Classful: uso ineficiente del espacio de IPs.

| Clase | Rango 1.er octeto | Bits iniciales | Redes | Hosts por red | Notas del PDF |
|---|---|---|---|---|---|
| A | 0-127 | 0 | 2^7 (solo hay 126 posibles redes) | 2^24 - 2 | Especial: 0.0.0.0. Privadas: 10.0.0.0. Reservadas: 127.0.0.1/8 Loopback |
| B | 128-191 | 10 | 2^14 | 2^16 - 2 | Privadas: 172.16.0.0 – 172.31.255.255. Reservadas: 169.254.0.0 – 169.254.255.255. Direcciones automáticas (APIPA): 169.254.1.0 – 169.254.254.255 |
| C | 192-223 | 110 | 2^21 | 2^8 - 2 | Privadas: 192.168.0.0 – 192.168.255.255 |
| D | 224-239 | 1110 | Multicast. Grupos de difusión (dirección de grupo multicast de 28 bits) | | |
| E | 240-255 | 1111 | No es para identificar redes. Uso experimental (bits 5 a 32) | | |

Esquema del PDF (anchura 32 bits): Clase A = 1 bit de clase + Network ID (bits 2 a 8) + Host ID (24 bits). Clase B = 2 bits + Network ID (bits 3 a 16) + Host ID (16 bits). Clase C = 3 bits + Network ID (bits 4 a 24) + Host ID (8 bits).

| Parte de host | Significado |
|---|---|
| Todo a 0 | Dirección instrumental que identifica la red |
| Todo a 1 | Dirección instrumental que identifica todos los hosts (broadcast: de una máquina a todas) |

> [!note] Ampliación (conocimiento general, no viene del PDF)
> El "-2" de los hosts por red corresponde a esas dos direcciones instrumentales (red y broadcast), que no se pueden asignar a un equipo. Del mismo modo, las "126 redes" de clase A salen de 2^7 = 128 menos dos redes reservadas (la 0 y la 127, esta última el loopback).

### 5.2 Traducción de direcciones: NAT

| Tipo | Qué hace |
|---|---|
| Source NAT | Se cambia la dirección IP de origen. Ejemplo: cuando usamos una IP privada en una red local y establecemos una conexión con un equipo de Internet. Un equipo de la red (normalmente el gateway) cambia la IP privada origen por la IP pública para que el equipo de Internet pueda contestar. También conocido como IP masquerading |
| SNAT estático (Static NAT) | La IP pública que sustituye a la IP origen es estática |
| SNAT dinámico o MASQUERADE | La IP pública que sustituye a la IP origen es dinámica (habitual en conexiones domésticas) |
| Destination NAT o port forwarding | Se utiliza cuando tenemos algún servidor en una máquina detrás del dispositivo de NAT. Un equipo externo inicia la conexión, solicita un determinado servicio y el dispositivo de NAT debe modificar la dirección IP destino. Ej: servidor web |
| PAT (Port Address Translation) | Modifica el puerto (origen o destino) en lugar de la IP. Ej: peticiones web al 80 -> 8080 |

> [!note] Ampliación (conocimiento general, no viene del PDF)
> Un servidor expuesto con port forwarding queda accesible desde fuera; para aislarlo de la red interna se suele situar en una DMZ (ver [[DMZ (zona desmilitarizada)]]).

### 5.3 Classless (CIDR)

- La ICANN introduce el concepto de prefijo CIDR (Classless Inter-Domain Routing).
- Notación w.x.y.z /a donde "a" es el prefijo de red. 32 - a bits para direcciones host (esquema del PDF: n bits de prefix + 32-n bits de suffix).
- Necesidad de nuevos protocolos de routing (RIPv2, OSPF).
- Las direcciones se agrupan en "Bloques CIDR" en los ISP según necesiten los RIR.
- Las tablas de encaminamiento antes tenían 3 cortes, ahora 31. Para minimizar el número de entradas en las tablas del router, se pueden agrupar distintos "Bloques CIDR" que compartan una parte de la numeración contigua: Supernetting.
- Prefijo mínimo /1; rango /1 - /31 (/31 = 2 máquinas, punto a punto); /32 = 1 máquina.

> [!note] Actualización 17/12/2025 (documento "# Actualizaciones 20_05_2026")
> La fe de erratas del autor para B4-T7.1 confirma exactamente este punto: "Direccionamiento IPv4 Classless - Prefijo CIDR: Mínimo /1 - /31 (2 máquinas - Punto a punto) - /32 (1 máquina)". Ya está así recogido arriba. El mismo documento indica, para el B4-T7.3, que los libros de subnetting incluyen un cuaderno de ejercicios de libre distribución (con soluciones el del profesor, sin soluciones el del alumno); son material complementario y no forman parte de esta nota.

### 5.4 Subnetting

- Consiste en dividir el espacio de host en subredes y hosts. Internet es un modelo de redes. Se roban bits de la parte host para hacer subredes (esquema: antes Network identifier + Host identifier; después Network identifier + Subnet identifier + Host identifier).
- FLSM: máscara de red fija. No admite subredes de distinto tamaño.
- Máscara de red/subred: parte red/subred a 1 y parte host a 0.
- Existe un tipo de máscara llamada wildcard que sirve para poder crear ACL's (permisos) en un router sobre una serie de hosts concretos. Parte de red a 0's y parte host a 1's.
- VLSM: máscara de red variable. Aprovecha mejor el espacio de direcciones. Solo aplicable con protocolos de enrutamiento classless. Es como un subnetting sobre clases.

| Concepto | Red | Host |
|---|---|---|
| Máscara de red/subred | 1 | 0 |
| Máscara wildcard | 0 | 1 |

### 5.5 Método VLSM (ejemplo resuelto del PDF)

Pasos:
1. Ordenar las redes de modo decreciente por número de hosts, de más a menos hosts.
2. Calcular el número de bits necesarios para direccionar el número de hosts de cada una de las redes, teniendo en cuenta la red y el broadcast.
3. Los bits de la derecha son para el host y los que sobran hasta la máscara son para subredes.

> [!example] Problema: partimos de 192.168.0.0 / 24
> Topología: una nube de 80 hosts, dos de 20 hosts y tres enlaces entre routers (Red D, E, F) de 2 hosts.
>
> | Red | Hosts | Bits de host | Resultado |
> |---|---|---|---|
> | A | 80 | 7 bits | 192.168.0.0 / 25 |
> | B | 20 | 5 bits | 192.168.0.128 / 27 |
> | C | 20 | 5 bits | 192.168.0.160 / 27 |
> | D | 2 | 2 bits | 192.168.0.192 / 30 |
> | E | 2 | 2 bits | 192.168.0.196 / 30 |
> | F | 2 | 2 bits | 192.168.0.200 / 30 |
>
> El PDF lo muestra en binario: A = 0 + 7 bits de host; B = 1 + 2 bits de subred + 5 bits de host (.128); C = 1 0 1 + 5 bits de host (.160); D, E, F = 1 1 0 + 3 bits de subred + 2 bits de host (.192, .196, .200). Los bits marcados "S" en el diagrama son los de subred.

## 6. Datagrama IPv6

Las direcciones son de 128 bits frente a 32 de IPv4. Cabecera de 40 bytes (40 octetos), frente a 20 de IPv4. Host: 64 bits menos significativos.

Cabecera básica (diagrama): Ver, Traffic Class, Flow Label, Payload Length, Next Header (= UL, capa superior), Hop Limit, Source IPv6 Address, Destination IPv6 Address. Después, el Upper Layer (UL) Header y el Payload.

### 6.1 Encadenamiento de cabeceras de extensión

> [!important] Cabeceras de extensión
> Si tienes Next header, las cabeceras de extensión se ponen en el payload, no en la cabecera. Cada cabecera de extensión lleva su propio Next Header que apunta a la siguiente (EH1 → EH2 → EH3 → UL).

Ejemplos del PDF:
- Datagrama IPv6 sin cabeceras de extensión transportando un segmento TCP: Next Header = 6 (TCP).
- Datagrama IPv6 con dos cabeceras de extensión: Next Header = 0 (Hop-by-Hop Options Header) → Next Header = 44 (Fragment Header) → Next Header = 6 → TCP.

Orden y códigos de Next Header (tabla del PDF):

| Orden | Tipo de cabecera | Código Next Header |
|---|---|---|
| 1 | Basic IPv6 Header | - |
| 2 | Hop-by-Hop Options | 0 (= Jumbo) |
| 3 | Destination Options (with Routing Options) | 60 |
| 4 | Routing Header | 43 |
| 5 | Fragment Header | 44 |
| 6 | Authentication Header | 51 |
| 7 | Encapsulation Security Payload Header | 50 |
| 8 | Destination Options | 60 |
| 9 | Mobility Header | 135 |
| - | No next header | 59 |
| Upper Layer | TCP | 6 |
| Upper Layer | UDP | 17 |
| Upper Layer | ICMPv6 | 58 |

### 6.2 Transición de IPv4 a IPv6

| Mecanismo | Detalle |
|---|---|
| Dual Stack | A la dirección ::FFFF:a:b:c:d se la llama mapped-address y es la forma de convertir una IPv4 en una IPv6 "interna" |
| Método 6to4 | Técnica basada en tunneling que permite enviar paquetes IPv6 sobre redes IPv4. Formato: 2002 (16 bits) + IPv4 (32 bits) + SubnetID (16 bits) + Interface (64 bits) |

### 6.3 Sintaxis / compresión de direcciones

- Se eliminan los 0 por la izquierda.
- Cambiar grupos seguidos de :0 por :: solo se puede hacer una vez. Lo habitual es comprimir el mayor grupo de ceros.

### 6.4 Tipos de direcciones

Ya no existe broadcast. Loopback: IPv4 127.0.0.1 /8 y IPv6 ::1/128.

| Tipo | Prefijo | Características |
|---|---|---|
| Unicast Link-Local (no enrutable) | FE80::/10 | Autoconfiguración y descubrimiento de vecindario. ≈ direcciones APIPA. 10 bits de prefijo (FE 10-00 0000) + 54 ceros + 64 de interface. No tiene identificador de red al no ser enrutable |
| Unicast Unique-Local (enrutable en tu red) | FC00::/7 (F 110-0/1) | Antes llamado Site-Local. ≈ direcciones privadas. Se divide en 2 bloques: FD00::/8 (cuarto bit a 1) y FC00::/8 (sin uso definido, cuarto bit a 0). 7 prefijo + 1 + 40 random + 16 subred + 64 interface |
| Unicast Global (pública) | 2000::/3 | Las redes empiezan por 2 o por 3 (0010 o 0011). La subred son 16 bits o menos. 001 + prefijo global (3 + 45 bits) + subred (16) + interface ID (64) |
| Multicast | FF00::/8 | Grupo de interfaces. FF02::1 = todos los nodos (scope 02 = link local). FF02::2 = todos los routers (scope 02 = link local) |
| Anycast | (como unicast) | Un interface dentro de un grupo. Varios equipos pueden tener la misma IP y el router decide a quién le entrega la información. Se usa para sistemas de alta disponibilidad |

Formato de la dirección multicast (diagrama): 8 bits a 1 (0xFF) + 4 bits de flags (0 R P T) + 4 bits de ámbito (scope) + 112 bits de identificador de grupo.

La dirección multicast "Solicited-Node" se usa en el protocolo de descubrimiento de vecinos y en la fase de detección de direcciones duplicadas del proceso de configuración automática de direcciones.

### 6.5 Configuración de interfaces IPv6

Configuración de la dirección IPv6 de la máquina:
- Manual.
- DHCP6: stateful.
- SLAAC: autoconfiguración stateless (mecanismo para detectar IPs duplicadas).

Generación de los 64 bits de la derecha (interface ID): aleatoria o algoritmo EUI-64 modificado:
1. Dirección MAC (48 bits) de la tarjeta de red.
2. En medio se mete FF FE (16 bits).
3. El 7.º bit se invierte.

> [!example] Ejemplo del diagrama del PDF
> MAC 22 AC 9E 18 BE 80 → EUI-64: 22 AC 9E FF FE 18 BE 80 → EUI-64 modificado: 20 AC 9E FF FE 18 BE 80 (el primer octeto pasa de 22 a 20 al invertir el 7.º bit).

Prefijo de red: protocolo NDP, mensajes ICMPv6: RA, RS, NS, NA y redirect (Router/Neighbor Advertisement/Solicitation).

## 7. Protocolos de enrutamiento

- Los algoritmos de exterior (EGP) se dan entre sistemas autónomos (AS), entre ISPs. El número AS lo asigna IANA.
- Vector distancia: intercambio con los vecinos.
- Estado enlace: foto completa de la red. Más óptimo.
- OSPF se puede descomponer en áreas (una de ellas llamada Backbone) y usa las direcciones multicast 224.0.0.5 y 224.0.0.6.
- RIPv2 manda por multicast la tabla de routing a todos los routers adyacentes a la dirección 224.0.0.9. RIPv1 usaba broadcast. Los routers usan RIP.
- Protocolos que soportan VLSM: OSPF, RIPv2, IS-IS y EIGRP.

### 7.1 Clasificación (diagrama del PDF)

| | Distance Vector (nº de saltos) | Link State (estado de los enlaces) | Path Vector (exterior, EGP) |
|---|---|---|---|
| Classful | RIPv1 (1982/1988), IGRP (1985) | | EGP (1982) |
| Classless | RIPv2 (1994), EIGRP (1992) | OSPFv2 (1991), IS-IS (1990) | BGP4 (1995) |
| IPv6 | RIPng (1997), EIGRP for IPv6 (not yet released) | OSPFv3 (1999), IS-IS for IPv6 (2000) | BGP4 for IPv6 (1999) |

Los de distance vector y link state son Interior Gateway Protocols (IGP).

### 7.2 Comparación RIP vs OSPF (tabla del PDF)

| Característica | RIP v1 | RIP v2 | OSPF |
|---|---|---|---|
| Algoritmo | Bellman-Ford | Bellman-Ford | Dijkstra |
| Selección de ruta | Por saltos (hop based) | Por saltos | Shortest Path (ver [[Algoritmo de Dijkstra]]) |
| Enrutamiento | Classful | Classless | Classless |
| Transmisión | Broadcast | Multicast | Multicast |
| Distancia administrativa | 120 | 120 | 110 |
| Límite de saltos | 15 | 15 | Sin límite |
| Autenticación | No | MD5 | MD5 |
| Protocolo | UDP | UDP | IP |
| Tiempo de convergencia | RIP > OSPF (RIP tarda más) | | |

> [!important] Idea clave
> RIP = vector distancia, Bellman-Ford, máx. 15 saltos, UDP. OSPF = estado de enlace, Dijkstra, sin límite de saltos, directamente sobre IP (protocolo 89), multicast 224.0.0.5/224.0.0.6.

## 8. ICMPv4

Protocolo de control ICMPv4: se encapsula directamente sobre IP, por lo que es enrutable. Cabecera de 4 bytes.

Formato del mensaje: type (1 byte: tipo de mensaje ICMP), code (1 byte: subtipo), checksum (2 bytes: similar al checksum de la cabecera IP, calculado sobre todo el mensaje ICMP) + additional information (4 bytes puestos a 0 si no hay información adicional, por lo que cada mensaje ICMP mide al menos 8 bytes).

| Categoría | Tipo | Mensaje |
|---|---|---|
| Error-reporting | 3 | Destination unreachable |
| Error-reporting | 4 | Source quench |
| Error-reporting | 11 | Time exceeded |
| Error-reporting | 12 | Parameter problem |
| Error-reporting | 5 | Redirection |
| Query | 8/0 | Echo (request/reply) |
| Query | 13/14 | Timestamp (req./rep.) |
| Query | 18/18 (tal como aparece en el PDF) | Address mask (req./rep.) |
| Query | 10/9 | Router solicitation/advertisement |

> [!important] Tipos clave
> - Los tipos 8/0 se usan en el comando ping y además el 11 en traceroute.
> - El tipo 3 con code=4 "Fragmentation Needed" se usa para el descubrimiento de MTU (relacionado con el flag DF del datagrama IPv4).

> [!note] Ampliación (conocimiento general, no viene del PDF)
> En el diagrama del PDF el par de address mask aparece como "18/18"; en la RFC 792 los tipos de address mask son 17 (request) y 18 (reply), por lo que probablemente es una errata de la imagen. No es un dato del PDF.

## 9. Transporte: TCP

- No usa direcciones, usa puertos. Es garantista (fiable). Cabecera de 20 a 60 bytes.
- El número de puerto identifica a una aplicación en uno de los extremos (Socket).

| Rango | Nombre | Quién asigna |
|---|---|---|
| 0 - 1023 | Well Known Ports o System Ports | IANA |
| 1024 - 49151 | Registered Ports o User Ports | |
| 49152 - 65535 | Dynamic Ports o Private Ports | |

- Proceso de establecimiento de conexión (handshake) previo al envío de información. Se determinan los números de secuencia que usará cada extremo en esa sesión. En el primer segmento SYN se establece Window Scale, MSS, ECN Capable, etc. El tamaño de ventana es muy pequeño, así que se usa un factor multiplicador (Window scale).
- Proporciona transporte fiable extremo a extremo (ACK con un número de secuencia). Opción SACK para confirmar un bloque de secuencias "sin orden" cuando hay pérdidas de paquetes.
- Mecanismo de control de flujo basado en ventana "de recepción" deslizante (cada ACK viene con el campo Window Size informado). Window Size = 0 si el equipo está saturado y no puede recibir más información.
- MSS: tamaño máximo de segmento que el destino está dispuesto a recibir. Número de bytes que estamos dispuestos a recibir en un único segmento (relacionado con la MTU para evitar fragmentación en IP). Se informa en la PDU. Cada extremo maneja un MSS independiente.

> [!important] Fórmula
> MSS = MTU – IPHeader – TCPHeader.

### 9.1 Flags importantes

| Flag | Nombre | Función |
|---|---|---|
| URG | Urgent | Los datos del paquete deben ser procesados inmediatamente |
| PSH | Push | Envía inmediatamente todos los datos almacenados en el buffer |
| FIN | Finish | No habrá más transmisiones |
| ACK | Acknowledgment | Reconoce la recepción de un paquete |
| RST | Reset | Resetea una conexión |
| SYN | Synchronize | Inicia una conexión entre hosts |

### 9.2 Cabecera TCP (20-60 bytes)

| Campo | Tamaño |
|---|---|
| Source port number | 2 bytes |
| Destination port number | 2 bytes |
| Sequence number | 4 bytes |
| Acknowledgement number | 4 bytes |
| Data offset | 4 bits |
| Reserved | 3 bits |
| Control flags | 9 bits |
| Window size | 2 bytes |
| Checksum | 2 bytes |
| Urgent pointer | 2 bytes |
| Optional data (opciones) | 0-40 bytes |

### 9.3 Handshake de 3 vías (diagrama del PDF)

| Paso | Origen | Segmento | Estado tras el paso |
|---|---|---|---|
| Inicial | | Cliente CLOSED, servidor LISTEN | |
| 1 | Cliente | [SYN], Seq=111, Ack=0 | Cliente SYN-SENT |
| 2 | Servidor | [SYN,ACK], Seq=444, Ack=112 | Servidor SYN-RECEIVED |
| 3 | Cliente | [ACK], Seq=112, Ack=445 | Ambos ESTABLISHED |

El diagrama marca los números de secuencia iniciales (ISN, Initial Sequence Number) elegidos por cada extremo.

## 10. Transporte: UDP

- No garantiza el transporte. Esto lo garantiza el nivel de aplicación.
- Cabecera de 8 bytes (Source Port, Destination Port, Length, Header and Data Checksum).
- Más rápido que TCP al tener menos overhead. Los equipos ya no fallan tanto.
- La unidad de datos de UDP también se llama Datagrama, como en IP.

Algunos protocolos que utilizan UDP como capa de transporte:

|---|---|
| SNMP | 161 y 162 |
| DNS | 53 |
| DHCP | 67 y 68 |
| NTP | 123 |
| RIP | 520 |
| NFS | 2049 |
| DHCP6 | 546 y 547 |
| RTP | (sin puerto en el PDF) |
| QUIC (Quick UDP Internet Connections) | (sin puerto en el PDF) |

Más puertos y la tabla completa por capas en [[B4 - T7.2 TCP IP - PROTOCOLOS]].

### 10.1 TCP vs UDP

| | TCP | UDP |
|---|---|---|
| Direcciones | Puertos | Puertos |
| Fiabilidad | Garantista (ACK, secuencia, SACK) | No garantiza; lo garantiza la aplicación |
| Conexión | Handshake previo | Sin handshake |

| Velocidad | Más overhead | Más rápido |
| Unidad de datos | Segmento | Datagrama |

## 11. FTP: modos de transferencia

FTP funciona en dos fases: fase 1, establecimiento de la conexión; fase 2, intercambio de datos.

| | Modo activo | Modo pasivo |
|---|---|---|
| Comando de inicio | El cliente inicia la comunicación con el comando "PORT" (indicando su puerto de datos) | El cliente inicia la comunicación con el comando "PASV" |
| Quién inicia la transferencia | El servidor | El cliente |
| Puerto cliente de control | P > 1023 | P > 1023 |
| Puerto servidor de control | 21 | 21 |
| Puerto cliente de transferencia | P+1 | P+1 |
| Puerto servidor de transferencia | 20 | Q > 1023 |

Ejemplo de los diagramas: cliente con puerto de control 1035 y de datos 1036.
- Modo activo: 1) el cliente manda PORT y el puerto 1036; 2) el servidor responde con ACK; 3) el servidor (puerto de datos 20) inicia la conexión de datos hacia el puerto 1036 del cliente; 4) el cliente envía ACK.
- Modo pasivo: 1) el cliente manda PASV; 2) el servidor responde con un puerto > 1023 (en el ejemplo, 2040; el puerto 20 no se utiliza); 3) el cliente inicia la conexión de datos desde el puerto 1036 hacia ese puerto aleatorio del servidor; 4) el servidor envía ACK; 5) se cierra la conexión.

> [!tip] Truco
> Activo = el servidor "llama" desde el puerto 20; pasivo = el cliente "llama" a un puerto alto (Q>1023) que le da el servidor.

> [!note] Ampliación (conocimiento general, no viene del PDF)
> El modo pasivo es el que suele usarse cuando el cliente está detrás de NAT/cortafuegos (sección 5.2), porque es el cliente quien abre ambas conexiones. FTP seguro (FTPS, SFTP): ver [[B4 - T7.2 TCP IP - PROTOCOLOS]] y [[scp y sftp (transferencia de ficheros por SSH)]].

## 🔑 Resumen ultra-rápido

- OSI = 7 capas (Aplicación, Presentación, Sesión, Transporte, Red, Enlace, Físico); TCP/IP = 4 (Acceso a red 1-2, Internet 3, Transporte 4, Aplicación 5-7). Unidades: dato, segmento, paquete, trama, bit. PDU(N) = SDU(N+1) + ICI.
- Router doméstico: niveles 1, 2 y 3. MAC y LLC son subcapas IEEE (nivel 2). MAC de 48 bits.
- ARP: IP → MAC por broadcast FF:FF:FF:FF:FF:FF, con caché. VLAN (802.1Q): etiqueta en la PDU, configurada en switches; el router enruta entre VLANs. Árboles sin bucles: STP, MSTP, RSTP, SPB.
- Rutas: directamente conectadas, estáticas, dinámicas. RIR: RIPE NCC, LACNIC, APNIC, AFRINIC, ARIN; IANA asigna AS; RFC los publica el IETF.
- IPv4: cabecera 20-60 bytes; MF (0 = último), DF (descubrimiento de MTU), TTL (0 → ICMP tiempo excedido), DSCP (QoS) y ECN. Protocol: 1 ICMP, 2 IGMP, 6 TCP, 17 UDP, 50 ESP, 51 AH, 89 OSPF.
- NFS + XDR + RPC siempre juntos.
- Classful: A 0-127 (126 redes, 2^24-2 hosts), B 128-191, C 192-223, D 224-239 multicast, E 240-255 experimental. Privadas: 10.0.0.0; 172.16.0.0-172.31.255.255; 192.168.0.0-192.168.255.255. APIPA 169.254.x.x. Loopback 127.0.0.1/8. Host a 0 = red; host a 1 = broadcast.
- NAT: SNAT estático / dinámico (MASQUERADE); DNAT = port forwarding; PAT cambia el puerto.
- CIDR /a (host = 32-a); supernetting agrupa bloques; /1 a /31 (/31 punto a punto), /32 un host. FLSM máscara fija; VLSM variable (solo con enrutamiento classless: OSPF, RIPv2, IS-IS, EIGRP). Wildcard: red 0, host 1 (ACL).
- VLSM: ordenar de más a menos hosts, calcular bits (red + broadcast), asignar. Ejemplo 192.168.0.0/24 → /25, /27, /27, /30, /30, /30.
- IPv6: 128 bits, cabecera fija de 40 bytes, sin broadcast. Link-local FE80::/10, Unique-local FC00::/7 (FD00::/8), global 2000::/3, multicast FF00::/8 (FF02::1 nodos, FF02::2 routers), anycast, loopback ::1/128. Cabeceras de extensión en el payload encadenadas por Next Header.
- IPv6 transición: dual stack (::FFFF:a:b:c:d), 6to4 (2002 + IPv4 + SubnetID + interface). SLAAC con EUI-64 (FF FE en medio, invertir 7.º bit); NDP con ICMPv6 (RA, RS, NS, NA, redirect).
- Enrutamiento: vector distancia (RIP, IGRP, EIGRP) vs estado de enlace (OSPF, IS-IS) vs path vector (BGP, EGP). OSPF multicast 224.0.0.5/6, áreas con Backbone; RIPv2 multicast 224.0.0.9; RIP máx. 15 saltos, dist. admin. 120; OSPF 110.
- ICMP: cabecera 4 bytes, sobre IP. Ping = 8/0; traceroute usa el 11; tipo 3 code 4 = fragmentation needed (MTU discovery).
- TCP: puertos (0-1023 well known, 1024-49151 registrados, 49152-65535 dinámicos), cabecera 20-60 bytes, handshake SYN / SYN-ACK / ACK, ventana deslizante, SACK, Window Scale, MSS = MTU − IP − TCP, flags URG PSH FIN ACK RST SYN.
- UDP: cabecera 8 bytes, sin garantías; SNMP 161/162, DNS 53, DHCP 67/68, NTP 123, RIP 520, NFS 2049, DHCP6 546/547.
- FTP: control puerto 21; activo (PORT, servidor inicia desde el 20) vs pasivo (PASV, cliente inicia hacia puerto Q>1023).

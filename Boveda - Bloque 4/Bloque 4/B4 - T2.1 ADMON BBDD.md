# Tema 2.1 · Bloque 4 — Administración de BBDD

> [!abstract] De qué va este tema
> Panorama de la administración de bases de datos: qué hace un DBA y, para los cuatro SGBD del temario (Oracle, MySQL/MariaDB, PostgreSQL y SQL Server), su arquitectura, puerto, ficheros, lenguaje procedural, herramientas de línea de comandos, copias de seguridad y soluciones de alta disponibilidad. El eje del tema es la comparación: qué es peculiar de cada uno. Continúa en [[B4 - T2.2 ADMON BBDD - SGBD]] (herramientas de administración por SGBD) y [[B4 - T2.3 ADMON BBDD - COMPARATIVA]] (sintaxis SQL comparada).

> [!note] Actualizaciones oficiales ya incluidas en el PDF
> El documento "Actualizaciones 20_05_2026" lista para este tema tres cambios (tablespaces por defecto en Oracle `system / user / sysaux`, alta de SSMS en SQL Server y puerto 2484 de Oracle con TLS). Los tres ya figuran en el PDF importado y están recogidos aquí; no hay erratas pendientes de aplicar.

## 3. Oracle

> [!important] Peculiaridad de Oracle
> Oracle es **el único SGBD que, al hacer la instalación, crea una BD**. La BD no es tuya, sino del producto. La BD es todo y ahí están los ficheros. Por eso en Oracle **no puedes crear BBDD**: creas un **usuario** (que es un esquema) al que pertenecerán las tablas.

### 3.1 Arquitectura: instancia y base de datos

| Elemento | Qué es |
|---|---|
| Puerto | **1521**; ahora reemplazado por el **2483** y **2484** (TLS) |
| **Listener** | Proceso que está constantemente escuchando las peticiones |
| **PGA** | Proceso del servidor que atiende a un proceso de usuario. Ej: Java JDBC |
| **SGA** | Área global con las cachés de datos (datos, redo log, diccionario, etc.) |
| **DBWn** | Proceso que escribe en BD, en ficheros físicos / *data files* |
| **LGWR** | Proceso que escribe los logs, los archivos *redo log* (buffer circular) |

Diagrama del PDF ("Instancia de Oracle"), descrito:

| Parte del diagrama | Contenido |
|---|---|
| Cliente | Software de usuario (producirá SQL y mostrará el resultado) → habla con el **Listener** y con el **Proceso de Usuario**, que conecta con el **Proceso de Servidor** (asociado a la **PGA**) |
| **Instancia de Oracle** → **SGA** | **Caché de Buffer de Base de Datos**; **Caché de Buffer de Redo Log**; **Shared Pool** (pool compartido) con **Caché de librería** (área SQL compartida), **Caché de diccionario de datos** y **caché de resultados**; **Java Pool**; **Streams Pool**; **Large Pool** (buffer E/S, respuesta de consulta, memoria libre, petición de consulta) |
| Procesos de segundo plano | **DBWn**, **CKPT**, **LGWR**, **PMON**, **SMON**, **ARCn** |
| **Base de datos** (ficheros) | archivos de datos, archivos de control, archivos *redo log* y, fuera/junto a ella: archivos de backup, contraseñas, traza y alerta, parámetros, históricos redo log |
| Flujos | DBWn escribe la caché de buffer de BD en los archivos de datos; LGWR escribe el redo log buffer en los archivos redo log; CKPT actualiza archivos de datos y de control; ARCn archiva los redo log en los históricos redo log |

> [!note] Ampliación (conocimiento general, no viene del PDF)
> El PDF solo rotula en el diagrama los procesos de fondo sin explicarlos, salvo DBWn y LGWR. Significado habitual: CKPT = *checkpoint*, PMON = *process monitor*, SMON = *system monitor*, ARCn = *archiver* (copia los redo log llenos a los históricos).

### 3.2 Estructura lógica vs física

| Estructura lógica | Estructura física (dentro del SO, pero fuera de Oracle) |
|---|---|
| Base de datos | — |
| Tablespaces | Archivos de datos |
| Segmentos | (una tabla puede estar en varios data files) |
| Extensiones | — |
| Bloques | Bloques del SO (existe un **mapeo** entre bloques lógicos y físicos) |

| Concepto | Definición del PDF |
|---|---|
| **Tablespace** | Agrupa segmentos/objetos. Puede guardarse en uno o varios ficheros |
| **Segmento** | Tabla, Índice, Undo, LOB, etc. Una tabla puede estar en varios data files. Al crear una tabla puedes especificar a qué tablespace pertenece |
| **Extensión** | Los segmentos se dividen en *Logical Extents*, como el LVM ([[LVM (Logical Volume Manager)]]). Son datos contiguos |
| **Bloque** | Cada extensión tiene uno o varios bloques lógicos. Existe un mapeo entre los bloques lógicos y los físicos |

> [!important] Tablespaces por defecto en Oracle
> `system` / `user` / `sysaux` (según el PDF y su actualización oficial).

### 3.3 Sentencias de creación (ejemplos del PDF)

Creación de un tablespace (puede haber más de uno):

```sql
CREATE TABLESPACE ts_data
  DATAFILE '/var/data/oracle/ts_data_01.dbf'
  SIZE 100 M
  AUTOEXTEND ON
  NEXT 20M MAXSIZE 2G;
```

Creación de una tabla (puedo indicar el tablespace donde se guarda):

```sql
CREATE TABLE tabla (...)
  TABLESPACE ts_data
  STORAGE (INITIAL 20K NEXT 30K MAXEXTENTS 50)
```

Creación de un usuario (el usuario **es un esquema**; se crea para poder crear las tablas):

```sql
CREATE USER nominas_owner
  IDENTIFIED BY 'password'
  DEFAULT TABLESPACE ts_data
  TEMPORARY TABLESPACE ts_temp;

GRANT CONNECT TO nominas_owner;
-- CREATE SESSION
-- CREATE TABLE
```

> [!important] `CONNECT` es más que un permiso
> Hay que darle capacidad de conexión. **Connect es más que un permiso: es un conjunto de ellos**. Ahora solo da permisos de **Create Session**. Para que haga más cosas habrá que darle más permisos (por ejemplo `CREATE TABLE`).

### 3.4 Otros objetos y características de Oracle

| Elemento | Qué es / cómo se usa |
|---|---|
| **PL/SQL** | Lenguaje de procedimientos almacenados (ver [[SQL-PSM, PL-SQL y Transact-SQL]] y [[Procedimiento almacenado (Stored Procedure)]]) |
| Columnas autoincrementales | `CREATE SEQUENCE` |
| Ver tablas de otro usuario | Para que un usuario de app (`nominas_lector`) vea las tablas de otro (`nominas_owner`): `CREATE SYNONYM` + `GRANT SELECT ...` |
| **Vistas materializadas** | Útiles si los datos son poco cambiantes. Es una foto de los datos en el momento de su creación. Puede refrescarse |
| **RAC** (Real Application Clusters) | Permite ejecutar una sola BD Oracle en varios servidores, maximizando la disponibilidad, permitiendo escalabilidad horizontal y permitiendo acceso al almacenamiento compartido |
| **Exadata** | Plataforma de BD Oracle que permite mayor rendimiento, escalabilidad y automatización en local o en la nube |
| **NLS_LANG** | Configuración regional. Conjunto de caracteres usado en el lado del cliente |

```sql
CREATE MATERIALIZED VIEW nom_vw
  ...
  REFRESH {FAST | COMPLETE | FORCE | NEVER}
  ...
  AS SELECT ... FROM ... WHERE ...
```

La vista materializada, a diferencia de una vista normal ([[Vista (VIEW) SQL]]), almacena los datos; el modo `REFRESH` indica cómo se actualiza: `FAST`, `COMPLETE`, `FORCE` o `NEVER`.

### 3.5 Backup en Oracle

| Herramienta | Ejemplo / nota |
|---|---|
| **RMAN** | `RMAN > BACKUP TABLESPACE ts_data FORMAT '/location' TAG 'nombre' FROM TIME ___ UNTIL TIME ___` |
| **Data Pump** | Exportación/importación (detalle en [[B4 - T2.2 ADMON BBDD - SGBD]]) |

## 4. MySQL / MariaDB

| Dato | Valor |
|---|---|
| Licencia | MySQL: **GPL o propietaria**; MariaDB: **GPL** |
| Puerto | **3306** |
| Lenguaje de procedimientos almacenados | No tiene nombre propio |

### 4.1 Arquitectura (diagrama del PDF)

Capas, de arriba abajo: **Clientes** → **Conectores** (C, JDBC, ODBC, .NET, etc.) → **Servidor MySQL**, que contiene: Utilidades y herramientas; Gestor de conexiones; Procesador de consultas; Control de concurrencia; Optimizador de consultas; Gestor de recuperación; Caché de consultas; Gestor de transacciones; y los **Motores de almacenamiento** (InnoDB, MyISAM, Memory, NDB Cluster, etc.) → **Sistema(s) de ficheros o particiones**.

### 4.2 Motores de almacenamiento

| Motor | Características |
|---|---|
| **MyISAM** | Indexado y secuencial. **Muy rápido**. **No transaccional. No asegura ACID. No permite Foreign Keys**. Soporta **Fulltext**, haciendo que sus índices sean muy rápidos. **Aria** es el nuevo MyISAM. Ficheros: `.frm` (estructura de una tabla), `.myd` (datos), `.myi` (índices) |
| **InnoDB** | Soporta **transacciones**. Permite **ACID** (ver [[ACID (transacciones)]]). **XtraDB** es el nuevo InnoDB |
| **NDB Cluster** | MySQL distribuido. `ndbd` es el demonio que fuerza las tx distribuidas (ver [[Transacciones distribuidas (Two-Phase Commit, Monitor Transaccional)]]) |
| **Memory** | En memoria. Muy rápido |
| Otros mencionados | Spider, ColumnStore, CSV |

Al definir una tabla se define el motor; también puede modificarse después:

```sql
CREATE TABLE tabla (...) ENGINE = "MyISAM";
-- sintaxis antigua equivalente en el PDF:
-- TYPE = "MyISAM";
```

> [!important] ACID
> **A**tomicity, **C**onsistency, **I**solation, **D**urability. MyISAM no lo asegura; InnoDB sí. Las tablas ISAM son potencialmente corrompibles (ver abajo el mantenimiento) justamente por no permitir ACID. Sobre el acceso ISAM: [[Tipos de acceso a ficheros (secuencial, directo, indexado, ISAM)]].

### 4.3 Soluciones de alta disponibilidad (HA)

| Solución | Descripción |
|---|---|
| **Replicación** | Sistema **Master-Slave asíncrono**. Las sentencias ejecutadas sobre el Master se guardan en el **BinLog** y éste se pasa de forma asíncrona al **RelayLog** de los esclavos para que se ejecuten |
| **Cluster** | **SQL Nodes** (`mysqld`) + **Data Nodes** (`ndbd`): nodos de servicio y nodos de datos |

### 4.4 Comandos de administración

| Tarea | Comando |
|---|---|
| Conectarnos al servidor | `mysql -u root -p` (usuario root; solicita la contraseña) |
| Mostrar las BBDD del servidor | `show databases` |
| Copia de seguridad | `mysqldump --databases -u root -p aeropuerto -add-drop-database > aeropuerto.sql` — el fichero es un script con sentencias **DDL** (crear tablas) y **DML** (poblar tablas) |
| Solo DDL | `--no-data --all-databases --lock-tables = false/true` |
| Restauración | `mysql -u [usuario] -p [db_name] < fichero.sql` — el fichero debe crear la BD y hacer un `USE` de la BD, o crearla por fuera antes |
| Mantenimiento de MyISAM | `myisamchk [...] tbl_name` y las sentencias SQL `OPTIMIZE TABLE`, `ANALYZE TABLE`, `CHECK TABLE`, `REPAIR TABLE`. También el comando `mysqlcheck` |
| ¿Está levantado? | `mysqladmin -u root -p ping`; `systemctl status mysqld`; `ps aux \| grep mysqld` (ver [[B4 - T1.1 ADMON SSOO]]) |
| Versión / procesos | `mysqladmin ... version`; `processlist` (muestra qué se está ejecutando en la BD) |
| Crear una BD | `create nom_bd` (tal como figura en el PDF) |
| Instalación segura | `mariadb-secure-installation` llama al script `mysql_secure_installation`, que permite poner una nueva contraseña a usuarios root, borrar cuentas root, etc. Nos permite volver a administrar nuestra instalación |

### 4.5 Ficheros de configuración

| Fichero | Para qué |
|---|---|
| `/etc/mysql/my.conf` | Hace referencia a `conf.d` y `mariadb.conf.d` o `mysqld.cnf` |
| `/etc/mysql/conf.d` | Configuración del servidor |
| `/etc/mysql/mariadb.conf.d/50-server.cnf` | Usuario, puerto, etc. |
| `/etc/mysql/mysql.conf.d/mysqld.cnf` | Dirección IP que MySQL está escuchando: `bind-address = 127.0.0.1` |

## 5. PostgreSQL

| Dato | Valor |
|---|---|
| Puerto | **5432** |
| Organización lógica | Se crean **BD y esquemas** para organizar las tablas de manera lógica |
| Organización física | Se pueden definir **tablespaces** para organizar físicamente las tablas, índices, etc. (≈ Oracle) |

### 5.1 Características propias

| Característica | Detalle |
|---|---|
| **Particionado** de tablas | Para tablas muy grandes: `CREATE TABLE medidas (...) PARTITION BY RANGE (campo);` + `CREATE TABLE medidas_2019 PARTITION OF medidas FOR VALUES FROM (...) TO (...);` |
| **Herencia** de tablas | Una tabla hereda los campos de otra: `CREATE TABLE cliente (...) INHERITS (persona);` |
| **Roles** | Toda la seguridad de usuarios se basa en roles: `CREATE ROLE nombre [opciones]`. Opciones: `LOGIN` (role de usuario, para crear un usuario), `CREATEDB`, `SUPERUSER`, `CREATEROLE` |
| **RLS** (Row Level Security) | Seguridad basada en filas: la seguridad del dato. `CREATE POLICY nombre_politica ON nom_tabla FOR SELECT TO usuario USING (filtro);` y `ALTER TABLE nom_tabla ENABLE ROW LEVEL SECURITY;` (activa la política) |
| Procedimientos almacenados | En **4 lenguajes**: PL/pgSQL, PL/TCL, PL/Perl y PL/Phyton (sic) |
| Replicación Master-Slaves | Mediante el archivo **WAL** (*Write Ahead Log* / REDO): guarda la información de las transacciones y los cambios |
| **MVCC** (Multi-Version Concurrency Control) | Modelo de concurrencia avanzada. Cada transacción tiene su propia **foto** de los datos; una foto coge unos datos, otra foto coge otros; cada transacción opera sobre sus datos y luego se mezclan los resultados. Al aislar a las transacciones con fotos de los datos en diferentes tiempos se **reducen mucho los bloqueos** |

> [!tip] Truco: dos "fotos" de concurrencia
> PostgreSQL = MVCC; SQL Server = **Snapshot** ("concurrencia avanzada como en Postgres"). Ambas evitan bloqueos trabajando sobre versiones/fotos de los datos. Aislamiento y anomalías: [[Niveles de aislamiento y lecturas anómalas (SQL)]].

### 5.2 Herramientas de línea de comandos

| Herramienta | Función |
|---|---|
| `createdb` / `dropdb` | Crear / borrar una BD |
| `createuser` / `dropuser` | Crea un rol con capacidad de login (y lo borra) |
| `psql nombre_bd < fichero.bkp` | Restauración, igual que `pg_restore` (custom format). SQL format dump |
| `pg_dumpall > fichero.bkp` | Copia **todas** las BBDD. Igual que `psql -f fichero.bkp postgres` |
| `pg_dump nombre_bd > fichero.bkp` | Copia de una BD |
| `pg_dump -U user -h host -p port nombre_bd > fichero.bkp` | Copia **remota** |
| `vacuumdb` | Limpia y analiza una BD. Recupera almacenamiento de **tuplas muertas** |
| `pg_ctl` | ≈ `systemctl start/stop postgres` |
| `reindexdb` | Por si se han degradado mucho las tablas y es necesario reindexarlas |

### 5.3 Ficheros de configuración

| Fichero | Contenido |
|---|---|
| `/etc/pg_hba.conf` | Todas las opciones de usuario y sus **métodos de autenticación** |
| `/etc/postgresql/9.6/main/postgresql.conf` | Configuración del servidor |

## 🔑 Resumen ultra-rápido

- DBA: instalar/mantener SGBD, almacenamiento (particionamiento), backup/restauración, rendimiento (Explain Plan), crear BBDD/scripts, usuarios/roles/trazabilidad, documentación, seguridad (datos: vistas y permisos; servicios: HA).
- Puertos: Oracle 1521 (ahora 2483 y 2484 TLS), SQL Server 1433, MySQL 3306, Postgres 5432.
- Oracle: único SGBD que crea una BD al instalar (del producto); no se crean BBDD, se crea un usuario = esquema. Listener (escucha), PGA (proceso de servidor), SGA (cachés), DBWn (escribe data files), LGWR (escribe redo log, buffer circular).
- Oracle lógico: Tablespace > Segmento > Extensión > Bloque (mapeo con bloques del SO). Tablespaces por defecto: system / user / sysaux.
- Oracle: `GRANT CONNECT` = conjunto de permisos, hoy solo `CREATE SESSION`. `CREATE SEQUENCE` (autoincremental), `CREATE SYNONYM` + `GRANT SELECT`, vistas materializadas (foto; `REFRESH FAST|COMPLETE|FORCE|NEVER`), RAC (una BD en varios servidores), Exadata, NLS_LANG, RMAN y Data Pump.
- MySQL/MariaDB: MySQL GPL o propietaria, MariaDB GPL. MyISAM (rápido, sin ACID ni FK, Fulltext, `.frm/.myd/.myi`, Aria) vs InnoDB (ACID, XtraDB) vs NDB Cluster (`ndbd`) vs Memory.
- MySQL HA: replicación Master-Slave asíncrona (BinLog -> RelayLog); Cluster = SQL nodes (`mysqld`) + data nodes (`ndbd`).
- MySQL: `mysql -u root -p`, `mysqldump`, restauración con `<`, `myisamchk`/`mysqlcheck`/`OPTIMIZE|ANALYZE|CHECK|REPAIR TABLE`, `mysqladmin ping`, `mariadb-secure-installation`, `bind-address = 127.0.0.1`.
- Postgres: BD + esquemas + tablespaces; particionado `PARTITION BY RANGE`; herencia `INHERITS`; roles (`LOGIN`, `CREATEDB`, `SUPERUSER`, `CREATEROLE`); RLS (`CREATE POLICY`); 4 lenguajes procedurales; WAL para replicación; MVCC.
- Postgres herramientas: `createdb/dropdb`, `createuser/dropuser`, `pg_dump`, `pg_dumpall`, `psql <`, `pg_restore`, `vacuumdb` (tuplas muertas), `reindexdb`, `pg_ctl`; ficheros `pg_hba.conf` (autenticación) y `postgresql.conf`.
- SQL Server: `.mdf` (primary), `.ndf` (secondary, opcional), `.ldf` (log); Transact-SQL; Snapshot (como MVCC); SSMS.

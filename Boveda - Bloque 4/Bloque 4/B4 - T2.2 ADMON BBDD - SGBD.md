# Tema 2.2 · Bloque 4 — Administración de BBDD: herramientas por SGBD

> [!abstract] De qué va este tema
> Complemento práctico de [[B4 - T2.1 ADMON BBDD]]: las herramientas de administración de cada SGBD. En **Oracle**, Data Pump (`EXPDP`/`IMPDP`, copia en caliente, con su preparación previa de directorio) y SQL*Plus (arranque/parada); en **MySQL/MariaDB**, la familia de utilidades `mysql*`; en **PostgreSQL**, `pg_ctl`, `psql`, `pg_dump`/`pg_restore`, `vacuumdb`, `reindexdb` y sus ficheros de configuración. ## 1. Administración de Oracle

### 1.1 Data Pump

> [!important] Qué es Data Pump
> Herramienta de **exportación/backup e importación/restauración**. Es una **copia en caliente**. Las aplicaciones usadas son **EXPDP** para exportación e **IMPDP** para importación. Para el contexto de estrategias de copia: [[Estrategias de backup (Completa, Incremental, Diferencial)]].

#### Pasos previos

Antes de crear las copias de seguridad hay que tener configurado un **directorio de destino** donde se almacenarán. Se crea un objeto `DIRECTORY` por defecto llamado **`DATA_PUMP_DIR`**. Este directorio **siempre hace referencia a la máquina del servidor**. Primero hay que crear dicho directorio (con herramientas del sistema operativo; por ejemplo, en un terminal de texto de Windows, `MKDIR C:\BACKUP-ORACLE`) y luego registrarlo en el SGBD de Oracle:

```sql
SQLPLUS /NOLOG
CONNECT / AS SYSDBA

-- Indicamos directorio donde almacenar los backups
-- Dicho directorio debe haberse creado previamente. Si no dará error.
CREATE DIRECTORY BACKUP AS 'C:\BACKUP-ORACLE';

-- Damos permisos de lectura y escritura sobre dicho directorio
-- al usuario deseado.
GRANT READ, WRITE ON DIRECTORY BACKUP TO usuario;

-- Podemos comprobar que se ha registrado correctamente el directorio.
SELECT DIRECTORY NAME FROM DBA DIRECTORIES;

-- Salimos del SGBD
EXIT
```

Después ya se pueden usar `EXPDP` e `IMPDP` desde el terminal de texto del sistema operativo.

#### Formato y ejemplos

Formato para exportación:

```
expdp _usuario_/_clave_ dumpfile=_archivo_backup_ logfile=_archivo_log_ _opciones_
```

| Qué se copia / restaura | Comando |
|---|---|
| Base de datos **completa** al directorio de backup por defecto | `expdp SYSTEM/SYSTEM dumpfile=BD_COMPLETA.dmp logfile=BD_COMPLETA.logfull=y` |
| **Esquema** EMPLEADOS al directorio por defecto | `expdp SYSTEM/SYSTEM dumpfile=ESQUEMA-EMPLEADOS.dmp logfile=ESQUEMA-EMPLEADOS.log schemas=EMPLEADOS` |
| **Tablas** SALARIOS y VACACIONES al directorio por defecto | `expdp SYSTEM/SYSTEM dumpfile=ESQUEMA-EMPLEADOS.dmp logfile=ESQUEMAEMPLEADOS.log tables=SALARIOS,VACACIONES` |
| Esquema EMPLEADOS al directorio de backup **definido** | `expdp SYSTEM/SYSTEM directory=BACKUP dumpfile=ESQUEMA-EMPLEADOS.dmp logfile=ESQUEMA-EMPLEADOS.log schemas=EMPLEADOS` |
| **Restauración** del esquema EMPLEADOS desde el directorio definido | `impdp SYSTEM/SYSTEM directory=BACKUP dumpfile=ESQUEMA-EMPLEADOS.dmp` |

> [!tip] Opciones según el alcance
> `full=y` (BD completa; en el PDF aparece pegado a `logfile=BD_COMPLETA.log`) → `schemas=` (un esquema) → `tables=` (tablas concretas). `directory=` elige el objeto DIRECTORY; si se omite se usa el directorio por defecto.

### 1.2 Herramienta SQL*Plus (arranque y parada del servidor)

```
SQLPLUS> SHUTDOWN TRANSACTIONAL | INMEDIATE | ABORT | NORMAL
SQLPLUS> START MOUNT | NOMOUNT | OPEN | RESTRICT | FORCE
```

| Comando | Modos indicados en el PDF |
|---|---|
| Parada (`SHUTDOWN`) | `TRANSACTIONAL`, `INMEDIATE`, `ABORT`, `NORMAL` |
| Arranque (`START`) | `MOUNT`, `NOMOUNT`, `OPEN`, `RESTRICT`, `FORCE` |

> [!note] Ampliación (conocimiento general, no viene del PDF)
> El PDF solo enumera los modos. En Oracle estándar el comando de arranque suele escribirse `STARTUP` (el PDF pone `START`, se transcribe tal cual). Orden habitual de las fases de arranque: `NOMOUNT` (instancia iniciada) → `MOUNT` (abre ficheros de control) → `OPEN` (BD abierta). Para `SHUTDOWN`, `ABORT` es la parada inmediata sin cierre ordenado y `NORMAL` espera a que se desconecten todos los usuarios.

## 2. Administración de MySQL / MariaDB

| Utilidad | Función (según el PDF) |
|---|---|
| `mysqldump` | Backup de bbdd(s)/tabla(s) en un script con el **DDL + DML** |
| `mysql` | Cliente de línea de comando |
| `mysqladmin` | Utilidad con funciones de administración generales |
| `mysqlcheck` | Chequea, repara, analiza y optimiza tablas |
| `mysqlimport` | Importar datos de un fichero externo |
| `mysqlshow` | Muestra información sobre bbdd, tablas y columnas |
| `mysqldumpslow` | Lista **queries que tardan mucho tiempo** en ejecutarse |
| `myisamchk` | Chequea, analiza, optimiza y repara tablas **MyISAM** |

> [!important] No confundir `mysqlcheck` y `myisamchk`
> `mysqlcheck` es la utilidad general (chequea, repara, analiza y optimiza tablas); `myisamchk` es la específica del motor **MyISAM**. Ejemplos de uso (`mysqldump`, restauración con `mysql <`, `mysqladmin ping`...) en [[B4 - T2.1 ADMON BBDD]].

## 3. Administración de PostgreSQL

| Herramienta | Función | Ejemplos del PDF |
|---|---|---|
| `pg_ctl` | Inicio, parada y control del PostgreSQL server | `pg_ctl start/stop/status/restart` |
| `psql` | Cliente de línea de comando | `psql -h host -d base_de_datos -U user -W` (pedirá password); restauración: `psql base_de_datos < fichero_backup.sql` o `psql -d base_de_datos -f fichero_backup.sql` |
| `createdb` / `dropdb` | Crear / borrar una base de datos | — |
| `createuser` / `dropuser` | Crear / borrar un usuario/role | — |
| `pg_dump` | Backup de **una** bbdd | `pg_dump base_de_datos > fichero_backup.sql`; formato custom: `pg_dump -Fc base_de_datos > fichero_backup` |
| `pg_dumpall` | Backup de **todas** las bbdd | `pg_dumpall > fichero_backup.sql` |
| `pg_restore` | Restauración cuando el formato de backup es de tipo *custom-format* | `pg_restore -d base_de_datos fichero_backup_custom_format` |
| `vacuumdb` | Limpia y analiza la bbdd (ej: tuplas muertas) | `vacuumdb test` (limpia); `vacuumdb --analyze bigdb` (limpia y analiza) |
| `reindexdb` | Reindexa la bbdd | `reindexdb base_de_datos` |

> [!important] Qué herramienta restaura cada formato
> Backup en SQL (`pg_dump` sin opciones) → se restaura con **`psql`** (`<` o `-f`). Backup en formato **custom** (`pg_dump -Fc`) → se restaura con **`pg_restore`**.

### 3.1 Información de configuración

`/etc/pg_hba.conf`: autenticación de los clientes, con el formato:

```
local  database user auth-method [auth-options]
host   database user address auth-method [auth-options]
...
```

`/etc/postgresql/9.6/main/postgresql.conf`: configuración del servidor:

```
port = 5432
max_connections = 100
data_directory = '/var/lib/postgresql/9.6/main'
hba_file = '/etc/postgresql/9.6/main/pg_hba.conf'
....
```

| Fichero | Contenido |
|---|---|
| `pg_hba.conf` | Autenticación de clientes (`local` / `host`, base de datos, usuario, dirección, método de autenticación y opciones) |
| `postgresql.conf` | Servidor: `port`, `max_connections`, `data_directory`, `hba_file` |

## 🔑 Resumen ultra-rápido

- Oracle Data Pump = copia **en caliente**; `EXPDP` exporta, `IMPDP` importa; directorio por defecto `DATA_PUMP_DIR` (siempre en la máquina del servidor).
- Pasos previos: crear carpeta en el SO -> `CREATE DIRECTORY BACKUP AS '...'` -> `GRANT READ, WRITE ON DIRECTORY ...` -> `SELECT ... FROM DBA_DIRECTORIES`.
- `expdp usuario/clave dumpfile= logfile= [full=y | schemas= | tables=] [directory=]`; restauración con `impdp ... directory= dumpfile=`.
- SQL*Plus: `SHUTDOWN TRANSACTIONAL|INMEDIATE|ABORT|NORMAL`; `START MOUNT|NOMOUNT|OPEN|RESTRICT|FORCE`.
- MySQL/MariaDB: `mysqldump` (DDL+DML), `mysql` (cliente), `mysqladmin`, `mysqlcheck`, `mysqlimport`, `mysqlshow`, `mysqldumpslow` (queries lentas), `myisamchk` (solo MyISAM).
- PostgreSQL: `pg_ctl`, `psql`, `createdb/dropdb`, `createuser/dropuser`, `pg_dump` (una BD; `-Fc` custom), `pg_dumpall` (todas), `pg_restore` (custom), `vacuumdb` (tuplas muertas; `--analyze`), `reindexdb`.
- PostgreSQL ficheros: `pg_hba.conf` (autenticación) y `postgresql.conf` (port 5432, max_connections 100, data_directory, hba_file).
